      **十一处 brief 说错的地方里，四处值得记：**
      ① **`mention` 表不存在**——ADR 0002 里那条 `SELECT … FROM mention` 是规划，
      今天唯一实现是正则 + 逐章扫磁盘。**不缓存是有意的**：稿子随时在变（作者就在旁边打字），
      缓存的命中表会在他保存那一刻变成一个**看起来正常的错误答案**。

      ③ **`MemoryBudget.for_context` 解的不是同一个问题**（它按 4:1:2 切给**同一个 prompt 里
      同时装配的三段**；索引四层是四次不同时刻的调用，没有哪一刻同框）。只复用了

   三个问题的答案：**歧义时空着**（`_Surfaces` 只收唯一指回同一个人的称呼，
   绝不替作者挑）；**只补这一个人**——「补一批」要么得读正文（`activity.py` 不读图、
   日志页也不该为此翻磁盘），要么得让前端把两份列表并起来（那是前端在造坐标）；
   `event_cast` 那一档不给（它跳的是名单不是矩阵的一行）。

   **⚠️ 上面那段的最后一句原本写的是「代价是显式 cast 压过推导，那张表只剩一行」——
   那个设计是 fail-open 的，当天被对抗性验证推翻了。** 留着这段是因为它错得有价值：

   坐标一旦走 `?cast=`，交付路径是 `jump.cast → store.cast → ?cast= → _effective_cast()`
   （「显式赢，否则推导」），而**同一个 `cast` 参数还喂 `/constraints` 和 `/state`**。
   实测：第 1 章萧决知道、李管家以为 ⇒ 推导下 `must_not_reveal = [血脉秘密]`；
   按 `?cast=萧决` 交上去 ⇒ **`must_not_reveal = []`**。**一条禁令凭空消失**——
   正是 `panel/constraints.py` docstring 里记着的「李管家静默地从 cast 里消失」那个修过的
   真 bug，这次由系统自己制造。（起草侧没被波及：`useContinuation` 不读 `store.cast`，
   `/draft` 的 cast 走请求体，M2 判分链不经 HTTP。）

   **改成 `?include=`（只加不减）**：`(场景块 or 推导) + include 里不重复的那些`。
   前端 store 拆成两个字段——`cast`（过滤，唯一来源是作者标的场景块）/
   `castInclude`（只加不减，只有 `jumpFromActivity` 写）。
   **最关键的一行是 `if not base: return []`**：推导为空的含义是「不知道谁在场 ⇒ 全禁」，
   把坐标加进去会让 `ResolvedCast.complete` 成立、**全禁塌成「只按他一个人算」**——
   那是同一种 fail-open 的完整形态。这一档一律不加人。

   **教训**：「显式赢」这条既有语义本身没错（作者标的场景块该赢），
   错的是**让系统生成的坐标走作者的那条路**。ADR 0018 的安全性押在
   「推导是超集 = 多禁 = fail-closed」上，任何**收窄** cast 的自动行为都在拆那个地基。

## 已知限制（不假装解决了）

- **底栏的花销汇总系统性偏低，而且没有任何东西说这件事。**
  `record_call` 全仓只有两个调用方（`extract/runner.py` / `draft/rolling_summary.py`）——
  **作者花钱最多的动作「起草」在 `model_call` 里一行都没有。** 2.1 的读端把这张表如实读出来了，
  于是「如实」变成了「骗人」：日志页显示的是真实花销的一小部分，看起来却像全部。
  修法便宜（`/draft` 那条路径补一次 `record_call`），**但补之前那个数字不该被当真**。
  （3.3 的 agent loop 没有走上这条老路：`ledger` 是它的必填参数。但它自己有一个更小的漏账口
  ——见下一条。）
- **`ProviderError` 那一路没有账。** 没有 `CompletionResult` 就没有 token 数，而 agent loop
  不许替它编一个（同 `cost` 那一列有意留空）。于是**已经发出去、生成到一半被作者掐掉的那些
  token 不在账上**。今天量级小（一次调用），但它和上面那条是同一个方向的偏低。
- **一次工具返回的天花板和整段对话的天花板是同一个数**（都是
  `memory_units_available()`）。于是一次满额的工具返回就能把整段对话顶满，第二步开始必剪。
  `run_turn(budget_units=...)` 可以显式放宽，但**默认值是紧的**，这是今天的真实形状不是余量。
  **3.4 的 HTTP 壳没有放宽它**（`api/chat.py` 不传 `budget_units`）——放宽是一个产品决定
  （多花多少输入 token 换多长的记性），该在有人真的用起来、看得见剪枝回执之后再定。
  回执已经出到 HTTP 上了（`TurnReceipt.context`），所以那时有数据可看。
- **作者在「模型这一次不叫工具、直接说话」的那次调用里按停，回执写的是 `done` 不是
  `author_stopped`。** 这是对的、不是漏的：那一轮本来就在这一次调用之后结束，
  停没有让任何事情少发生，报「按你的意思停下了」等于替它认领一件没做的事。
  **但界面上要留意**：作者按了停、屏幕上却写「说完了」，读起来像按钮没反应。
  3.5 画那颗按钮时要么把这一档说清楚，要么在 `TurnReceipt` 上多带一个「你按过停」的位——
  **后者要改出参形状，别顺手加**。
- **两个标签页对同一段会话各跑一轮时，「占位」必须发生在写库之前。** 实测过的真故障：
  占位放在追加作者那句话之后，于是第二个窗口先把话写进历史，第一轮跑完想追加自己的产物时
  撞上乐观并发闸——**先按发送的那一个被判失败，后按的那一个反而通过**。
  现在顺序是「占位 → 读 → 写」，`tests/test_chat_api.py` 里那条断言两边都钉着。
- **`_Running` 是进程内的**（同 `autopilot.py::JOBS`）。重启之后没有任何一轮在跑，
  而库里那段对话照旧读得回来——resume 靠的是「缺哪几个 `tool_result`」，不是一个
  `status='RUNNING'` 标志位。**故意不落库**：落库的那个标志会在进程崩掉之后永远卡住，
  而清它需要一个没人会写的看门狗。
- **`model_call.cost` 这一列至今没有写入方**，`priced_calls` 恒 0、`cost` 恒 `null`。
  BYOK 之下引擎不知道作者签的什么单价，这是有意的空，不是漏的。
- **`_call_detail` 把 `params_json` 原样 `str()` 出去**，是日志读端唯一没过收窄的直通口。
  今天安全只因为写入方只写 `{finish_reason, schema_version}` 两个键——
  而 `001_init.sql` 的注释明写这一列还要长（「必须如实记录 thinking / output_config」）。
  **毒测覆盖今天的写入方，不覆盖明天的。** 那一列变宽的那一天要同时把收窄补上。
- **ADR 0021 承诺的「版本历史要能按 `actor` 过滤」today 不成立**：
  `ChapterSnapshot` 上没有 actor 列，`GET …/history` 也没有。关联键**是存在的**
  （落盘那一行的 `payload["text_sha256"]` == 那条快照的 `text_sha256`），
  但没有出参把它们连起来。ADR 自己把这条列在「代价」里，所以是欠账不是 bug——
  但作者自己存的那几版被机器稿淹掉**发生得比 ADR 想的快**（一轮最多 6 稿）。
- **起草留在对话里的那份正文没有过期检查**（边界三的第三个受害者）。
  `chapter_text` 的返回过期时投影会换成一句「重新读一次」，而 `draft_chapter` 的返回里
  同样躺着一整章正文、同样进 `chat_message`、同样会过期——**判据认不出它**
  （`ChapterFullText` 是 `extra="forbid"`，`DraftResult` 验不过）。
  **照抄那个判据会更坏**（一稿不带章标题，直接比一定恒不相等 ⇒ 每一稿刚写完就被自己擦掉），
  要补得先给它一个能比的锚。已有一条带一半对照的测试，修的时候它会红。
- **按「停」中断不了正在跑的起草。** 打断走的是适配器包在**流**上的信号，
  而起草直接调 `complete()`，没过那个适配器；何况它的输出预算 7,024 远在流式阈值
  16k 之下。粒度 = 「这一稿写完才停」，比对话那一档贵得多。
- **`TurnLimits.max_tokens = 300_000` 第一次真的够得着**：以前只有聊天调用记账
  （8 步 × ~5k），步数闸先到；现在一轮最多 8×6=48 稿，成本闸在 ~20–25 稿处咬住——
  **那是一次对话里二十几稿正文的钱。** 这个数该被重新裁一次。
- **agent 落盘会静默抹掉那一章里作者标的场景块**（`## 场景 N` + `<!-- nh: cast=… -->`）。
  方向是安全的（场景块没了退回从正文推，ADR 0018 押的就是「推导是超集 = 多禁」），
  而且进了快照、退得回来。**但没有任何东西提过这件事。**
- **起草那一行账在日志页上答不出「为哪一章」**：`_call_chapter` 是从 `extraction_run` /
  `chapter_summary` 反查的，起草没有这样一张业务表。落盘那一行有章号，所以找得到现场。
- **会话的 `house_style` 到不了起草那一稿**（它是 prefix 里的一条 system message，
  不是 `chat_session` 的列）。所以 **agent 起的稿不跟作者的文风**。
- **agent loop 的 `ProviderError` 那一路没有账，`steps` 也不计那一次。**
  没有 `CompletionResult` 就没有 token 数，这一层不许编（同 `cost` 那一列有意留空）——
  但「已经发出去、生成到一半被作者掐掉」的 token 因此**在两个口径上都不可见**。
  方向和 `/draft` 那个洞一样是偏低。
- **agent loop 的预算只量对话、不量工具声明**（声明约 3862 字 vs 默认预算 17000，
  约 18% 的系统性低估，方向偏松）。另：`stop_wording(CONTEXT_FULL)` 里有一对字面量 `**`，
  前端不渲染 markdown 的话作者会看见星号。
- **滚动摘要会过期，而 `coverage()` 只问「有没有」不问「新不新」。** 整章重写之后，
  索引照旧原样交出旧摘要且一个字不说——**缺摘要是索引在那章「瞎」，过期是索引在那章「说错」**，
  而摘要是模型在这一层唯一的「这一章讲了什么」。3.2 的处置是拿磁盘 mtime 兜一层
  （`may_be_stale` + `stale_checked`，把「我没查」和「没过期」拆开）；
  **彻底的做法是在 `coverage()` 里按 `prompt_hash` 算一个 `stale` 纯量**，
  那会一路动到前端契约，留给以后。
- **一条测试纪律，栽过一次值得记**：`tests/test_agent_index.py::FakeEvents` 忽略了
  `chapter` 参数，**比真库宽**，于是事件轴那个静默上限在测试里一直是绿的。
  **假实现比真实现宽的时候，测试绿而产品错。** 假端口要和 `graph/queries.py`
  的 `TEMPORAL_WHERE` 同解。
- **`GET /runs` 不走 `_with_jump`**，于是底栏那几行的 `endpoints` 恒空——
  而空 `endpoints` 在本仓的契约里是一句断言（「今天没有任何路由能改这个」）。
  **底栏因此在说一句假话。** 今天无害只因为 `BottomBar.tsx` 根本不渲染 jump，
  但这条不一致是颗定时炸弹：谁哪天让底栏渲染 jump，它就当场骗人。
- **屏幕守卫罩不住小写裸枚举值**（`author` / `system` / `failed` / `extractor` / `alive` …）。
  收它必假红（`token` / `ms` / `deepseek-v4` 形状上分不开），**而假红的下场是被人加豁免、
  然后豁免被拓宽**。这一类只能在源头堵。判据文件里写着这个洞，且有一条测试
  钉住「它必须继续自己承认」。
- **`/matrix` 的 unresolved 横幅措辞对歧义称呼是错的**：写的是「这些称呼未在花名册中找到」，
  而歧义称呼**在**花名册里，只是指向多个人。预存问题。
- **`CostTotals` 的 `tokens_in/out/ms` 是 `COALESCE(…,0)` 的非空 int**，
  而同名字段在 `ActivityCost` 里可空、渲染成「未记录」。provider 不报 usage 的书，
  底栏会显示「入 0 / 出 0 token」——正是 `cost` 被特意给了 `null` 想避开的那种静默零（约束 8）。
  修它要改出参形状 + 重生成 `api.json`。

- **改 CANON 事件的 `summary` 还做不到** —— `story_event` 上有
  `UNIQUE(project_id, evidence_id, information_scope)`，同一条引语上物理装不下第二条 CANON 事件，
  「写新的 + 撤旧的」在这儿不存在。要么松掉那个 unique（丢掉「一句引语 ⇒ 一条事实」），
  要么宣布 summary 是可原地改的展示字段。**这是 schema 裁决不是一下午的活。**
  队列路径（还没升 CANON 的）照旧能改。
- **只改 `believed_value` 不翻类型** 撞同一个幂等键，`upsert_edge` 当重跑处理、只更 props。
  那**是**一次原地修改，算不算 supersede 要单独裁一次。
- **一个真实事故：开着的 dev server 会把新迁移应用到作者的真书上。**
  子 agent 加了 `005_fact_edit.sql`，它同时在改 `src/` → `uvicorn --reload` 重启 →
  lifespan 跑 `ensure_schema()` → **`/Users/lixibin/Desktop/111935/book.db` 的 `user_version`
  自己从 4 变成了 5**。这次无害（ALTER 是加列、有默认值，723 章 / 753 节点 / 30 条
  `decision_log` 逐个复核过，数据完好），但机制是真的：**开着 L1 dev server 的时候写迁移，
  等于对真书做了一次没有备份、没有确认的 schema 变更。** 下次写迁移前先 Ctrl-C。

- **卷级摘要没有** —— 722 章现在装得下，3000 章装不下。那时要「50 章压成一条」再分层定位。
  数据模型撑得住，今天没做。
- **`knowers` 是推断不是文本事实** —— 自动生效之后它是最可能出错的一维，
  而认知边界正是这个产品唯一的独家价值（ARCHITECTURE §1）。
  退路是编辑（1.1）+ 可查（2.x），**不是事前批准**。
- **R2 / R3 在作者手里仍然是死的** —— `props.first_appears_chapter` 和 `value_key`
  全仓只被读、没有生产写入方，作者无法声明「血枭盟第 200 章才出现」或「某人死了」。
  详见 [`2026-08-06-引擎能力差最后一厘米没接线.md`](2026-08-06-引擎能力差最后一厘米没接线.md)。
  **这是 capability gap 不是 verdict gap**，M3 判定本身成立。
- **MCP 不做** —— 工具表就是权限边界（ADR 0019 边界一），
  而 MCP 的价值恰恰是「工具可插拔」。插进来一个第三方的「读图谱节点」工具 = 当场泄漏。
  反方向（把 novel-harness 做成 MCP server 给别人查）是另一件事，
  撞 [`2026-08-04-正文真相源在磁盘与外部审计的边界.md`](2026-08-04-正文真相源在磁盘与外部审计的边界.md)。
