# 任务：认知边界在两个模式下怎么注入

> 2026-08-22 定。「认知边界」= 谁在第几章知道 / 不知道 / 误以为哪条秘密。
> **两个模式今天拿到的东西差得很远，方案也各不相同。**

## 先纠一个说法

本文之前的几轮讨论里说过「三层都拿不到谁知道什么」——**那是错的**。
整章起草时，认知矩阵是**逐格进 prompt** 的（cast 解析成功时）：

```
【本场设定要点】
截至第 10 章的认知边界：
- 苏挽：知道「沈孤鸿之死」（第 9 章起）
- 萧决：还不知道「沈孤鸿之死」
- 李管家：误以为「血脉秘密」是「已泄露」（第 4 章起）
这一场不得写破：沈孤鸿之死、血脉秘密
```

带起始章、连"误以为"那一态都给。**「一个知道的人和一个不知道的人同处一场」那种戏，
模式二写得了。**

写前校准的简报确实不带 KNOWS/BELIEVES，但那是**分工**不是洞——
它的注释原话是「认知边界由后端即时安全约束渲染，**不经过** SceneBrief 的事实通道」，
意思是走另一条通道，不是不给。

---

## 今天两个模式各自拿到什么

| | 模式一（协助） | 模式二（novel-agent） |
|---|---|---|
| 起草时 prompt 里有矩阵 | ❌ | ✅ 逐格 |
| 模型主动查得到矩阵 | ——（没有工具） | ❌ |
| 禁写清单 | **全书全禁** | 这一场算出来的 |
| 在场名单哪来的 | 前端不传 | 从这一章正文数 |
| 退化条件 | **恒退化** | 正文里数不出人时 |

模式一恒退化的原因：**后端那条路支持传名单，是前端一次都不传。**
不是引擎缺能力，是那条线没接。

---

# 模式一的方案

## 写的时候：删一块，留一块

**删掉**：

```
【在场】
未知。因此这一段不得说破任何尚未公开的秘密。
```

「未知」两个字不带信息；后半句跟下面那行禁写清单是同一句话说了两遍。

**保留**：

```
这一场不得写破：血脉秘密、沈孤鸿之死、顾清音真身    ← 当提醒
尚未登场、这一场不得出现：血枭盟（第 47 章首现）    ← 不依赖在场，退化态里仍精确
```

**认知矩阵不补到写时。** 续写算不准谁在场，那份东西归验证侧。

### 拆分线：**依赖在场的搬走，不依赖在场的留下**

| 东西 | 依赖在场吗 | 归哪 |
|---|---|---|
| 认知矩阵 | 依赖 | 验证侧 |
| 精确的禁写清单 | 依赖 | 验证侧 |
| 【在场】那一块 | 就是它本身 | 删掉 |
| 粗的禁写清单（全书） | —— | **留在写时当提醒** |
| 尚未登场的实体 | 不依赖（只看章号） | 留在写时 |

## 保存之后：精确验一遍

**关键是一条不对称：写之前不知道谁在场（那是写出来的结果），写之后知道（数得出来）。**

同一个问题在生成侧无解（只能退化成全禁），在验证侧**精确**。
把它搬过去不是降级处理，**是搬到了它唯一能算准的地方**。

```
① 扫这一章正文 → 数出谁真的在场          现成能力
② 拿这几个人的认知矩阵                    现成能力
③ 用模型判：有没有对不该知道的人说破什么  ← 新
④ 一条通知落在右栏，不阻断                 出口现成
```

**③ 只能用模型，不能用规则。** 代码注释自己写着：「真书里秘密内容散在语义里，
集合判断够不着」——合成小册子每条秘密配一个生造专名（「玄血蛊」），真书没有这个东西。

而「写完之后用模型做语义核对、只写通知、不阻断、不改数据」这个形状，
**2026-08-17 已经专门为它开了窄例外（ADR 0030）**，且已有一个模块在跑同样的形状。

## 两道各管各的，都要

| | 写的时候 | 保存之后 |
|---|---|---|
| 判据 | 全书所有未公开的秘密 | **这一章真正在场的人**算出来的 |
| 精度 | 粗（算不准，只能全禁） | **精确** |
| 作用 | 提醒别往那儿走 | 抓住它还是走了的那次 |
| 拦不拦 | 不拦 | 不拦 |

写时那道拦不住（只是 prompt 里一句话）；写完那道拦不了（字已经写下了）。
**两道叠起来漏网概率比任何一道单独都低，而且成本都不高。**

## 通知那一块要补的两件

**已经有的**：规则发现问题时会落一条通知（`validation_blocked`），
所以「结果丢了」这个说法是错的。

**缺的**：

1. **通知不带定位。** 它只说「第 N 章的正文检查发现需要留意的地方」，
   不说哪条规则、哪一段、哪一句。而规则产出的 Issue **本来就带着精确的锚**
   （第几段 / 那句原话 / 第几次出现）——那个锚没跟着通知走。
   （这正撞上作者对工作台的第一条期待：**日志可跳转**。）
2. **新加的检查不能挂 `validation_blocked`。** 那一类**有副作用**：
   通知里那句「新正文不会再自动生成总结与情节」是真的，验证不过会把后面两支停掉。
   而语义核对按 ADR 0030 的立场**只告警不阻断**——挂错类型会让作者改个老章
   就把整章的自动整理停掉。**要另一种不阻断的通知类型。**

# 模式二的方案

## 洞一：模型主动查的时候拿不到矩阵

### 先说清楚为什么今天不给——两个理由，一个站得住一个站不住

**站不住的**：模块头写「出参一律收窄，`Node` / `StateSnapshot` / `KnowledgeMatrix`
一个都不出」，理由是节点属性里作者写的东西会穿过序列化。
**但矩阵里没有节点属性**——它只有 id/label/name 和几个纯量。这条对它不成立。

**站得住的**：

> 对话是**持久化且会累积的**，之后每一轮起草它都还在上下文里。

矩阵跟章号绑死。模型在第 10 章查了一次，那张表就永远躺在历史里；
写到第 50 章时**它已经错了**，而且错的方向是 **fail-open**
（到第 50 章更多人已经知道，禁令该更少，旧表看起来更严，模型会按旧的走）。

ADR 0019 边界六把「认知矩阵」明确列在**不能进稳定前缀**那一列，就是这个。

**起草时的 prompt 每次重建、用完就没了，所以安全；工具结果会永久留下，所以不安全。
两者的差别不在内容，在寿命。**

### 方案：别给整张表，给一格

模型主动查时要的不是整张表，是一个具体问题：「我现在要不要让苏挽把这句话说出口？」
——那是**一个格子**。

**加一条窄工具：某人在第 N 章知不知道某条秘密。**

```
问：萧决 / 沈孤鸿之死 / 第 10 章
答：还不知道（截至第 10 章）
```

| | |
|---|---|
| 量小 | 一行，不是几十行 |
| 带章号 | 答案里明写「截至第 10 章」，过期了看得出来 |
| 过期只错一格 | 不是整张表一起错 |
| 按需 | 问什么答什么，不问就不占地方 |

跟起草时那份不冲突：**起草时照旧拿完整的表（每次重建、不留存），查的时候拿一格。**

配合已有的编号取回机制（工具结果会被收起、按编号取回、**编号只活这一轮**），
即使查了很多格也不会永久堆在历史里。

## 洞二：数不出人就退化成全禁

**先看它多常见**：起草一个刚开头的空章，**必然触发**——而那正是最常用的起草场景。

### 方案：只加不减地往前借

```
第 11 章正文只有一行标题 → 数出 0 个人
  ↓ 往前借
第 10 章出现过：苏挽、萧决、李管家
  ↓
cast = 这三个人 → 按这三个人算禁写清单
```

**方向可证明是安全的**：

> 判据是「在场**至少有一个人**还不知道」→ 就禁。
> **多算一个人只会多一批禁令，少算一个人才会漏。**

所以**只加不减**是 fail-closed 的那一侧。仓库里已有一处用同一原则——
右栏那个"往里加人"的参数，注释写着「只往里加人，绝不减人」。

### 歧义那一半用同一招

今天「师兄」解析不出唯一的人 → 整个退化成全禁。
**改成：把所有候选都算在场。** 「师兄」对应 8 个人 → 8 个都加进去。
禁令只会更多不会更少，仍然 fail-closed，**但比"全书全禁"精确得多**。

### 什么时候全禁仍然对

**第一章、或者全新的书，前面没人可借。** 那时全禁是唯一诚实的答案，留着。

---

# 共同的判据

> **多算一个人 = 多一批禁令 = 安全；少算一个人 = 漏 = 危险。**
> 所以拿不准的时候**往里加**，而不是**整个放弃**。

「整个放弃」（全禁）也是安全的，**但它安全得没用**——
AI 面对一份「什么都别碰」的清单，写出来的东西本来就不能用。

# 任务清单

### ⚠️ M1-a 会撞上 `assemble.py` 的守卫 —— 裁定：**改守卫，不绕开**（2026-08-22）

那一行是 `assemble.py::_base()` 发出来的，而 `_base()` 是**三臂共用**的那一段，
不是产品独有分支。`test_calibration_eval_guard::test_three_arm_assembler_is_byte_identical`
号称把它逐字节冻住。

**但实测下来那道守卫只拦未提交的改动**（它用的是 `git diff --exit-code`）：

```
未提交时改 assemble.py  →  守卫红
提交之后再跑            →  守卫绿
```

**一道自称「三臂冻结 prompt 逐字节不动」的守卫，实际效果是「别把这个文件改脏了」。**
拦得住「顺手改了忘了看」，拦不住「改了并且提交」——而真要改考卷的人当然会提交。

**做法**：

1. 把守卫从「有没有未提交改动」换成「**这个文件的内容哈希等不等于登记的那个**」；
2. M1-a 的改动落地时，**同一笔更新那个哈希**。

**理由**：绕开（在外面后处理）会把 prompt 形状拆成两处，而那是为了绕一道**根本没锁的门**。
改守卫的代价约等于零（几行），收益是**那道守卫第一次真的生效**——
此后每一次改 `assemble.py` 都必须显式动那个哈希，**改卷子这件事再也藏不住**。

---

```
模式一
  M1-a  删掉续写 prompt 里【在场】那一块              小（连带把守卫改成真冻结）
  M1-b  保存后新增「秘密有没有被说破」的语义核对      中（用模型，ADR 0030 窄例外）
  M1-c  通知带上定位（哪条规则 / 哪一段 / 哪一句）    小，今天两条规则也需要
  M1-d  新增的检查走不阻断的通知类型                  小

模式二
  M2-a  加一条窄工具：某人在第 N 章知不知道某条秘密    小
  M2-b  数不出人时往前借上一章的 cast，只加不减        中
  M2-c  歧义称呼把所有候选都算在场，只加不减           小
  M2-d  第一章 / 全新书仍然全禁                        不动
```

**M1-a / M2-a / M2-c 都很小，可以先做。**
**M1-b 跟轨道阶段 2 是同一条路、同一个通知落点，一起做。**

# 验收

- 续写的 prompt 里**不再有**「【在场】未知」那一块，其余每一行都还带着信息。
- 起草一个刚开头的空章时，禁写清单**不再是全书全禁**，而是按往前借来的人算出来的。
- 「师兄」这种歧义称呼**不再把整章打成全禁**。
- 模型能问出「某人在第 N 章知不知道某条秘密」，答案带着章号。
- 保存之后，如果这一章对不该知道的人说破了什么，右栏出现一条**能点过去**的通知，
  且**不停掉**这一章的自动整理。
