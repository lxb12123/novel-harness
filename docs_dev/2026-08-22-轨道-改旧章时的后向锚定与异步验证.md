> 它不是素材（不是拿来照着写的），是护栏（写出来的东西不许跟它相抵触）。

## 要解决的事

作者写了很多章之后跳回去改第 2 章。今天引擎**完全不知道第 3 章之后存在**：

- 拼上下文时只取「比当前章更早」的；
- 续写只给光标**之前**、同一章之内的文字；
- 后台算权重时把章号更大的一律当成"还没写"。

于是改出来的东西可能跟第 47 章直接打架，而没有任何东西会发现。

---

## 一、触发：只在"不是最新章"时启用

比一下当前章号和全书最大章号，一次查询。**这个判断已经在用了**（后台算调度原点时就是这么干的）。

是最新章 → 照旧，什么都不变。不是 → 走下面这条路。

---

## 二、锚定：按相关性，不按位置

**不取"后面 N 章"**（区间是死的：猜小了漏、猜大了全浪费，而且铺垫的影响范围本来就不固定）。
**按"共同提到了谁 / 哪个地方 / 哪个物件"取。**

四级，前三级全免费、零模型调用：

| 级 | 做什么 | 量 | 花钱 | 今天 |
|---|---|---|---|---|
| 一 | 扫作者刚改的那段字 → 命中花名册里哪些东西 → 反查倒排表 → 后面哪些章的总结提到了它们 | 一串章号 | **0** | 索引在跑、函数在，**没人调** |
| 二 | 读那几章的总结 | 8 章 ≈ 960 字 | **0** | 同上 |
| 三 | 总结说不清 → 下探到那几章原文的**相关段落**（不是整章） | ≈ 1,000 字 | **0** | 定位能力在，"只取那几段"要写 |
| 四 | 用模型判"写的这段跟轨道抵不抵触" | 一次调用 | 花 | 见下 |

倒排表**六类都收**：人物、地点、势力、秘密、伏笔、**物件**。
所以「玄铁令第 64 章写着只能在水底唤醒，你第 2 章写它发白光」这种，
和人物那条线是**同一次查询**捞回来的，不用分别做。

（不收的是引擎内部的状态维度和章节本身——它们在总结里到处都是，进去全是噪声。）

### 第二级到第三级那个"够不够"的判断

模式二交给循环（模型自己决定要不要再查一次）；模式一先只做到第二级。
**现在定死规则就是拍脑袋**，等有真实案例再说。

## 三、信息隔离：写的那个看不到轨道

**这一条是整个设计的地基。**

后面章节的总结里，可能写着这一章的读者还不该知道的事
（第 64 章：「萧决终于知道自己身上养的是玄血蛊。」）。
把它给写第 2 章的模型看，等于把伏笔亲手告诉它——**那正是这个产品的核心主张会被从背后拆掉的地方。**

**解法不是过滤，是分开：写的和验的不必是同一个上下文。**

```
Writer 的上下文：前文、下文、前面章节的总结          —— 干净的，从没见过轨道
       ↓ 写出来
验证那一侧：轨道（可能带着不该出现的内容）+ Writer 写的那段
       ↓ 判
回给 Writer：一条结构化的评语，不含轨道原文
```

**验证那一侧可以用另一个模型**——它干的是判对错不是写文章，可以更便宜更快。
上下文本来就分开了，换模型是零代价。

### 回给 Writer 的那条评语，形状要限死

只许返回「第几句 + 跟第几章冲突 + 冲突类型」，**不许自由文本的理由**。

```
✅ 第 3 句 ↔ 第 64 章，设定冲突
❌ 「你写萧决不知道那件事是错的，第 64 章他才知道自己身上是玄血蛊」
```

结构化的出参能被机械检查，自由文本不能。作者要细节自己去翻第 64 章。

## 四、两个模式的形态

| | 模式二 | 模式一 |
|---|---|---|
| 什么时候验 | Writer 自己调工具，写完就验 | **落进正文之后，后台异步验** |
| 谁看得到轨道 | 那个工具（独立上下文） | 后台那一侧 |
| Writer 拿到什么 | 一条结构化评语 | 一条通知 |
| 挡不挡 | 不挡，它自己决定改不改 | 不挡，只提示 |

### 模式二：做成工具，不做成流水线

ADR 0019 第一条边界是「**工具表就是权限边界**」——这句话在这儿是字面成立的：
**那个工具有权看轨道，agent 没有。**

做成工具而不是写死的"写完必须验、验完必须改"，那条 ADR 的「循环归模型，不归代码」也保住了。

**但不能指望模型自觉去调。** 系统发现"不是最新章"时，要在那一轮的开场把这件事说给它听
（「你正在改第 2 章，后面还有 156 章已经写完了，动笔前先查一下轨道」）。
**判断在系统这边，调用在模型那边。**

### 模式一：异步，落在右栏的通知里

ADR 0019 明写模式一不适用它，理由是「停手 400 毫秒就要出结果的交互里塞不下第二次往返」。
**这句话仍然对**，所以模式一不在续写那一次里验：

```
续写建议照旧出来（不等验证）
  → 作者接受了、落进正文
  → 后台验一遍（跟保存后跑总结/抽取同一条路）
  → 不对 → 一条通知，不阻断
```

**落点是右栏那一格「通知」**（作者原本就加了那一栏）。
后端今天有三种通知类型（总结对不上 / 后台失败 / 验证阻断），
**加第四种是一次迁移 + 同一套渲染，前端不用动。**

不阻断这一条跟仓库一贯立场一致：能算准的当场算，算不准的事后告警，永不阻断。

## 五、还要补的两块（不在锚定这条链上）

**光标后面的同章文字。** 今天续写只给光标**之前**的。改老章时，光标后面那几千字是
**已经写好的正文**，模型看不到它，写出来可能跟紧接着的下一段接不上。

改老章时把整章都给（或前后各一截），但 prompt 里要分清楚：

```
【上文】  接着往下写
【下文】  已经写好的，别重写，写出来的要能接上它
```

不说清楚，模型会把下文也当成"要写的"，重写一遍。

**ADR 0019 那一格要补一句。** 它当年的六问里有一问是「多角色要独立上下文？」，
答案是「**不要**，查约束/跑检查/读正文全是纯函数」。

**那个理由在这儿不成立**：验证轨道不是纯函数（要模型判语义），
而且要独立上下文的原因**不是"角色不同"，是"写的那个不能看见验的那个看见的东西"**——
**这一条当年没考虑过。**

不是推翻它，是补一格：信息隔离这个理由成立，且落地形态是**工具**不是流水线。
不补的话，下一个人读到那张表会以为这件事已经被否掉了。

## 六、分阶段

```
阶段 1（接线，全免费）
  · "不是最新章"的判断
  · 第一、二级锚定接到写作那条路上
  · 续写改老章时把光标后的同章文字也给上

阶段 2（模式一的异步验证）
  · 后台验一遍，出一条通知
  · 通知表加第四种类型
  · 验证那一侧独立上下文，可以换模型
  · 评语形状限死

阶段 3（模式二的工具）
  · 包成一个工具，工具持有轨道
  · 系统在"不是最新章"时提醒它去调
  · 第三级下探交给循环自己决定

阶段 4（待定）
  · 第三级在模式一里要不要做、按什么规则触发
  · 等有真实案例再定，现在定就是拍脑袋
```

**阶段 1 全是接线，不花钱、不改语义、可以先做。**

## 今天的真实缺口，一句话

**不是缺一套检索，是缺一根线。**
索引在跑、反查函数在、定位能力在、通知那一格在——
**但写作那条路一次都不调它们。**
