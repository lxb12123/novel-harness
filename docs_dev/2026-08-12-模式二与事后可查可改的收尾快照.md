## 一 · 今天这一摊是什么状态

**能用了。** 模式二从「后端有个 loop」变成了「作者在浏览器里真的能用」，
而它写进书里的每一步，事后查得到、退得回。

一条链今天是通的：

```
开一段对话 → 说一句话
   → agent 用书内索引定位（目录 / 谁和谁同框在哪几章 / 摘要区间 / 一章正文，越往下越贵）
   → 起草（屏幕上一个字一个字长出来）
   → 它自己决定存进第 N 章（**不弹框**）
   → 活动记录里有那一行
   → 不满意就在版本历史里退回上一版
```

撑着这条链的几条设计，各一句：

- **工具表就是权限边界**（ADR 0019）。`ToolContext` 上没有连接、没有 `CanonWriter`
  ——「模型改 canon」在类型层不成立，不是靠纪律。
- **循环归模型，停止条件归代码。** 每一种停法都说得出自己为什么停，措辞唯一出处在引擎。
- **一轮不再是黑箱**（ADR 0024）：编排边跑边发事件、模型能停下来问作者。
  但**事件流里没有工具查到了什么**——推上屏过的东西改代码删不掉。
- **起草是提议不是写**（ADR 0022）：稿子落在候选表，既不进正文也不进对话；
  对话里只有 id + 定长预览 + 那一稿的自述。
- **落盘不问，但每步留痕**（ADR 0020 / 0021 同一条理由链）。唯一的闸不是「问你可不可以」，
  是**「拒绝覆盖你比它更晚改过的那一章」**。

**「能用到什么程度」的边界，说清楚免得被当成 bug：**

| 今天的真实形状 | 为什么它是这样 |
|---|---|
| **新建不了章** | 新开一章要起章标题，而章标题是切章的锚——切错了整本书章号会漂 |
| **模型写不了图** | 工具表全是「读 + 起草 + 问一句 + 记一条规矩」，一条都碰不到节点或边的 props |
| **agent 起的稿不跟作者的文风** | 见 §2.1——这是欠账，不是设计 |
| **逐字长出来的是稿子，不是回话** | 对话回复那一档不流式，理由见 §2.2 |
| **一轮的花销闸那个数从落地起没重裁过** | 见 §2.1——闸有两道（次数 / 按 token），要重裁的是后者 |

模块清单、路由、已知洞的**权威副本在 ARCHITECTURE**，这儿只留指针。

## 二 · 还欠什么

### 2.1 要修（按「谁挡着谁 / 谁最伤作者」粗排）

#### A. 作者马上就会撞到的

1. **作者的规矩：记得下，但看不见、也取消不了。**
   ADR 0023 的退路押在「**看得见 + 能取消**」上。引擎侧齐了（存 / 数重复 / 按章号过期 / 撤销），
   `remember_rule` 也已经接进工具表（`f10ddbb`）——**所以「一条规矩都进不去」这句话已经不成立了**，
   勘察那份写的是接线之前的状态。
   欠的是另一半：作者看不见现在哪几条生效，也点不掉。
   ⚠️ **写这份快照的当口，这一半正在落**（`api/chat.py` 工作区脏，两条 `…/rules` 路由已经出现）。
   **洞关没关以 ARCHITECTURE「工作台的已知洞」为准，别信这一行。**
   另：「整本书都这样」那条升格路径（进稳定前缀的那种）今天仍然零生产调用方。

2. **agent 起的稿不跟作者的文风。**
   会话上有 `house_style`，起草那一层拼请求时不传它。对话面板 2026-08-12 才落地，
   **作者第一次用就会撞上「它写的不像我」**，而那看起来像模型不行，其实是一根线没接。

3. **落盘会静默抹掉那一章里作者标的场景块。**
   方向是安全的（场景块没了退回从正文推，而推导是超集 = 多禁），进了快照、退得回来。
   **但落盘那句回话只说「章标题保持原样」，一个字不提场景块。**

4. **写作助手那一档的账答不出「为哪一章花的」。**
   四个写入方里三个已经在填章号，只剩它。后果比「少一个字段」重：
   同一张日志页上**一半的行有章号、一半没有**，「未记录」在一片有章号的行里
   读起来像「这一次不为任何一章花的」，而不是「我们没记」。
   ⚠️ **不能照会话章号填**：起草工具花的钱属于它被要求写的那一章，和作者此刻停在第几章可以不是同一个数。

#### B. 屏幕在说假话

5. **`GET /runs` 那条路上的 `endpoints` 恒空，而空 `endpoints` 在本仓契约里是一句断言**
   （「今天没有任何路由能改这个」）。它不走那道填坐标的工序，于是所有档一律空。
   两处比旧板子写的更重：
   ① 旧板子说「今天无害只因为底栏不渲染 jump」——**底栏根本不消费这个端点**，
   那个「无害的理由」挂在了一个永远不会触发的守卫上；真正的引信是活动记录页顶上那条用量条
   （它今天只读汇总，哪天读明细就当场骗人）；
   ② 有一档（恰好一条待审提案）**本来有三条真路由**，所以那是真的假话，不是「本来就空」。
   顺带：它会污染 ADR 0020 的观测点——「真的没入口」和「这条路没算」在出参上长得一模一样。

6. **`/matrix` 那句「这些称呼未在花名册中找到」对歧义称呼是错的，而且躺了三份。**
   歧义称呼**在**花名册里，只是指向多个人（后端确认歧义和查无此人都进同一个字段）。
   三处里**有两处根本不是 `/matrix`**，还有一条测试把这句措辞钉着，改的时候要一起改。
   **一份措辞三处拷贝**——正是本仓反复栽的那个病，这次躺在前端。

7. **屏幕守卫罩不住小写裸枚举值，而且它自认的范围比真洞还窄。**
   判据文件自己列了一串（`author` / `system` / `failed` …），可 `alive`
   **既不在那份自述里、也不在自守卫的探针里**——旧板子那句「有测试钉住它必须继续自己承认」
   会让人以为清单是齐的。
   收它必假红（一个小写英文单词和界面上合法的英文形状上分不开），
   **而假红的下场是被人加豁免、然后豁免被拓宽**。所以这一类只能在源头堵。

#### C. 账和闸

8. **可中断换掉了起草的 token 计数——那一次裁决还没做。**
   一开可中断就走流式，而只有一部分端点会在流式下报用量，
   **工作台设置抽屉里那两个占位符填的那一家不在其中** ⇒ 每一稿的 token 数退成「不知道」。
   （⚠️ 这句原本写的是「**README 教作者填的**」—— 假的，**README 一个字都没提过那家**，
   它只说「API 地址可自定义」。真正在教作者填的是设置抽屉的 placeholder。
   这句也是从旧板子逐字搬来的，同样没验。）
   旧板子给的三条路里，「先修底栏那个把空显示成 0 的合计」**已经执行了**（`2bcc3e1`），
   所以「一个诚实的空在屏幕上变成一个撒谎的零」不再是加速理由。
   **剩下的是「认了」还是「只在确认报用量的路由上开」——一次产品裁决，不是一个 bug。**

9. **模型联系不上那一路没有账，步数也不计那一次。**
   已经发出去、生成到一半被作者掐掉的 token 在两个口径上都不可见；
   方向和别的漏账口一样是偏低。（旧板子把它记成两条，是同一件事。）

10. **每加一条工具，成本闸就提前咬住一点——这条不是预存的，已经生效过一次。**
    供应商不报用量时，判据退回按 prompt 字节估，**而那份字节含整张工具声明**。
    工具表长了之后那条测试当场变红，阈值被抬过一次。加工具的那天要一起看。

11. **一轮的花销闸该重裁一次。** 上界是「步数 × 每步能并发几个调用」，
    而最贵那一档全是起草（每次一稿正文）。那个数从 loop 落地起没被重裁过——
    旧板子说它是「唯一的闸」已经不对了（后来加了批宽度闸、且每派发完一个就查一次），
    **但「该重裁一次」这句话仍然成立**。
    **它和上一条是同一个闸的两头，别读成互相矛盾**：上一条说量出来的那个数在往上涨，
    这一条说那个上限从来没跟着裁过。（旧板子上这一簇曾经有三条，方向看起来互相打架，
    因为它们量的其实是三个不同的计数器；今天只剩这两条。）

#### D. 会悄悄说错的

12. **候选稿那条路上「这一稿已经落过盘了」会过期。**
    按 id 读回全文那条工具交回的是整章正文（表里最贵的一条返回），
    而过期判据只认磁盘正文那一种形状，**认不出它**。
    诚实说清它比旧的那个洞轻在哪：候选是不可变的，它不会像磁盘正文那样「变了」；
    真正会错的是它随身带的「已落盘」那一位（稿子落盘之后作者又改了那一章）。
    **别照抄那个判据**——一稿不带章标题，直接比一定恒不相等 ⇒ 每一稿刚写完就被自己擦掉。

13. **滚动摘要会过期，而覆盖率只问「有没有」不问「新不新」。**
    **缺摘要是索引在那一章「瞎」，过期是索引在那一章「说错」**，而摘要是模型在那一层
    唯一的「这一章讲了什么」。今天靠磁盘时间戳兜一层（把「我没查」和「没过期」拆开），
    彻底的做法要一路动到前端契约。

14. **一条测试纪律，栽过一次值得记：假实现比真实现宽的时候，测试绿而产品错。**
    书内索引那个假事件端口忽略章号、比真库宽，于是事件轴上一个静默上限在测试里一直是绿的。
    假端口要和时态过滤那份唯一实现同解。

#### E. 退路还不够

15. **版本历史分不出「后台整理」和「写作助手改了我的正文」。**
    快照上没有 actor 列；而落盘那一行记的是「系统」——ADR 0021 时这是对的（落盘是起草的副作用），
    **ADR 0022 之后落盘是模型的一个显式动作**。关联键**是存在的**（落盘那行留了正文摘要，
    和快照对得上），只是没有出参把它们连起来。
    ADR 0022 之后被机器稿淹的速度慢下来了，但「作者能把系统做的和自己做的分开看」
    这条退路在这个粒度上还不成立。

16. ~~**回执上没有一个字段说「哪一章被写了」**，所以对话面板每跑完一轮就把全书正文的缓存
    全失效一次。同批还有一条：会话列表不轮询。（这两条是旧板子上别处一个字都没有的东西。）~~

    🔴 **整条作废，2026-08-12 落地当天由对抗性核实推翻 —— 而且它是「搬运连着假话一起搬」的
    活标本，留在这儿当病史。** 三处都错：

    - **「回执上没有那个字段」是假的。** `TurnReceipt.drafts` 每一稿带 `chapter` + `landed`，
      而且 `api/chat.py` 那个字段的 docstring 里**逐字写着这条余债已经还上了**。

    - **「所以每轮无条件重取」因果是倒的。** `hooks.ts` 里写着理由：字段在、

17. **R2 / R3 在作者手里仍然是死的，而模式二整个落地之后它一毫米都没动。**
    R2 和 R3 的两个判据字段全仓只被读、没有生产写入方（CLI、HTTP、前端一处都没有），

    作者无法声明「某某盟第 200 章才出现」或「某人死了」——那正是 R2 唯一的开火条件。

#### F. 要裁一次，不是要写一下午

18. **只改「他以为的是什么」而不翻认知类型，会撞同一个幂等键**，被当成重跑处理、只更 props。
    今天走不到那儿只因为入口先拒了。**它算不算一次 supersede，要单独裁一次。**

19. **改一条已确认情节的摘要还做不到**：同一条引语上物理装不下第二条已确认事件，
    「写新的 + 撤旧的」在这儿不存在。要么松掉那条唯一约束（丢掉「一句引语 ⇒ 一条事实」），
    要么宣布摘要是可原地改的展示字段。**这是 schema 裁决不是一下午的活。**
    还没升上去的那条路径照旧能改。

### 2.2 有意不做（理由今天重新验过，仍然站得住）

- **成本那一列恒空。** BYOK 之下引擎不知道作者签的什么单价，编一个是假话；
  出参里那个「有几次算得出价」把这个零的理由一起发出去。
- **记账失败会把一次成功的起草变成 500。** 取舍是明的：一条静默失败的记账
  就是日志页第二次骗人。**若改主意认为「宁可丢账不丢稿」，改动点只有那一个 `try`。**
- **「正在跑」不落库。** 落库的那个标志会在进程崩掉之后永远卡住，而清它需要一个没人会写的看门狗。
  重启之后没有任何一轮在跑，而那段对话照旧读得回来——恢复靠的是「缺哪几个工具结果」，不是一个状态位。
- **对话回复那一档不流式。** **不许为了让它流式去抬输出预算**：那样能力表没登记的端点会被
  fail-closed 拒掉，作者换个自建端点整个写作助手不能用。所以聊天里按停的粒度仍然是
  「这一次调用跑完就停」（起草那一档已经是真的逐字了）。
- **卷级摘要没有。** 今天这本书装得下；到几千章那天要「几十章压成一条」再分层定位，
  数据模型撑得住，今天不做。
- **谁知道什么是推断，不是文本事实。** 自动生效之后它是最可能出错的一维，
  而认知边界正是这个产品唯一的独家价值。**退路是可改 + 可查，不是事前批准**——
  而那条退路今天是真通的（矩阵那一格、事件的知情/在场名单，浏览器里都改得动）。
- **MCP 不做。** 工具表就是权限边界，而 MCP 的价值恰恰是「工具可插拔」：
  插进来一个第三方的「读图谱节点」就是当场泄漏。反方向（把本项目做成 MCP server 给别人查）
  是另一件事，撞 [`2026-08-04-正文真相源在磁盘与外部审计的边界.md`](2026-08-04-正文真相源在磁盘与外部审计的边界.md)。
- **填表式的「AI 起草」抽屉删掉了，不留第二个入口。** 它和「在场从正文推」（ADR 0018）冲突，
  而且一个功能不留两个入口。**后端那条起草路由一个字没动**——它现在是 agent 的起草工具。
- **保存章节之后不自动生成摘要；后台整理按「离开某一章」触发，不按「保存」。**
  那个哈希是正文的哈希，按保存触发 = 写一小时存 30 次就付 30 次钱。

## 三 · 接手最容易踩的坑

1. **别照任何一份 `docs_dev/` 排期，先读 ARCHITECTURE 的「当前状态」和「工作台的已知洞」。**
   这个仓库真的栽过：一份过期清单把三样**已经写完、被几十条测试覆盖着**的东西说成
   「一个字符都没有」，照它排期的人会去重写已完成的工作。**「已做完文档说没做」比反过来更贵。**
2. **空 `endpoints` 是一句断言，不是一个空位。** 它同时是 ADR 0020 那条推翻条件的观测口：
   编一个假按钮出来 = 把观测点关掉；让一条不填坐标的路混进来 = 把它污染。
3. **系统生成的坐标绝不许走作者那条路。** 面板的在场参数里，
   「过滤」那一个会**收窄**在场 ⇒ 少一批禁令 ⇒ fail-open ⇒ 泄漏；
   系统自己塞进去的坐标只能走**只加不减**那一个，而且推导为空那一档一律不加人
   （「一个人都没数出来」= 不知道谁在场 = 全禁，加一个人进去会把全禁塌成「只按他一个人算」）。
4. **加一条工具不是零成本。** 它进 prompt 字节（供应商不报用量时成本闸提前咬住），
   而且**每一轮、每一次调用都要重发一遍**——短的不是记性，是钱。
5. **措辞只有一个出处。** 说给作者的中文全在后端；前端再翻一遍就是第二份措辞源，
   §2.1 第 6 条那三处拷贝就是现成的反例。同一条纪律的另一面：**别手写前端夹具**——
   两份手写的东西互相验证正是那条缝原本的病。
6. **假实现比真实现宽的时候，测试绿而产品错。**
7. **写迁移之前先看有没有开着的 dev server。** 现在有机械保护了，**但那是备份不是免疫**（下一节）。

## 四 · 事故史（**不是限制，别再排进待办**）

**开着 L1 dev server 写迁移 = 对作者的真书做了一次没有备份、没有确认的 schema 变更。**
机制是真的：迁移文件同时改了源码 → `--reload` 重启 → 起服务时跑建表 → 真书的库版本自己往上跳。
**发生过三次**（同一台从月初就开着的 dev server），三次都无害——都是加列、有默认值，
章数 / 节点 / 决策日志逐项复核过，数据完好。

值得记的是**它怎么收场的**：

- 前两次的处置是一条规矩（「下次写迁移前先 Ctrl-C」）。**那条规矩失败了两次。**
- 第三次改成**机械保护**：迁移在真的要改 schema 之前，先给有数据的库拷一份备份
  （必须用 `VACUUM INTO`——库是 WAL，只拷主文件会得到一份看起来正常、其实少了最近全部改动的备份；
  拷不成就**拒绝迁移**）。
- **第三次那一回它在作者的真书上真的接住了**：书旁边出现了那份备份文件，
  完整性检查通过、章数和体积都对。**也就是说这个机制不是在测试里绿，是在野外跑过一次。**

它同时帮到真作者：一次坏迁移落在几百章的书上是不可恢复的，而作者不会手动备份。
**这条比「下次记得 Ctrl-C」值钱得多**——留着它是因为「规矩失败两次 ⇒ 换成机械保护 ⇒
机械保护在野外真的生效」这条闭环，本仓只走通过这一次。

## 五 · 这份快照什么时候作废

**它是快照，不是板子——它不接受打勾。**

§2 里任何一条被做掉时，**改的是 ARCHITECTURE 的「当前状态」/「工作台的已知洞」**，
那儿是权威；本文原地不动，跟着日期一起变旧。**回来改这一份 = 它既不是 2026-08-12 的事实、
也不是今天的事实。**

真要再记一次这一摊，**另开一份新日期的快照**（一份快照一个文件，时间戳才有意义）。
