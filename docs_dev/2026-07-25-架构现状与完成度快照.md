## 挡在路上的只有两件事，其余都是加法

### 1. 空花名册洞（今天就能做，立刻见效）

后端 `POST /api/projects/{pid}/nodes`（`api/app.py:708`）与 `.../aliases`（`:744`）**都在**，
前端**零调用**；而导入 TXT 只切章、不抽实体（ADR 0004 是有意的）。

于是首次导入一本书之后花名册是空的 → declare 写闭环里的「填称呼」必然 `UnknownName` 404
→ **认知矩阵 / 约束 / declare 三样头牌全部起不来**。作者今天仍得回终端 `nh declare character` 起头。

这是「非程序员能用」这条标准上最硬的洞，也是唯一一个**今天就能做、且立刻见效**的。

### 2. M2 kill-gate 没跑（决定项目定位）

整个项目押的那个宝——**「提前告诉 AI『这个角色现在还不该知道 X』，AI 就不会写漏」**——
**到今天为止没有人验证过它是不是真的**。

协议已经冻在 `docs/EVAL_PROTOCOL.md`，但**它还是 untracked**。
而那份文件第 11 行自称「先 commit 的 git 时间戳是预注册成立的**唯一**证据」——
**在它进 git 之前，之后任何 `runs/*.jsonl` 都不具备预注册效力。**

**这是全项目最便宜、且最紧急的一步**：一次 `git add` + `commit`，几秒钟，
但它决定后面所有实验算不算数。拖着不提交等于把未来所有实验的效力挂在空中。

## 我当时的判断

1. **别按「完成度百分比」安排工作。** 引擎那 8981 行已经过了最难的部分（时态图 + 声明层），
   剩下的大头不是代码量，是**两个洞和三条没验的门槛**。再写 3000 行引擎代码，
   离「作者能用」也不会更近。
2. **最短路径是先做那两件挡路的**，且顺序建议是先 commit `EVAL_PROTOCOL.md`（几秒），
   再补空花名册洞（前端调两个已有路由，工作量小、见效立刻）。
3. **真书这件事被低估了。** 三条门槛卡在同一个前置上，而那不是技术问题——
   是「去弄一本 TXT」。它现在挡着 R5 的生死判断，也挡着切章器的唯一一次真实验收。
4. **M2 判负是被允许的结局。** README 里写着「砍掉 AI 起草线，定位改成作者的记忆外挂」。
   所以在 kill-gate 出结果之前，别把桌面壳、签名、API key 入口这些**只对起草线有意义**的东西做掉。
