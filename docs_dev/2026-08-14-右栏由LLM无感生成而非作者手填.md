## 规则原文（作者，2026-08-14）

> 右边那栏里边的东西由 llm 在相应的时期去进行**无感生成**，生成后用户可以明确看到内容，
> 并且用户可以**手动去修改增加**之类的，然后这些值调用时候就可以取出来用。
> 那你现在很多东西，都是需要靠用户手动抽取之类的，**这个太烂了**。

## 拆成四条可验收的

右栏那九格（花名册 / 认知矩阵 / 状态 / 约束 / 局部图 / 证据 / 章节总结 / 检查 / 待确认）
**每一格**都要同时满足：

1. **谁在什么时刻生成它？** —— LLM，在恰当时机，**不由作者点按钮触发**。
2. **作者在哪儿看得见？** —— 明确显示，不是藏在库里的隐式状态。
3. **他怎么改？** —— 手工路径存在，但它是**改**和**增补**，不是**从零建**。
4. **谁取用它？** —— 写作上下文 / 规则 / 面板。

**三个问题答不上就是没做完**，哪怕代码、测试、界面都齐了。

### 最硬那一条的证据

- `first_appears_chapter` 的唯一写入方：`Ledger.declare_first_appearance`（`declare.py:617`）
- `EdgeProps.value_key = HealthValue.DEAD` 的唯一写入方：`Ledger.declare_dead`（`declare.py:609`）
- 抽取器的 `state_updates` **只映射到 `LOCATED_AT`**（`extract/ingest_helpers.py:216`）

这两个字段分别是 **R2 FUTURE_LEAK** 和 **R3 DEAD_SPEAKS** 的输入。没有 LLM 写入方 =
这两条规则要靠作者手填才开得了火 —— 正是这条规则要消灭的形态。

**而 `checks/__init__.py` 开头那段警告记着**：2026-08-02 到 08-13 之间，这两条规则
每天绿着、生产上结构性哑火，因为那时连手工写入方都没有。补法是那两条 CLI，
**所以今天不能因为「它是手工的」就把它删掉** —— 得先有 LLM 那一侧，再撤手工那一侧。
