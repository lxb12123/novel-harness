# 2026-07-25 给决策日志开一个独立文件夹

**决定了什么**：新建 `docs_dev/`，放我自己平时的决策记录，命名 `YYYY-MM-DD-主题.md`。
同时在 CLAUDE.md 里写明：AI 不主动读、不主动写、不主动整理这个文件夹，且它不是权威。

**为什么**：起因是想搞清楚 `docs/` 里到底放的是什么。搞清楚了：
`docs/` 里四份文档 + 8 份 ADR 全是**工程约束**，AI 每次动代码前都会去读（CLAUDE.md 指路）。
那我自己平时想事情留下的东西没地方放——塞进 `docs/` 会污染约束层，
AI 读到我的半成品想法会当成规矩执行；不写下来又会忘。所以单独开一个。

**放弃了什么**：
- 放弃了「塞进 `docs/` 加个前缀区分」——同一个目录里混两种权威等级，迟早出事。
- 放弃了「记在 CLAUDE.md 的备注里」——CLAUDE.md 每次会话都自动进 AI 的上下文，
  我的思考过程进去只会挤占它的注意力，而且越写越长。
- 放弃了 gitignore 掉——决策记录的价值就在于能回溯，不进 git 等于没有。

**什么情况下要推翻它**：如果发现 `docs_dev/` 里的东西反复被搬进 `docs/`，
说明这一层是多余的中转站，那就直接写 ADR，砍掉这个文件夹。

## 顺带修的一个洞

同一次发现：`docs/UI_ARCHITECTURE.md`（32KB，第二大的文档）**在 CLAUDE.md 里一次都没被提到**。
它只被 `frontend/README.md`、ADR 0007、`api/app.py` 的注释引用。
意味着 AI 被叫去改工作台时，读完 CLAUDE.md 根本不知道有这份设计方案存在。
已经把它和 `EVAL_PROTOCOL.md` 一起补进 CLAUDE.md 的「动手之前先读」，
并按「必读 / 按需读」分成了两组。
