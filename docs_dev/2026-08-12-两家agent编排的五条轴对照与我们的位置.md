## 证据等级标注（这个机制必须保留）

- **【眼见】** = 在 Claude Code 这个会话里直接观察到的
- **【拆解】** = 来自 Codex 源码拆解（`openai/codex` 是开源的，Apache-2.0）
- **【第三方】** = 别人写的分析
- **【实测】** = 在**本仓库**跑出来的数（本文新增的一档，见下）

**Claude Code 不开源**，所以关于它内部的只有【眼见】和【第三方】，**不许把听来的写成看见的**。

### ⚠️ 【眼见】要分清是谁的眼睛（落笔时发现的一条）

这份文件是**子 agent** 写的，而它的系统提示词和主会话那一份**不是同一个**。所以原稿里的
【眼见】其实混着两种：

| | 谁看见的 | 本文怎么标 |
|---|---|---|
| 轴③ 延迟加载 | 我自己的提示词里就有（"Some tools are deferred… use ToolSearch"），而且**我这一轮真的调了一次 `ToolSearch` 才拿到 `WebSearch`** | 【眼见·自证】 |
| 轴④ 后台 subagent + 通知 | 我自己的提示词里写着"Subagents run in the background by default; you'll be notified when one completes" | 【眼见·自证】 |
| 轴① "a denied call means the user declined it" | **不在我的提示词里**，是维护者在主会话里读到的 | 【眼见·维护者】 |
| 轴② 压缩出来的是结构化清单 | 同上，维护者在主会话里看到的那次压缩 | 【眼见·维护者】 |
| 轴⑤ `[Request interrupted by user]` | 同上 | 【眼见·维护者】 |

**不降级、也不冒充。** 维护者亲眼看到的仍然是【眼见】；只是标出来哪几条**我复核不了**——
一份连"是谁的眼睛"都分不清的对照表，下一次就会有人拿它当源码读。

## 五条轴

### ① 谁来批准一次危险的工具调用

- **Codex**：**另一个模型**给这次调用打风险分 0–100，**< 80 自动放行**，超时和解析失败都拒绝【拆解】
  > **一条诚实说明**：OpenAI 自己的公开页面确实描述了同一个**形状**——把计划中的动作和最近的
  > 上下文发给一个 "auto-approval subagent"，低风险自动批、高风险停下来问【第三方】。
  > 但**那个 0–100 的量表和 80 这个阈值，公开页面里查不到**，它只出自源码拆解那一路。
  > 形状可信，数字请当【拆解】读。
- **Claude Code**：**人**。系统提示里写着「a denied call means the user declined it」——
  中间没有任何模型当法官【眼见·维护者】
- 一句话：一个信任模型的判断力，一个信任人的判断力。前者能无人值守跑一整夜，
  代价是安全性变成概率的；后者卡人，代价是你得在场。

### ② 上下文满了怎么办

- **Codex**：**整段总结**。拆解自评「比 Claude Code 的四层级联简单——总结一切而不是外科式编辑——
  用粒度换实现清晰」【拆解】
- **Claude Code**：**外科式**。这段对话被压过一次，压出来的不是一团散文，是一份结构化清单
  （做了什么 / 改了哪些文件 / 用户说过哪些话逐条列着）【眼见·维护者】
- 摸得到的差别：**粗压丢的是「他当时到底怎么说的」，细压把那句原话留着。**

### ③ 工具表大了怎么办

- **Codex**：三层分派（定义 / 路由 / 编排）+ 聚合 MCP，**全表都发**【拆解】
- **Claude Code**：**延迟加载**。系统提示里二十来个工具**只给了名字**，用之前要先调 `ToolSearch`
  把参数说明取回来【眼见·自证】

### ④ 并发跑到哪一层

- **Codex**：**一轮之内** —— 只读工具拿读锁并行，会改东西的拿独占写锁【拆解】
- **Claude Code**：**跑到轮次之外** —— subagent 后台跑，跑完发通知【眼见·自证】
- Codex 是「这一步里三个查询同时发」；Claude Code 是「这件事你去干，干完喊我，我先干别的」。
  后者要的东西多得多（任务表 / 通知 / 跨轮次身份），换来的是人不用坐着等。

### ⑤ 按停之后

两家一致：**保留半截 + 标注**。Claude Code 的标注是 `[Request interrupted by user]`【眼见·维护者】；
Codex 是 `Op::Interrupt` + Tokio cancellation token 一路传下去【拆解】。

## 我们站在哪（**每一条都核实过，改动在文末**）

### 像 Claude Code 的两条，而且都是有意选的

#### 1. 外科式剪枝（**原稿说「明确不整段总结」，这句被改掉了**）

[ADR 0023](../docs/adr/0023-context-is-pruned-by-rebuildability.md) 决策一的排序判据确实是
**「可不可重建」**，不是「新不新」：作者说过的话永不动 → 作者的规矩升格 → 图谱/正文的工具返回随时丢
（"丢掉不是有损，是升级"，重查回来的更新鲜）→ 中间推理丢。**这一条成立。**

但**它没有禁止总结**。ADR 0023 的原话是：

> **总结（compaction）仍然受边界四管**：该留「作者的意图、被否决的方向、现在写第几章、
> 文风偏好」，**禁止含**「`must_not_reveal` 的内容、谁知道 / 不知道什么、任何绑章号的
> 状态 / 秘密名 / 未登场实体名」。

**所以准确的说法是三句，不是一句：**

1. **今天全库一个字都不摘要。**【实测】`agent/loop.py` 的模块 docstring 自己写着"这里只剪不压"，
   而 3.4 那一层（`api/chat.py`）也没有任何压缩——`grep` 全仓找不到一个对话压缩的实现。
   `draft/rolling_summary.py` 是**章节**摘要，不是对话压缩，两回事。
2. **最后一档不是砍作者的话，是停下来。** `project()` 只有三档剪枝（老 `tool_result` 删内容留壳 →
   老 `tool_call` 连壳带调用成对拿掉 → agent 中间推理），**没有第四档**；剪完仍然装不下就把
   `over_budget` 立起来，`run_turn` 报 `CONTEXT_FULL`，对作者说的那句是
   「这段对话说得太长，装不下了……**你说过的话一句都没被删掉**」。
3. **它留了第二个口子，而且是有意钉死的**：`draft/capabilities.py` 的
   `server_context_management`（三档 `NONE / OPAQUE / REPORTED`，未登记 fail-closed）——
   **注册表里全部路由都是 `None`，全库零消费者**。ADR 0023 落地当天就自己修订了开启条件：
   在 `chat.completions` 这个无状态协议上，"我们已经放弃的那部分"是**空集**，
   而且**服务端不知道第几章**。所以它今天是一个占位，不是一条路径。

**理由那一半原稿是对的，而且是我们独有的**：压成散文之后「他此时还不知道」——
**「此时」是第几章？**（ADR 0019 边界四，同 ADR 0017 拦 wiki 的那条论证。）

#### 2. 半截保留 + 标注（ADR 0022 + 迁移 010）——**成立，而且落到了五个读端**

【实测】迁移 010 的注释写死了理由（"按 id 读回这一稿时，这个标注必须跟着一起回来"），
而它今天真的落到了这几处：

| 读端 | 在哪 |
|---|---|
| 库 | `draft_candidate.stopped_reason`（迁移 010） |
| **模型（按 id 读回）** | `agent/tools.py::_handle_read_draft` → `DraftFullText.stopped_reason` |
| **模型（就在被打断的那一轮）** | `agent/drafting.py::_stopped` 抛的 `ToolRefused` 那句话里就带着"它没写完，多半断在半句上，**别把那个断口当成一种写法**" |
| HTTP | `api/chat.py::_draft_view` → `TurnReceipt.drafts` 和 `GET …/drafts` |
| 屏幕 | `frontend/src/components/DraftCandidates.tsx`（措辞照抄后端，前端不许自己造一句） |

措辞的唯一出处是 `agent/drafting.py::AUTHOR_STOPPED_NOTE`。
**而且这个仓库的"标注"不止这一处**：`agent/loop.py` 里另有四条同样形状的占位常量——
`PRUNED_RESULT`（剪掉的工具返回）/ `STALE_MANUSCRIPT`（作者改过之后那份正文）/
`UNRUN_CALL`（一批停在中间没跑的）/ `LOST_RESULT`（canonical 里永远补不上的缺口）。
**留占位而不是删，一半是协议要求**（OpenAI 兼容的 wire 上一条没人接住的 `tool_call` 就是 400），
**另一半才是语义**。这一条比原稿说的强：不是"我们也这么做"，是**这个仓库把它做成了一个通用形状**。

### ~~像 Claude Code 的第三条：审批交给人~~ ——**这一条整条是错的，改掉**

**我们这儿今天没有「批准」这个动作，一个都没有。**【实测】`src/novel_harness/agent/`、
`src/novel_harness/api/` 里 `approve` / `approval` / `permission` / `批准` / `授权`
**零命中**；`frontend/` 里也没有任何"允许这次调用吗"的 UI。

不是"还没做"，是**被两份 ADR 显式拆掉的**：

- [ADR 0020](../docs/adr/0020-clean-extraction-auto-canon.md)（2026-08-10）把**事前批准**整个换成
  **事后可查 + 可改**。`activity.py` 开头那条注释就是这次裁决的落款。
- [ADR 0021](../docs/adr/0021-agent-writes-drafts-without-asking.md)（2026-08-11）推翻了
  ADR 0019 边界一的最后一句「写正文必须作者确认」。[ADR 0022](../docs/adr/0022-drafting-is-a-proposal-not-a-write.md)
  改了机制、**原样保留了"落盘仍然不问作者"**。

**那边界一今天靠什么成立？靠类型和入参形状，不靠任何一次判断：**

| 闸 | 长什么样 | 在哪 |
|---|---|---|
| 模型改不了 canon | `ToolContext` 上**只有 `StoryGraph`**，没有 `Connection`、没有 `CanonWriter`；`EventStore` 那三个写方法被收窄成只读的 `EventIndex` | `agent/ports.py` |
| 模型不能"只写不草" | `save_draft` **只收一个候选 id，收不到一个字文本**——能进磁盘的只有后端刚按那一章约束生成出来的东西 | `agent/tools.py` |
| 秘密出不去 | 出参一律收窄到 `NodeRef`（id/label/name）+ 纯量，`Node` / `StateSnapshot` / `KnowledgeMatrix` 一个都不出（`NodeProps` 是 `extra="allow"`，`twist` 会穿过任何一次 `model_dump_json()`） | 同上 |
| 模型递不回过期约束 | `DraftAsk` / `SceneConstraintsArgs` 上**没有约束字段**，两个都是 `extra="forbid"` | 同上 |

**唯一一道运行时闸是 sha 闸**（拒绝覆盖作者比它更晚改过的那一章）——**它也不是审批，它不问人，它比哈希。**

**所以原稿那句"审批交给人，但理由不一样"要整条换成：**

> **我们这儿没有审批这个动作。** 边界一是在**类型层**堵的，
> 而不是在运行时问谁——**连问都不问，是因为根本没有那条路可走。**

原稿说"秘密有没有到模型手里是个**集合成员问题**，可判定"——**方向对，位置说错了。**
真正的形状是：可判定，**而且判定被推到了类型层和测试里，运行时一个判断点都不留**。
集合判断那一层在别处：`panel/constraints.py` 算 `must_not_reveal`（cast × secret 的集合查询，
ADR 0004 / ADR 0005），以及 `tests/test_agent_tools.py::leaks` 那张**子串网**——喂一本带
`twist` / `plot_note` 的书跑完整链路，在**模型看得见的十三个返回面 + 工具声明 + 交给起草侧的那份约束**
上逐个搜那几种毒，连 `"props"` 这个键本身都单独算一条违规。
**用模型去答等于把确定的换成概率的（ADR 0005）——这句原样保留，它是对的。**

> **一个必须说清的例外，否则"零审批"是句假话**：界面上确实有一个「待确认」面板
> （`ProposalReviewTab`，M4）。但**它确认的是"书里发生了什么"这一类事实**
> （抽取出来的冲突 / 低置信 / 新人物三个例外 bucket），
> **不是"准不准这个 agent 干这件事"**。两者根本不在一条轴上，别混。

而 Claude Code 那个"后台跑完喊我"的形状，**我们一个字都没有**。

## 那笔"工具说明书吃掉 30%"的账，今天重新量了一遍

【实测】2026-08-12，`uv run python` 直接调 `tool_declarations()` / `tool_declaration_units()` /
`project()` 量出来的：

| 量 | 数 | 出处 |
|---|---|---|
| 工具条数 | **9** | `agent/tools.py::TOOL_TABLE` |
| 工具声明 | **5,171 字** | `tool_declaration_units()` |
| 地板（稳定前缀 + 工具声明 + JSON 信封） | **5,571 字** | `project(空对话, budget_units=0).payload_units` |
| 其中 `AGENT_SYSTEM_PROMPT` | 326 字 | |
| `DEFAULT_MEMORY_BUDGET.total` | **17,000**（8,000 + 3,000 + 6,000） | `draft/product_context.py` |
| `run_turn` 的默认 `budget_units` | **22,571** = 5,571 + 17,000 | `agent/loop.py:1174-1177` |

**所以"5,171 / 17,000 = 30.4%"这个数没错——但它后面那半句已经不成立了。**

ADR 0023「前置」写的是"留给对话历史的只剩 11,429 字"。**那是落地之前的形态。**
落地时代码走的是**加，不是扣**——`agent/loop.py` 的注释把理由写死了：

> 从对话的额度里扣掉它们，对话能记住的东西就凭空少一截，而**加一条工具会再少一截**……
> 最贵的那一档症状是：一条按 `return_units` 截好的返回在**下一次**投影里被剪成占位……
> 于是那次调用等于没发生（钱花了、那段字进了持久化的对话却从没被读过），模型再查一次，
> 三次之后撞上 `REPEATED_CALL`，作者收到的说法是「它在反复查同一件事」。

**今天真实的三个数：**

| 口径 | 工具声明占比 |
|---|---|
| 相对**对话额度** 17,000（能力表**没登记**这个模型时的兜底） | **30.4%** |
| 相对**真正那份 payload 的默认上限** 22,571 | **22.9%** |
| 相对**登记了的路由**（`gpt-5.6` / `deepseek-v4-pro`，1M 窗口 ⇒ `return_units` 撞 `MEMORY_UNITS_CEILING` = 60,000 ⇒ 预算 65,571） | **7.9%** |

**结论：30% 是最坏那一档的数，不是常态**，而且它已经不再从对话历史身上扣了。
但那句"每加一条工具，所有会话的记性都变短一截"**仍然值得留着**——只是今天它变短的是**钱**，
不是记性（地板加在预算之上，每一轮每一次调用都在付那 5,171 字）。

顺带记两个数以后好对：`PAYLOAD_ENVELOPE_UNITS = 256`（量不到的那层信封的容差，
实测五条路由 + 一个本地端点在 **53–129 字**之间）；
`StopReason` 十个取值（`DONE` + 代码自称的"九种停法"）。

## 两家都没有的那一条 —— **原稿是强断言，我找到反例了**

原稿写的是：

> 他们的权限边界管的是「**能对这台机器做什么**」—— 所以沙箱、审批、写锁是核心。
> 我们的边界一管的是「**什么信息允许到达模型**」。
> 沙箱对这件事一点用都没有，Guardian 也判不了它 —— 而它是这个产品唯一的独家价值。

**"两家都没有这个形状"这半句站不住。** 反例：Claude Code 的 `settings.json` 里
`permissions.deny` 支持 `Read(**/.env)` 这样的规则，命中就报
"Permission to read … has been denied"，而且文档说它会**连带影响内建工具**（读不到的文件会被略去）【第三方】。
**那就是一条"什么信息允许到达模型"的边界，不是"能对机器做什么"。**

**但三条区别是真的，而且它们才是那句话本来想说的东西：**

1. **它是路径谓词，没有时间轴。** `Read(**/.env)` 永远为真或永远为假。
   我们的边界一 + 边界五是：**同一行数据，第 90 章视角允许、第 40 章视角禁止**——
   谓词被一个**故事时钟**参数化（`project(canonical, chapter)`，闭开区间 `[valid_from, valid_to)`）。
   任何权限文件里都没有这根轴。
2. **它只会「拦」，我们做的是「译」。** deny 只能在"全给"和"不给"之间选。
   `scene_constraints` **两个都不选**：它返回秘密的**显示名**（`血脉秘密`）和未登场实体的**首现章号**，
   **永不返回内容 tell**（`玄血蛊`）。模型必须知道"有这么一条不许说破"才能遵守它，
   同时**永远不知道它是什么**——**一条 deny 规则表达不了这件事**，而这正是产品能成立的地方。
3. **执行方式不同。** 我们那一侧是类型保证（`ToolContext` 上没有写入面）+ 一张跑在 CI 里的子串网；
   而那些 deny 规则被多次报告为**未被真正强制**（`anthropics/claude-code` 上有若干条这样的 issue）【第三方】。
   **这一条只当参考**：拿别人的 bug 单去论证自己的架构不体面，也不牢靠——issue 会被修。

**所以那句话的正确版本是：**

> 权限边界这个东西两家都有，**"什么信息允许到达模型"这个方向他们也有**（deny-read）。
> **他们没有的是这条边界的两个性质：它被一个故事时钟参数化，而且它的动作是转译而不是拦截。**
> 沙箱对这件事仍然一点用都没有——沙箱管的是进程，管不了"同一条事实在第 40 章该缩成什么形状"。

（Codex 那一侧我没去翻源码找反例，**所以那半句我只能说"没找"，不能说"没有"**。）

## 写给作者的一节：我们和他们，结构上只差一格 —— 以及那一格值多少

> 这一节是作者点名要的（"让我了解一下我们的架构具体是怎么样的"），所以它是**解释**，不是约束。
> 它躺在 `docs_dev/` 里不矛盾：**它不改变任何一个工程决定**，只是把上面那些对照说给不写代码的人听。
> 下面每一个数都是**在本仓真的量出来的**，量法写在最后。

### 一、先说结论：结构上只差一格

一个 AI 写作工具，内部大致是三段接力：**模型** ↔ **编排**（决定叫哪个工具、什么时候收手）
↔ **工具**（查约束、读正文、起草）↔ **界面**（你看见的那块屏）。
每两段之间都有一道"缝"，缝可以是**同一个进程里的一次函数调用**（快到量不出来），
也可以是**一次网络请求**（哪怕对方就是本机）。

三家摆在一起，只有一格不一样：

| | 模型 ↔ 编排 | 编排 ↔ 工具 | 编排 ↔ 界面 |
|---|---|---|---|
| Codex | 流式 HTTP | 进程内 | **进程内**（TUI 同进程） |
| Claude Code | 流式 HTTP | 进程内 | **进程内**（终端 UI 同进程） |
| **我们** | 流式 HTTP | 进程内 | **HTTP ← 只有这一格不同** |

**他们的"一问一答"压根没有传输层**——界面和引擎是同一个进程，
读一个文件就是一次函数调用，微秒级。我们那一格走的是 HTTP。

### 二、那一格的价钱：**大约 1 毫秒**

同一个端点、同一台机器、真的开着 socket，一层一层加上去量（每档 200–300 次取中位数）：

| 量的是什么 | 耗时 |
|---|---|
| ① 引擎直调（**含开一次、关一次数据库连接**） | **0.832 ms** |
| ② ＋ 路由 / 校验 / 序列化（还没走网络） | **1.310 ms**（+0.48） |
| ③ ＋ 真的走一趟本机 socket | **1.878 ms**（+0.57） |

**HTTP 那一整层 ≈ 1 毫秒。**

这个数本身没有意义，**要紧的是拿什么跟它比**：

- **开一次数据库连接就要 0.83 毫秒。** 也就是说，走一趟 HTTP 大约等于**多开一次库**——
  而我们本来就一直在开库。
- **人能察觉到的最小间隔是 200 毫秒左右。** HTTP 这一层是它的**两百分之一**。
- **一次起草是 30 到 60 秒。** HTTP 这一层是它的**三万到六万分之一**。

一句话：**这条差别在这个产品里量不出来。** 你在屏幕上永远不会因为它多等一下。

### 三、为什么我们那一格非得是 HTTP

因为**界面是浏览器里的 JS**，而引擎是 Python。这两个天生就不是一个进程。

**就算以后做成桌面安装包也一样。** 那个方案早就定了
（[`2026-07-25-分发形态定为桌面应用走C方向.md`](2026-07-25-分发形态定为桌面应用走C方向.md)：
PyInstaller + pywebview，用系统自带的 WebView）——而那份文件里写的实现，
**本身就是"`nh serve` 加一个窗口"**：起一个本机端口，让窗口去打开 `http://127.0.0.1:那个端口`。
装机之后 JS 仍然跑在系统 WebView 里，仍然是两个进程。

**确实有一条绕过去的路**：pywebview 提供了 JS ↔ Python 的直通桥（`window.pywebview.api`），
桌面壳里可以不走 HTTP。**但那样一来，开发时（浏览器）和装机后（桌面壳）就是两条不同的传输**——
**两份东西迟早会漂**，而"同一件事有两份实现"正是这个仓库一直在治的那个病
（这份文件前面那些"拷贝会骗人"的例子，全是同一种病的不同长相）。

所以：**HTTP over loopback 买的是"一条传输同时管开发和发布"，而这个价钱是 1 毫秒。**

### 四、那为什么还要换掉它？——**不是因为慢**

**这是这一节的重点，也是最容易被误解的一句。**

要换掉的那一条，跟性能没有半点关系。1 毫秒对一个要跑三分钟的操作毫无意义。
问题在于**"请求 / 响应"这个形状本身不能"推"**：

> 你按下发送 → 屏幕转圈 → 三分钟后，所有东西**一次性**全出来。

中间那三分钟里，它其实一直在干活：查第 40 章不许说破什么、读上一章的结尾、
同时写三稿……**但这些你一个字都看不见**，因为一次请求只能在**结束时**回答一次。
想在中途显示"正在查第 40 章的约束""第 2 稿写完了，第 3 稿还在写"，
**在任何延迟下都做不到**——哪怕 HTTP 快到零毫秒，也做不到。

**那不是性能问题，是能力问题。**

### 五、所以"像 Codex 那样"这句话，要拆成两半

| | 能不能拿 | 为什么 |
|---|---|---|
| **事件流**（编排边跑边往外发事件） | **能拿，而且这就是下一刀** | 那是他们真正的设计价值，**跟传输快慢无关**——它解决的是上面那个"看不见中间过程" |
| **进程内 CRUD**（界面和引擎同进程） | **拿不了，也不该拿** | 拿它就要放弃"一条传输管开发和发布"，换回来的是 1 毫秒 |

**顺带说清一件事：那些"问一句答一句"的操作（打开一本书、列出人物、存一章）继续走 HTTP
不是妥协，是它们本来就长那个样子。** 换成长连接一分好处都没有，只多一套要维护的东西。

> 一句话收尾：**我们和他们结构上只差一格，那一格值 1 毫秒；
> 而真正要补的东西（让你看见中间过程）跟那 1 毫秒毫无关系。**

**量法**（给以后想重跑的人）：脚本在本次会话的 scratchpad 里
（`…/scratchpad/perf.py`），用的是我们自己的 app、真 loopback socket、同一个端点
（`GET /api/projects`），三档分别是引擎直调 / FastAPI `TestClient`（有路由无 socket）/
`uvicorn` + `httpx` 走真端口。**scratchpad 会被清掉，这几个数就是当天的快照。**

## 结论

**那一刀不是「从 Claude 式转成 Codex 式」。**

内核已经选定并且已经落地：**外科式剪枝**（而且是"只剪不压"这个更硬的形态）、
**边界一在类型层而不是在审批里**、**半截保留 + 标注**（五个读端 + 五个占位常量）。
Codex 式的东西我们**已经有一条了**（轴④ 一轮之内并发，`parallel_tools=3`），
还差的是**对外通道**（queue-pair / 事件流：今天零 SSE、零 WebSocket，`/turn` 是一次阻塞 POST）。

> **补的是通道，不是内核。** 怎么剪 / 谁批准 / 边界一，一个字不动。

**而那条通道要补的不是速度，是"能不能在中途往外推"**——
上一节量出来的那 1 毫秒就是这句话的证据：**慢不是问题，形状才是。**
