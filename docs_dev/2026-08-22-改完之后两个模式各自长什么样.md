# 模式一（协助模式）

**这个模式唯一会生成正文的动作是行内续写。** 整章起草不在这个模式里
（「AI 起草」抽屉 2026-08-10 删，前端那个 hook 2026-08-14 删）。

## 改完 · 情况 B —— 跳回去改老章（多两块）

```
……情况 A 的全部内容，另外多出两块……

【下文】                                                  ← 轨道计划新增
（光标后、同一章已经写好的文字）
—— 这一段已经写好了，别重写它；你写出来的要能接上它

【轨道】后面已经写定的                                    ← 轨道计划新增
- 玄铁令只能在沉舟渡的水底被唤醒（第 64 章）
- 苏挽独自下崖，未与人同行（第 9 章）
—— 这一段不得与它们相抵触
```

**轨道怎么来的**：扫光标前那段字命中哪些人 / 地点 / 物件 →
反查倒排表：后面哪几章的总结提到了它们 → 取那几章的总结。
**按相关性，不按位置**——第 150 章要是提到同一个人，它照样被捞出来。
通常 8 章 ≈ 960 字。全程一次 SQL，零模型调用。

**触发**：比一下当前章号和全书最大章号。是最新章 → 照旧；不是 → 多这两块。

## 模式一 · 尾巴：保存之后

**关键是一条不对称：写之前不知道谁在场（那是写出来的结果），写之后知道（数得出来）。**
所以精确的那一道只能在这边，不可能挪到写的时候。

```
作者保存
  ↓
① 扫这一章正文 → 数出谁真的在场                    现成能力
② 拿这几个人的认知矩阵                              现成能力
  ↓
③ 未登场实体出现了吗            纯字符串规则        今天就有
④ 死了的人还在说话吗            纯字符串规则        今天就有
⑤ 有没有对不该知道的人说破什么   用模型判            ← 新
⑥ 这一段跟后面章节的设定抵不抵触 用模型判            ← 新（轨道阶段 2）
  ↓
有问题 → 一条通知落在右栏「通知」那一格，能点过去，不阻断
```

**⑤ 只能用模型，不能用规则**：代码注释自己写着「真书里秘密内容散在语义里，
集合判断够不着」——合成小册子每条秘密配一个生造专名，真书没有这个东西。
而「事后用模型语义核对、只写通知、不阻断、不改数据」这个形状，
**ADR 0030 已经为它开好了窄例外**，且已有一个模块在跑同样的形状。

**⑤⑥ 是同一条路、同一个落点，一次做。**

### 通知那一块要补的两件

1. **带定位。** 今天那条通知只说「第 N 章的正文检查发现需要留意的地方」，
   不说哪条规则、哪一段、哪一句。而规则产出的 Issue **本来就带着精确的锚**
   （第几段 / 那句原话 / 第几次出现）——那个锚没跟着通知走。
2. **⑤⑥ 不能挂现有那个「验证不过」的通知类型。** 那一类**有副作用**：
   它会把这一章的自动整理停掉。语义核对**只告警不阻断**，要另一种类型。

## 改完

**情况甲的形状不变**（它今天就是对的），只有三处动：

```
① 【第 N 章原文片段】那一块整个删掉         它一直没有生产方
② 【连续性依据】的来源标签改成五档          第 7 条：作者声明的不再标成「机器推演」
③ 缺总结 / 总结是旧的 → 跳过 + 下单         同模式一
```

**情况乙不再退化到全禁**：

```
第 11 章正文只有一行标题 → 数出 0 个人
  ↓ 往前借（只加不减）
第 10 章出现过：苏挽、萧决、李管家
  ↓
【在场】苏挽、萧决、李管家（借自第 10 章）
【本场设定要点】
截至第 11 章的认知边界：
- 苏挽：知道「沈孤鸿之死」（第 9 章起）
- …                                        ← 矩阵回来了
这一场不得写破：沈孤鸿之死                  ← 从"全书全禁"收窄成算出来的
```

**歧义同一招**：「师兄」对应 8 个人 → **8 个都算在场**。
禁令只会更多不会更少，仍然 fail-closed，但比全书全禁精确得多。

**第一章 / 全新的书**，前面没人可借 → **仍然全禁**（那时它是唯一诚实的答案）。

### 工具侧多一条

模型主动查约束时，今天拿不到矩阵。**加一条窄工具：某人在第 N 章知不知道某条秘密。**

```
问：萧决 / 沈孤鸿之死 / 第 10 章
答：还不知道（截至第 10 章）
```

**为什么不直接返回整张表**——理由不是"内容敏感"（矩阵里只有 id/label/name 和纯量），
**是寿命**：

> 对话是持久化且会累积的，之后每一轮起草它都还在上下文里。

矩阵跟章号绑死。第 10 章查的那张表会永远躺在历史里，写到第 50 章时它已经错了，
而且错的方向是 **fail-open**（更多人已经知道，禁令该更少，旧表看起来更严）。

**起草时的 prompt 每次重建、用完就没，所以安全；工具结果会永久留下，所以不安全。
两者的差别不在内容，在寿命。**

一次一格就没这个问题：量小、带章号、过期只错一格、按需。
再配合已有的编号取回机制（**编号只活这一轮**），也不会永久堆在历史里。

## 模式二 · 尾巴：保存之后

**跟模式一同一条路、同一个落点。** 模式二的正文最终也要落进磁盘、走保存，
所以 ③④⑤⑥ 那四条检查**一份实现两个模式共用**。

模式二多的是**写的时候还能自己查一次**：

```
写之前 / 写到一半
  └─ 模型自己调工具：某人在第 N 章知不知道某条秘密      ← 新，一次一格

写完落进正文
  └─ 同模式一的 ③④⑤⑥ + 通知                            共用一份实现
```

**模式二有循环，模式一只有一次往返**——这是两个模式在验证这件事上唯一的结构差别。

# 一页总表

| | 模式一 | 模式二 |
|---|---|---|
| **生成动作** | 行内续写（停手 400ms） | 起草工具（一次调用） |
| **在场哪来的** | 不填 → 归验证侧 | 从正文数，数不出就往前借 |
| **认知矩阵进 prompt** | ❌ 不补（归验证侧） | ✅ 逐格 |
| **模型能主动查矩阵** | ——（没工具） | ✅ 一次一格（新） |
| **禁写清单** | 全书全禁（当提醒） | 这一场算出来的 |
| **前几章总结** | ✅ 新增 | ✅ 今天就有 |
| **事件 / 人物档案** | ❌ 不接（400ms 塞不下） | ✅ 今天就有 |
| **改老章多两块** | 【下文】+【轨道】 | 同（轨道阶段 3 做成工具） |
| **写完之后的检查** | ③④⑤⑥ | **同一份实现** |
| **能不能自己再查一次** | ❌ 没有循环 | ✅ 有循环 |
