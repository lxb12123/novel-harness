## 二、为什么中转端点会落进 unknown

那张表的钥匙里有**地址**，而中转就是「换个地址转同一批模型」：

```
opencode.ai/zen/go/v1     openrouter.ai/api/v1     公司内网代理     自建转发
```

地址列不完，模型名是跟着模型走的。同一件事 `temperature` 那边已经按模型名做了
（`provider.py::_model_family`：「换个中转就能悄悄绕过，一道绕得过去的守卫等于没有」），
思考这边没有。于是：

```
api.deepseek.com      + deepseek-v4-flash  →  认得
opencode.ai/zen/go/v1 + deepseek-v4-flash  →  不认得
```

## 三、实测（2026-08-25 ～ 26，真调用）

### 三类模型三种行为

| 模型 | 能不能关 | 默认 | 听不听 `max_tokens` | 报不报草稿用量 |
|---|---|---|---|---|
| `minimax-m2.5` | ❌ `400 Reasoning is mandatory` | —— | ✅ 要 8192 给 2513 | ✅ 328 |
| `deepseek-v4-flash` | ✅ 两种写法都认 | 全开 | ❌ 要 8192 给 23113，`finish=stop` | ❌ `None` |

**把「关」正确发出去，minimax 那一侧会全部 400。**

### deepseek 开关对照（真书第 1 章，同一份 prompt）

```
什么都不发            246 秒   输出 23,113   答案 6,324 字
thinking:disabled     153 秒   草稿 0        答案 6,285 字
reasoning_effort:none  42 秒   草稿 0        答案 5,937 字
```

出参是中文 JSON。注册表里给 DeepSeek 配的是 153 秒那种，42 秒那种它也认。

### 同一个请求，8 秒到 300 秒以上

完全相同的请求（deepseek、8192、什么都不加、真书第 1 章），六次：

```
302 秒   空
246 秒   输出 23,113   答案 6,324 字
301 秒   空
  8.0 秒 输出  1,853   答案 4,298 字
  7.8 秒 输出  1,596   答案 3,684 字
  7.9 秒 输出  1,420   答案 3,374 字
```

慢的那次输出两万三（约一万七是草稿），快的三次基本不打草稿。
这条路的账单里草稿那一栏是 `None`，看不出它每次想了多少。

查过并否掉的三种解释：

| | |
|---|---|
| 我们的 `max_tokens` 太小 | 它不听——要 8192 给 23113 |
| 模型停不下来 | 每次都 `finish=stop`，自己正常结束 |
| 对面 300 秒掐线 | 后来三遍都 8 秒，没撞到墙 |

## 四、三道闸

```
┌──────── 上下文窗口 ────────┐   ← 闸 A：输入 + 输出 总和
│  输入                       │
│  ─────────────────────      │
│  本轮输出                   │   ← 闸 B：请求里写的 max_tokens
│    草稿  ──┐                │   ← 闸 C：模型自己的输出天花板
│            ├ 抢同一份额度   │
│    答案  ──┘                │
└─────────────────────────────┘
```

草稿不返回给作者，但从输出额度里扣。最干净的一组：

```
给 40 个额度   → 草稿 39 + 答案 1  → 答案是空的
给 2000 个额度 → 草稿 25 + 答案 17 → 「我是MiniMax-M2.7，…」
```

那次 591 秒的失败没用到闸 A（输入 2,186 token，窗口 20 万）。

引擎对作者这条路，两个上限都没有值：

```
上下文上限   None    ← 那个 1,000,000 是作者手填的
输出上限     None
```

## 五、今天不知道的四样

```
① 这个模型一次能吐多少        None
② 它允不允许关、默认多少      不知道（minimax 不允许关，是 400 才知道的）
③ 该用哪家的说法发出去        认不出对面是谁就不发
④ 草稿实际吃了多少            deepseek 这条路不报
```

另有一条没测过的观察：真书那次抽取丢掉的事件全是引语对不上
（`ratio = 0.667 / 0.826 / 0.923 / 0.947`），模型改写了原文，锚不回去。
