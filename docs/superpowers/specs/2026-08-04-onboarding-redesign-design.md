# “开始一本书”上手页重设计

日期：2026-08-04
状态：设计已确认，待实现计划

## 1. 目标

把当前近似浏览器默认表单的“开始一本书 / 新建导入”界面，改成一个克制、精致、具有桌面应用质感的上手页。视觉参考 Cursor 的信息密度、留白、边框和交互层级，但不复制其品牌、图标或具体界面。

本次只改上手流程，不重做工作台、章节准备页或右侧面板。

成功标准：

- 首屏清楚回答“我现在能做什么”，不暴露“先建项目记录、再导入”的内部实现。
- 用户不会再把空项目误认为已导入成功的小说。
- 导入失败不留下项目记录、空目录或半套章节文件。
- 新建空白书后，磁盘上真实存在第一章，而不是只在界面显示默认章号。
- 默认浅色，并跟随 macOS/系统深色外观。

## 2. 已确认的产品方向

### 2.1 首屏结构

桌面宽屏采用左右布局：

- 左侧约 37%：品牌、产品价值和三条本地优先承诺。
- 右侧约 63%：唯一的启动面板。
- 小于约 900px 时隐藏左侧品牌区，只保留启动面板。

左侧文案：

- `Novel Harness`
- `让长篇小说中的每个人，只知道此刻该知道的事。`
- `正文保存在本地磁盘`
- `不配置 AI 也能完整使用`
- `原始 TXT 不会被移动`

右侧文案：

- 眉题：`Novel workspace`
- 标题：`从哪里开始？`
- 副标题：`打开已有手稿，或创建一本全新的小说。`

两个入口：

1. 主操作：`导入现有小说`，说明 `选择 TXT，自动识别书名并切分章节`。
2. 次操作：`新建空白小说`，说明 `创建第一章，从零开始写`。

底部显示：

- `你的稿子不会上传`
- `外观跟随系统`
- 一句短说明：导入会读取 TXT、按章标题切分，并在本地生成 Markdown。

### 2.2 视觉语言

- 默认浅色：暖灰背景、白色操作面板、深石墨主按钮。
- 系统深色时通过现有 `prefers-color-scheme` 跟随，不增加独立主题设置页。
- 圆角控制在 9–16px；边框比阴影更重要，阴影只用于建立前后层级。
- 使用现有系统字体；标题收紧字距，正文保持中文可读性。
- 图标使用小型内联 SVG 或 CSS 图形，不增加图标依赖。
- 隐藏原生 file input，以可访问按钮触发文件选择。
- hover 只做边框、背景和 1–2px 位移；遵守 `prefers-reduced-motion`。
- 键盘焦点必须有清晰的 `:focus-visible` 样式。

不引入 Tailwind、shadcn 或新的设计系统依赖。本次用现有手写 CSS 变量完成，避免为一个页面扩大构建面。

## 3. 交互流程

### 3.1 选择入口

初始状态只显示两个入口，不显示书名输入框和浏览器原生文件控件。

点击任一入口后，右侧面板原地切换；不弹浏览器对话框之外的模态框，不跳到工作台，不改变左侧品牌区。

### 3.2 导入现有小说

1. 点击主操作，打开系统文件选择器，只接受 TXT/纯文本。
2. 前端继续使用现有 `readTextFile()`：先按 UTF-8 解码，出现替换字符时退到 GBK。
3. 选中文件后，右侧面板进入确认态，显示：
   - 文件名；
   - 文件大小；
   - 从文件名去掉扩展名后推导出的书名输入框，可编辑；
   - `返回` 和 `导入并进入工作台`。
4. 用户确认后，服务器一次完成项目创建、TXT 切章、Markdown 写盘和数据库索引。
5. 成功响应必须包含项目和导入报告；前端刷新项目/章节查询、选择新项目并进入工作台。
6. 切不出章、名称非法或写盘失败时，留在确认态并显示可读错误。不得留下项目、目录或章节文件。

原始 TXT 只在浏览器中读取，不移动、不重命名、不删除。

### 3.3 新建空白小说

1. 点击次操作，右侧面板原地显示书名输入框。
2. 用户确认后，服务器一次创建项目和真实的 `chapters/0001.md`。
3. 第一章文件内容使用切章器认可的原始章标，不加 Markdown `#`：

   ```text
   第一章

   ```

4. 数据库同步出真实 Chapter 节点与快照后，前端才进入工作台第 1 章。
5. 失败时仍留在输入态，不产生空项目或目录。

### 3.4 状态与错误

页面局部状态为：

- `choose`
- `import-review`
- `blank-name`
- `submitting`
- `error`

提交中禁用重复操作并显示内联进度。错误消息放在右侧面板相应操作下方，不使用 `alert()`，也不因失败清空已选择的文件或书名。

## 4. 前端结构

保留 `Setup` 作为对外入口，将内部拆为职责单一的组件：

- `OnboardingShell`：全屏左右布局、主题和响应式行为。
- `StartChooser`：两个入口。
- `ImportReview`：文件摘要、可编辑书名、提交和错误。
- `BlankBookForm`：空白书名和提交。

`Setup` 仍支持两种承载方式：

- 没有项目时：渲染完整 `OnboardingShell`。
- 工作台点击“＋新书 / 导入”时：抽屉只渲染右侧流程，不重复品牌左栏。

流程状态留在组件本地；成功后才调用 Zustand 的 `setProject`。可从 API 拉取的数据继续由 TanStack Query 管理，不新增全局业务状态。

## 5. 后端边界

### 5.1 统一启动端点

新增一个薄 API 入口：

```text
POST /api/projects/bootstrap
```

请求使用可判别联合：

```json
{"mode":"import","name":"青云记","text":"……"}
```

或：

```json
{"mode":"blank","name":"青云记"}
```

成功响应：

```json
{
  "project": {"id":"…","name":"青云记","root_path":"…","canon_version":0},
  "initial_chapter": 1,
  "import_report": null
}
```

导入模式的 `import_report` 为真实 `ImportReport`。

现有 `POST /api/projects` 和 `POST /api/projects/{pid}/import` 保留，避免破坏 CLI、旧前端契约和现有测试。

### 5.2 业务服务与原子性

API 壳不直接实现业务。新增一个上手服务，复用：

- `project` 对 project 表的唯一写所有权；
- `importer.chapterize/explode/sync` 的唯一切章与文件规则；
- `SqliteStoryGraph` 的章节写路径。

服务必须满足：

1. 先校验名称和 TXT 是否至少切出一章，再创建持久状态。
2. 在 `books/` 下使用本次操作独占的暂存目录写章节。
3. 数据库 project/Chapter/快照写入处于同一外层事务；store 的内部事务检测到已有事务时不得提前提交。
4. 全部数据库写入成功后，把暂存目录改名为最终书目录，再提交事务。
5. 任一异常回滚数据库，并只清理由本次操作创建的暂存/最终目录。
6. 不覆盖已有作者文件；书名目录冲突继续使用现有 `-2`、`-3` 后缀策略。

`project.create()` 当前自行提交。实现时需要在 `project` 模块内部抽出一个“调用方持有事务”的插入原语；普通 `create()` 继续保持现有提交语义，上手服务使用非提交原语。project 表的写所有权不能转移到 API 或 importer。

### 5.3 请求连接可靠性前置

真实浏览器并发已经复现 FastAPI 同步依赖在线程间交接 SQLite 连接的问题。上手流程交付前必须保证：

- 一次请求仍只使用一条共享连接；
- 不同并发请求各自持有独立连接；
- 同一请求的依赖、路由和清理阶段即使落到不同工作线程，也不会触发 `sqlite3.ProgrammingError`；
- 写事务仍由现有事务边界串行化。

这是一项可靠性前置，不扩大工作台视觉范围。

## 6. 可访问性与响应式

- 两个入口使用真实 `button`。
- 自定义文件按钮关联隐藏的 `input[type=file]`，支持键盘和读屏器。
- 输入框有可见 label；错误通过 `aria-live` 宣读。
- 文本和背景满足 WCAG AA 对比度。
- 900px 以下隐藏品牌栏；启动面板保持最大宽度，不出现横向滚动。
- 600px 以下降低外边距和标题字号，但不改变流程。

## 7. 测试

### 7.1 后端 pytest

- 导入 UTF-8 TXT：创建一个项目、正确章数和 Markdown 文件。
- 零章 TXT：返回 `import_refused`，项目表无记录，目录不存在。
- 空白书：创建 `chapters/0001.md`、Chapter 节点和初始快照。
- 书名目录冲突：不覆盖旧目录，使用稳定后缀。
- 在文件写入、sync 和提交点注入失败：数据库与文件系统均无本次残留。
- 旧创建/导入端点回归测试继续通过。
- 真实并发请求回归：不再出现 SQLite 跨线程错误。

### 7.2 前端 Vitest

- 初始只渲染两个入口。
- 选择 TXT 后展示文件摘要和推导书名。
- `readTextFile()` 对 UTF-8 与 GBK fixture 都得到正确 Unicode 文本。
- 可修改书名并提交统一端点。
- 导入成功后才 `setProject` 并进入工作台。
- 导入失败保留文件和书名，展示结构化错误。
- 空白书成功后进入真实第 1 章。
- 抽屉模式不渲染左侧品牌栏。
- 键盘可触发两个入口与文件选择；焦点顺序正确。

### 7.3 验证命令

```bash
uv run pytest -q
uv run ruff check .
cd frontend && npm test
cd frontend && npm run build
```

最后在浅色和系统深色下各做一次桌面浏览器人工检查。

## 8. 非目标

- 不重设计工作台、章节准备页、抽屉系统或全局导航。
- 不加入最近项目、模板、云同步、账号或登录。
- 不引入新的前端样式库或图标包。
- 不修改切章规则，不尝试用 AI 猜章标题。
- 不移动或删除用户选择的原始 TXT。

## 9. 交付验收

以下条件全部满足才算完成：

1. 首屏视觉与已确认的 A + A1 方向一致。
2. 原生文件控件不再直接暴露。
3. 导入与空白书两个入口都能独立完成并进入真实章节。
4. 任意失败路径不会留下空项目、空目录或半套章节。
5. 浅色、系统深色、窄屏和键盘操作均可用。
6. 后端、前端、构建和并发回归验证全部通过。
