# EVAL_PROTOCOL 修正案 8：长度降权——±10% 宽容带，带外才 INVALID

- 状态：已接受（维护者裁定 2026-08-03）
- 前置：修正案 1–7 全部早于任何有效 `runs/*.jsonl`；本修正案写于 7 轮 INVALID
  （全部死于长度，无泄漏率数字）之后、第八轮之前。
- 作用域：只改修正案 5 裁定 3 的**长度判死条件**与修正案 6 的宽容；不动 225 格、
  三臂、裁决表、统计阈值、`PROTOCOL_VERSION` 的 1–7 部分（考试卷面不变，
  只是给长度这一小题改了扣分规则）。

## 为什么改（权重比例）

一场考试里不是每题同样重要：**大题（图谱约束对泄漏率的影响，McNemar / Δ / 符号稳定）
占大分，长度只是仪器卫生**。前 7 轮全部死于「超了 16–194 字」这类小偏差，
一刀切 INVALID 等于把小题当成大题判死——仪器因此一直交不出卷子，
而核心问题（注入到底有没有用）一个字都没量到。

裁定原则：**先看超得多不多、严不严重，再决定生死**。小偏差记录、公开、不判死；
只有严重越界才算仪器坏。

## 裁定

1. **宽容带**：最终文本 `actual_units ∈ [min×0.9, max×1.1]`
   （M2 = 2,000/2,500/3,100 → **1,800–3,410**）→ 有效 cell，
   generation 记录 `length_tolerated=true`，ADR 0009 逐格透明列出。
2. **带外判死**：`< 1,800` 或 `> 3,410` → 仍 INVALID（仪器坏，整轮作废）。
3. 取代修正案 6 的固定 `≤100` 宽容（它只有上限一侧、且比 10% 更窄）；
   续写策略（under-min 触发一次）、`finish_reason=length` 判死、225 格、
   三臂同配置全部不变。
4. **诚实声明**：宽容带不是藏偏差——每个被容忍的 cell 都带标记进证据，
   若一轮里偏差普遍偏大（如大量 3,300+），ADR 0009 仍会写「长度控制不良」。

## 若决策错误，修复成本

中。若发现 10% 宽容让长文本系统性抬高泄漏率（文本越长越容易碰到 tell），
可再开修正案收紧到 5%；已跑的 run 不能重解释，但新 run 用新带。
