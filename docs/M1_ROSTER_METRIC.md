## 一、量的是什么

**角色册覆盖率**：作者在正文里实际用到的**称呼词实例**，有多大比例能精确对上
角色册里的条目（canonical 或 usable alias）。90% 意味着「作者随手写的称呼，
十个里至少有九个系统认得出」——认不出 = 面板/规则/起草都够不着那一处提及。

## 二、口径（先定义、后测量）

### 分母：gold 标注的称呼实例

gold 由维护者**人工标注**（判定人 = 想验收 M1 的那个人），格式：

```json
{
  "project_id": "…",
  "chapters": [
    { "chapter": 1, "mentions": { "顾清音": 5, "顾姑娘": 2, "萧决": 3 } }
  ]
}
```

标注规则（什么算一次「称呼实例」）：

1. 只标**独立出现的称呼词**：人名、别名、称呼（顾清音 / 顾姑娘 / 萧公子）。
2. **不标**：代词（他/她）、省略主语的对白、泛指（「两人」「师兄妹」）。
3. 说话人标签位置算一次（`顾清音道：「…」` 里的「顾清音」算 1 次）。
4. 一章内的同一词按**实际出现次数**记（`str.count` 语义，非重叠）。

工具会**把 gold 与正文逐字核对**：任一 surface 的标注次数和正文实际次数对不上，
直接拒绝出数（同 `leak_selfcheck` 的纪律：一份和原文对不上的 gold 是假数据，
拿它算出来的覆盖率也是假的）。

### 分子：角色册能精确覆盖的实例

每个 gold surface 过 `store.resolve([surface])`（**不带** `rules_only`——
`rules_only=True` 会把没覆盖的项整个滤掉，破坏 1:1 对齐），判
`resolution.usable_for_rules`：能解析到**唯一**节点（canonical 或 usable alias）
= 覆盖；否则 = 没覆盖。
覆盖实例数 = 被覆盖 surface 的 gold 次数之和。

### 门槛

```text
覆盖率 = 覆盖实例数 / 全部实例数 ≥ 90%
```

按章分别出数，**门槛按全书合计判**（真书验收是连续 20 章 / 全书）。工具同时打印
没被覆盖的称呼清单——那就是作者该补的别名（角色册空着时这一项必然不达标，
是数据问题不是工具问题）。
