## 裁定 1：§6 的「该臂」在 Δ 平票时指**两条**臂

### 原文

> `max(Δ1,Δ2) ≥ 0.15` 且**该臂** Holm 校正后 p<0.05 且符号稳定 且判别对≥8

### 歧义

`Δ1 == Δ2` 时，「取到 max 的那条臂」有**两条**。按「只看其中一条」读，实现自然会写成
`best = max((a1, a2), key=...)` ——而 Python 的 `max` 平票返回第一个，于是**永远只评 A1**。

### 见证（实测）

```
20 条 KNOWS：8×(x0=111,x1=000,x2=000) + 3×(111,000,111) + 3×(000,111,000) + 6×(111,111,111)
  A1: Δ=0.40  Holm p=0.0573  符号稳定  判别对 14   ← Holm p 不显著
  A2: Δ=0.40  Holm p=0.0156  符号稳定  判别对 8    ← 四个条件全过
  只评 A1 → 落进 §6 第 6 行 → KILL
  两条都评 → §6 第 4 行逐字命中 → PASS
```

同一份数字，**只把 X1、X2 两列对调**，裁决就从 KILL 翻成 PASS。
模拟（n=15、3 次重复、X2 相对 X1 每次 12% 翻转，60000 轮）显示 **Δ 平票占 26.5%**——
不是角落情形。

### 裁定

**取到 `max(Δ1, Δ2)` 的每一条臂都是「该臂」。只要其中任意一条四条件全过，即 PASS。**

理由是字面的：§6 写的是 `max(Δ1,Δ2)`，不是 `argmax`。一个由「哪一列写在前面」
决定的裁决不是裁决。

### 同时明确：**次大臂永远不是「该臂」**

Δ 严格更小的那条臂，即使四条件全过，也**不构成 PASS**。这一格逐字忠于 §6，
且是两种读法里对本项目**更不利**的那个（实测发生率约 0.09%）。
`GateDecision.eligible_arms` 会把「谁是该臂」写进裁决记录，ADR 0009 直接引用。

## 裁定 2：§5 的「三次必须同号」= 与**陷阱级 Δ** 同号

### 原文

> **符号稳定性过滤**：按「仅单次重复」重算 Δ 三遍，三次必须同号，否则那 ≥15pt 判为方差。

### 歧义

「同号」可以读成「三次彼此同号」，也可以读成「三次都与被主张的方向同号」。

### 见证（实测）

```
19 条 KNOWS，三次单次重复的 Δ 分子 = [-1, -1, -1]     ← 每一次注入都让泄漏更糟
陷阱级（多数投票后）Δ = +0.42                          ← 噪声被磨平后翻了向
按「彼此同号」读 → 三次都是负、彼此同号 → 报「符号稳定」→ PASS
```

也就是说：**在一个每一次重复都显示注入有害的数据集上，判出「注入有效，进 M3」。**
这正是符号稳定性过滤存在的理由所在的那一类情形——按前一种读法，它在自己最该生效的
地方失效了。

### 裁定

**「同号」= 与陷阱级 Δ 的符号一致。** 任一次重复的 Δ 与之反向，或恰好为零，即判不稳定。

（`Δ == 0` 判不稳定这一条不是本次新增，原实现就有，理由是「零没有符号」，
刻意从严——被这条守着的是「注入有效」这个会让产品上线的结论。）

## 裁定 3：重复次数只有 3 和 5 两个合法值

### 原文

§5「每条陷阱跑 **3 次重复**」；修正案 2「预案一次性升到 **5 次重复**」。

### 歧义

协议没说「别的次数不合法」。而实现如果只校验「奇数且 >0」，`repeats=1` 就能过——
那时符号稳定性过滤**退化成恒真**（只有一次重复，它必然与自己同号），
四个 PASS 条件里最难的那个白送，而裁决记录上还写着「符号稳定」。

### 裁定

**`repeats ∈ {3, 5}`，别的值一律抛错，不许硬判。**
3 是首轮（§5），5 是缓刑轮（修正案 2）。别的值意味着 runner 出了 bug，
而一份形状不对的 run 只能重跑——静默凑合出来的裁决没人能复算。

这条同时收紧了修正案 2 里「`repeats >= 5` 是缓刑已用掉的标记」那个操作化定义：
现在它等价于 `repeats == 5`，不再需要考虑 7、9 这类协议没定义的形状。
