# EVAL_PROTOCOL 修正案 6：超长 ≤100 字宽容（上限 3,000 → 3,100）

- 状态：已接受
- 日期：2026-08-02
- 作用域：只改修正案 5 裁定 1 的 `max_units`（3,000 → 3,100）与裁定 3 的超长判定
  （>3,100 才 INVALID）；不改 min/target、陷阱、三臂、重复数、tell 检测器、统计阈值或 §6 裁决表。
- 前置：修正案 1–5 全部早于第一份 `runs/*.jsonl`；本修正案晚于四份 **INVALID** run
  （无任何泄漏率数字、无裁决），但早于任何能出裁决的有效轮。

## 为什么改

真实模型（deepseek-v4-flash）的一次性长度控制有小的右尾：首段生成偶尔落在
3,000–3,100 之间（实测 3,016 / 3,067，超 16–67 字）。修正案 5 把「超长」一刀切判
INVALID，而超长没有补救手段（续写只允许 under-min 触发），于是四轮都死在这条上，
整台仪器数学上无法完成 225 个 cell。

维护者裁定：**超出 ≤100 字不是内容质量问题**——小说写作的验收关键是内容，不是
字符数上的 16 个字。把上限放宽到 3,100（即 3,000 + 100 宽容），>3,100 仍判 INVALID。

## 裁定

1. 修正案 5 裁定 1 的长度档改为：`zh` `min=2000 / target=2500 / max=3100`。
2. 修正案 5 裁定 3 的「多于 3,000 个中文单位」改为「多于 3,100 个中文单位」。
3. 其余不变：不足 2,000 仍最多续写一次；两次调用的模型、预算、reasoning、采样配置
   必须完全相同；两段按返回顺序原样拼接。

## 对预算的影响（全部仍为确定值）

```text
visible = ceil(3100 × 2) + 1024            = 7,224
required = ceil(7224 ÷ (1 − 0.8))          = 36,120
request = 向上取整到万位                    = 40,000（不变）
stream：request > 16,000 → True（不变）
```

## 诚实声明

这是四轮 INVALID 之后对**仪器**的修正，不是对**及格线**的修正：§6 的 FLOOR/CEILING、
符号稳定、McNemar 阈值与裁决表一个数字都没动，且四轮均无有效泄漏率可供事后调整。
若此后发现模型把超长推到 3,100 以上，按同一路径再开修正案，不许静默改。
