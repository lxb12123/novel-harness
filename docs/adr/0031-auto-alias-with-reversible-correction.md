# ADR 0031：无歧义别名自动入档、歧义隔离、纠错可回放

- **状态**：已接受
- **日期**：2026-08-17
- **推翻了**：[ADR 0004](0004-declaration-over-extraction.md) 中
  「别名聚类必须先确认」的**一部分**：无冲突的别名允许自动入档、作者
  事后纠正；**歧义仍然待确认**。ADR 0004 其余部分原样保留——
  秘密、伏笔、认知边界仍由作者声明，抽取只做 PROVISIONAL。
- **相关**：[ADR 0004](0004-declaration-over-extraction.md)（声明优于抽取）、
  [ADR 0005](0005-set-judgment-only.md)（只做集合判断）、
  [ADR 0029](0029-save-triggers-snapshot-refresh.md)（保存触发刷新）

## 决策

**明确无冲突的别名允许自动写 ACTIVE alias 行（`source=extractor`），
歧义进入 `alias_resolution` 聚类提案；所有自动结果都能修改、撤回、
改归属，纠错走持久 replay outbox。**

自动入档必须**同时**满足：

1. 目标称呼唯一解析到同项目 Character；
2. alias surface 当前未映射到任何人；
3. 证据 quote 逐字包含目标称呼和 alias surface；
4. 同一 run 没有另一个候选把该 surface 指向别人；
5. `confidence >= 0.90`。

任一条件不满足 ⇒ 生成 `alias_resolution` 提案，不自动选择。

配套规则：

- 别名是 `alias` 索引表的数据，不进入 `Node.props_json`，不作为关系边。
- `(project_id, surface) WHERE status='ACTIVE' AND source='extractor'`
  是 partial unique：防两个并发自动任务把同一 surface 激活到不同人物；
  作者明确创建的同名 alias 仍可跨人物并存为歧义。
- 机器 alias 至少要有**一条 FRESH alias_evidence** 才参与解析；
  作者 alias 不要求伪造证据。旧证据失效但还有其他 FRESH 证据时继续解析；
  全部失效时停止解析但保留历史行。
- 作者修改自动 alias = 撤回旧机器行 + 派生一条 `source=author` 的新行，
  以 `derived_from_alias_id` 指回机器行，不原地改 node_id、不丢原证据。
- 自动 alias 写入并重建 resolution map 后，必须对同一 S2/G2/attempt/
  ruleset epoch 再运行一次正文验证器；只有持久
  `final_gate_state=PASSED` + `final_validation_report_id` 才放行 summary
  head 切换与抽取 facts 生效——初次 PASSED 不能冒充最终结果。
- 别名新增、撤回、改归属后，对精确受影响的当前 snapshot 重算验证/解析；
  决策事务同时停火旧机器 facts 并插入幂等 `alias_replay_job`，
  dispatcher 重启可继续，禁止「先停火、事务提交后再内存 enqueue」。

## 为什么

### 1. 别名是索引不是事实，自动化的失败方向比事实轻

别名错了的代价是「一个称呼暂时解析到错误的人」，作者改回来即可；
它不进入认知边界、不进入规则开火。ADR 0004 对别名要「聚类确认」
的原始理由是角色册是所有下游的键——但那条理由保护的是**事实**的
确定性，不是**索引**的确定性。索引错了可纠正，事实错了会污染规则。

### 2. 歧义隔离是自动入档能成立的前提

「师兄」映射多人、「清音」可能是顾清音的别名——这两类一旦自动选一个，
就把身份未决的事实误判成 clean。所以身份未决的**整条相关事实保持隔离**，
不能先丢掉未知人物再把「剩下的事件」判成 clean。自动入档只对
「目标唯一 + surface 未占用 + 高置信度 + 证据逐字可查」开放，
这个条件本身是纯集合判断（ADR 0005 不破）。

### 3. 先纠错后自动是这条 ADR 的启用顺序

别名自动入档开放之前，人物基础信息的读取、添加、修改、撤回、改归属
和决策日志入口必须先落地（Task 11/15）。否则「系统自动改你的角色册，
而你改不回来」会重现 ADR 0020 论证过的那个不可接受状态。

## 代价（承认，不粉饰）

- 自动 alias 可能错，错误会短暂地影响提及解析和 R2/R3 的输入；
  退路是纠错入口 + 证据可追溯，不是事前确认。
- `alias_evidence` 是新的持久表，机器 alias 的证据失效判断多一条读路径。
- 自动 alias 触发二次验证会让部分保存的整理流程多跑一遍确定性规则。

## 什么条件下推翻本 ADR

- 真书实测自动 alias 的纠正率超过阈值（当前无真书数据，不预编数字）。
- 出现「作者改不回来」的形态：别名修改/撤回/改归属任一入口缺失时，
  自动入档必须先行关闭。

## 若此决策错误，修复成本是什么

**低到中等。** 别名是可纠正的身份索引：关掉自动入档是一个条件判断；
已自动写入的行可以全部标 RETRACTED 保留历史。真正的成本是如果
自动 alias 污染了 R2/R3 的输入（别名解析错误 → 误报），
要连同二次验证一起排查——所以二次验证闸门不能省。
