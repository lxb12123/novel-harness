# ADR 0028：作者的规矩按**情境**失效，由模型判；章号不是有效期

- **状态**：已接受
- **日期**：2026-08-14
- **推翻了**：**本仓库自己**——[ADR 0023](0023-context-is-pruned-by-rebuildability.md)
  **决策二的后半段**（「作者的规矩带章号区间」「说第二遍从批级升到章级」），
  以及它押的那条退路的界面形态（「这一章的规矩」那颗按钮 + 两条 HTTP 路由）。
  **决策二的前半段原样有效**：规矩是模型从作者随口一句话里提炼的，他一个表单都不填。
- **相关**：[ADR 0005](0005-set-judgment-only.md)（**没有被碰**，见下面「铁律没破」一节）、
  [ADR 0019](0019-agent-loop-not-graph.md)（边界五：投影；边界六：稳定前缀）、
  [ADR 0027](0027-scene-blocks-cut.md)（同日的另一刀，同一条起因）

## 决策

**一条规矩不再按章号过期。引擎只做三件确定的事，「它此刻还作不作数」交给模型。**

引擎侧（`agent/rules.py::surviving_rule_indices`）：

1. 作者取消掉的不留（`_revoked_indices`，**读的那一半留着**，见下）；
2. 同一串字只留最后那一次（`rule_key` 归一化后字节相等，纯去重）；
3. 最多 `RULE_KEEP_MAX = 12` 条，留最近的——**成本的闸，不是有效期**。

模型侧：每条规矩进 prompt 时前面加一句（`RULE_PROMPT_PREFIX`，只在投影里加，
**canonical 存的仍是作者那句话本身**）：

```
（作者写第 722 章时随口说的；情境不在了就不必守）男主在这片沙地不杀人
```

一起没了的：`REPEAT_TO_WIDEN`（说两遍升章级）、`AuthorRule.heard` / `chapter_wide` /
`valid_from` / `valid_to`、`live_rules()`、`revocation()`（写入方）、
`GET`/`DELETE …/chats/{cid}/rules[/{seq}]`、前端 `ChatRules.tsx` 和那颗按钮。

## 为什么

### 1. 章号从来不是有效期，它只是引擎唯一能确定知道的数

作者的原话（2026-08-14）：

> 「这个原本就不需要展示给用户看，并且这个规则是有时效性的。比如用户说男主不准杀人
>   在这个沙地，那男主出了沙地这个规则就失效了，这个要由 llm 智能判断，
>   而不是显示出来给用户选择。」

他说的是**机制**，不是显示。ADR 0023 决策二把有效期定成「作者说它时那一章」，
理由写在一张「拿不准就放掉」的表里：留着 = 第 200 章写不出打戏，而作者不知道为什么。
**那个担心仍然成立，换掉的是谁来解决它。**

章号作为有效期的代理，**两个方向都错**：

| 形态 | 章号说 | 实际 |
|---|---|---|
| 写一章要好几天、跨好几段对话 | 翻一页就没了 | 他刚交代的事，模型下一轮就忘了 |
| 「男主在这片沙地别杀人」 | 管这一整章 | 他走出沙地就该没了，**同一章里** |

而「男主还在不在那片沙地」要读懂剧情。引擎判不了，**模型判得了**。

### 2. 「默默收集」本来就成立，露在外面的只有撤销那半边

提炼是模型干的（`agent/rules.py` 顶上那句「第五件不在这儿」）——作者从来没填过表单。
屏幕上那颗「这一章的规矩」按钮和它背后的面板，是 ADR 0023 押的退路
（**看得见 + 能取消**，不是事前确认）的界面形态。

而在**绝大多数章上它管着零条东西**，于是那颗按钮一直挂在对话头上，
教一个作者不需要主动使用的概念，还把「按章号算」这个粗糙度原样摆到他面前
（面板上每条规矩后面跟着一句「翻到下一章就自动放掉」）。

### 3. 退路换成了他本来就在用的那一条

**这是这份 ADR 最该被质疑的地方，所以把它写清楚。**

ADR 0023 明写：这条机制会判错，而押的退路只有「看得见 + 能取消」。
拿掉界面 = 拿掉那条退路的一半，看起来正是本仓库反复栽过的那个坑
（ARCHITECTURE「工作台的已知洞」第 4 条：滚动总结一直在花作者的钱、影响每一稿，
而他看不见、改不了、删不掉）。

维护者提出了这一点，**作者驳回了，理由成立**：

> 「用户察觉到错误自然会在左侧章节看到实时的内容就知道改的行不行，要是不行肯定会说
>   这个时间不对，或者说这么走出沙地还是这样……所以这个 llm 偶尔判读错误
>   不是什么大事情。」

**滚动总结那个洞和这里的差别是「看得见」的成本**：那份总结不出现在任何一稿的字面上，
他读一百遍稿子也发现不了它错了；而一条规矩**直接写在字上**——「他都走出沙地了还这样」
是他读第一遍就会说的话，说完模型当场就修正。稿子本身就是审查面，而他每一稿都要读。

**代价说清楚**：一条提炼错的规矩，从前最多祸害一章（翻页自动失效），
今天它活多久由模型说了算。这是**有意接受**的，不是漏掉的。

### 4. ADR 0005 的铁律没有被碰

「只做集合判断，不做语义判断」管的是 **`checks/`**——那是会给作者报红字的规则层，
误报的代价是他弃用。**这次的语义判断发生在 prompt 层，由模型自己做**：
引擎只是把规矩连同「他是写第几章时说的」一起发出去，一个「这句话是什么意思」都没问。
`surviving_rule_indices` 今天比从前更纯：去重靠字节相等，上限靠计数，撤销靠结构槽。

## 什么留着，为什么

- **`is_revocation` / `_revoked_indices`（读的那一半）必须留着。**
  canonical 只增不改：作者当年按过的那些取消还躺在真实的库里，
  不认它们就等于把他明确说过不要的规矩又放回 prompt。
  写入方（`revocation()`）删了——今天没有任何入口能造出一条新的撤销记录。
- **`RULE_MAX_UNITS = 120`（每条的字数上限）留着**，理由不变：规矩每一轮都要重发，
  而作者是按 token 付钱的那个人。加上 `RULE_KEEP_MAX = 12`，最坏约 1,440 字常驻。
- **`promoted()`（升格进稳定前缀）留着**，而它的含义变了：从前的差别是「换一章还在不在」，
  今天两份都还在，差别是**升格那一份不带任何情境标记**——「整本书都这样」没有情境可言。

## 补记（2026-08-15）：模型要写下时效，而且那份记录看得见

**这份 ADR 落地的第二天，作者补了一件事**：

> 「我觉得可以留一个记录这种规则的，特别是比如说你在写某一章的时候用户讲过的规则，
>   然后**你规定的时效**什么的都可以记一下。」

**「你规定的」三个字改了一处设计。** 上面那一节里，时效是模型每一轮从规矩正文里
自己读出来的（「男主在这片沙地不杀人」——条件混在句子里），进 prompt 的是一句通用的
「情境不在了就不必守」。那样能用，但**没有任何可以记下来的东西**。

所以：

- **`remember_rule` 多一个必填入参 `until`**（迁移 016：`chat_message.rule_until`）。
  模型记一条规矩时必须同时交出「这条什么时候就不算数了」，一句人话，
  **引擎一个字都不解析**（要归类就得先回答「这是哪一类时效」，那是 ADR 0005 禁的）。
- **进 prompt 时把它自己那句判断摆回它面前**（`RULE_PROMPT_UNTIL`）：
  「作者写第 722 章时说的，你当时判定它管到「男主走出这片沙地为止」；情境不在了就不必守」。
  「你当时判定」是有意的——那是它自己的判断，不是一条不知道谁定下的期限，
  而后者会被当成硬约束。
- **`GET /projects/{pid}/rules` + 日志页上一张表**（`RulesTable.tsx`）。

⚠️ **那张表不是这份 ADR 撤掉的那块面板，两者必须分得开**：

| | 撤掉的（`GET …/chats/{cid}/rules`） | 新长出来的（`GET …/rules`） |
|---|---|---|
| 回答 | 这一章此刻**哪几条生效** | 我到底**跟它交代过什么** |
| 形态 | 对话头上常驻按钮 + 能点掉的面板 | 日志页上一张回头翻的表 |
| 取消 | 有（存在的理由） | **一颗按钮都没有** |
| 生不生效 | 引擎按章号算给作者看 | **不说**——那是模型每轮按情境判的事 |

**「记一下」和「摆出来让他管」是两件事**，作者 8-14 否掉的是后者。
表上不许长出「还生不生效」那一列（两侧各有一条测试钉着）：那个答案引擎给不出来，
给一个出来就是编，而编出来的那一列在屏幕上看起来完全正常。

**016 之前记下的规矩不补写时效**，表上那一格照实说「没记下」——
替模型说一句它没说过的话，比缺一句更贵。

## 什么时候该重新考虑

**触发条件是「模型死守一条作者已经不要的规矩」在真书上真的发生。**

那时正确的加法是给模型一个 `forget_rule` 工具（和 `remember_rule` 对称、同样不上屏，
`_revoked_indices` 那一半现成），**不是把那颗按钮加回来**。
作者已经就「不上屏」这件事表过态两次。
