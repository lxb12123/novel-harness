# ADR 0048：起草即写入 —— 稿子写完直接进那一章，版本历史是退路，对话里不摊第二份正文

- **状态**：已接受（2026-09-12，作者提出）
- **日期**：2026-09-12
- **推翻了**：不是原始需求文档，是**本仓库自己**——
  [ADR 0022](0022-drafting-is-a-proposal-not-a-write.md) 的**入口形态**：「生成 / 落盘拆成
  两个动作，候选摆在对话里让作者挑」。它的另一半（候选表、`read_draft`、并排页、
  「候选不进对话」）原样保留。
- **相关**：[ADR 0021](0021-agent-writes-drafts-without-asking.md)（落盘不问作者——
  这一条**回到了它最初的形态**）、[ADR 0019](0019-agent-loop-not-graph.md)（边界一）、
  [ADR 0047](0047-drafting-is-assistant-curated-not-calibrated.md)（同一天的上一刀）

## 作者的原话

看着右边对话里摆着的一整稿（可展开、带「起草要求 / 补充资料」）和助手那句
「你觉得这个方向可以吗？可以我就存进去了」：

> 我在想为什么不直接修改在左边，反正这不是有历史状态管理吗？要是觉得不可以就直接点那个
> 历史恢复就行了……（改一两句的话红色跟绿色那种）我感觉也不需要这样子，因为写小说的话，
> 如果有红色绿色的整体看起来很乱，反正就是在左边那边改。

三句话三条裁定：**稿子进左边的正文**；**退路是版本历史**（不是先问一句）；
**不做红绿 diff**（散文上看着乱）。

## 决策

**`draft_chapter` 写完直接写进那一章，而且写的过程就在左边。** 写手写的那几十秒里，
字一片片流进左边的编辑器（同一条 `draft_delta` 流，`frontend/src/liveDraft.ts`），
作者看着稿子在正文该在的地方长出来；写完落盘，那一步一跑完前端就重取正文和版本历史，
编辑器换成磁盘上那一版，中间没有一帧空白。不满意在「历史」里退回上一版。

| 动作 | 花钱 | 动书 | 谁决定 |
|---|---|---|---|
| **起草**（`draft_chapter`） | 花 | **动**（写完即落盘） | 模型 |
| **读回一稿**（`read_draft`） | 不花 | 不动 | 模型（只在作者要合并两版时） |

- **`save_draft` 删了。** 落盘不再是模型的一个动作，它没有第二件事可做，所以也不会再问
  「要不要存」——工具描述、人设、`landing_saved` 那句回执都改成「不用问，写完说一句写了什么」。
- **落盘那五道闸一条没动**（ADR 0021 / 0022：sha 闸 / 只对已存在的章 / 先 sync /
  留章标题 + 验「恰好一章」/ 空稿闸）。写不进去的稿子**留在桌上**：`DraftResult.landed=false`
  + `landing` 那句说为什么，模型据此告诉作者；对话里那一稿仍然是一张卡——那是它唯一能被
  读到的地方。
- **一批几稿依次全进书。** 第二稿的底稿是第一稿落盘之前那一版，闸会把它当成「作者在这中间
  改过」——ADR 0022 当年拆成两步的理由正是这一条。现在 `ChapterDesk` 记得自己写进各章的
  那一版（`_written`）：磁盘上现在正是那一版时按它比对，接着盖；作者真在中间改过一笔，
  哈希对不上，照旧拒。最后一稿留在正文里，其余在版本历史和并排页里。
  **默认写一稿**，作者明确要几个版本时才一次写几稿。
- **对话这一侧只剩一行。** 写进去的每一稿：「第几稿 · 字数 · 已写入第 N 章」+ 写手那句自述，
  底下一句「如需撤销，可在正文「历史」中退回上一版」。**不摊正文、不摊起草要求和补充资料**
  （正文在左边；要求和资料跟着稿子存着，在并排页上能看）。没写进去的那几稿照旧是卡。
- **不做行内红绿 diff。** 版本历史那页本来就有差异视图，作者要看时去那儿看；正文编辑器里
  不涂色。
- **到手的字匀速露出来，不是一段一段跳**（`frontend/src/typewriter.ts`）。模型一片一片吐，
  一片多大不由我们定（有的服务商攒成一段才发，网络再把几片攒成一个包）；直接画就是一段一段
  跳，作者说「看起来就是不美观」。所以「到手」和「露出来」分开：露字的速度按最近两秒来了
  多少字定，一片到了之后在下一片到之前均匀铺开；积压超过三秒的量时加速；流收场之后加速收尾。
  右边那一格在编辑器接手时**什么都不画**（作者：「不用特地提醒在左边什么的」）。
- **流进编辑器的那几十秒，键盘锁着；作者手上有没保存的字时不接。** 锁键盘是因为他敲的字
  会和流进来的字混在一起、落盘那一刻又被磁盘盖一次；有没保存的字时那条流仍在右边那一格里
  长（同以前），落盘后编辑器只说一句「本章已在别处修改」。一批几稿同时在飞时编辑器只有一个
  位子——第一条流进编辑器，其余留在右边。写手第一行那句自述不画进正文（后端落盘时也切掉它）。
- **写手那句自述的记号，第一行开头的变体也认。** 真书上写手把 `〖自述〗` 写成了 `「自述」`，
  ADR 0022 下那一行只是候选卡上多一行机器话，现在它会直接进作者的章。`split_self_note`
  只在第一个非空行的开头认 `【自述】` / `「自述」` / `（自述）` 这几种（那是我们要它写自述
  的位置，写手的散文不会从那儿起笔），行中和后面的行仍然一律不认。

## 为什么

### 1. 「问一句要不要存」是 ADR 0022 拆开之后长出来的，不是谁想要的

ADR 0021 的精神是「落盘不问作者，退路是版本历史」。ADR 0022 把落盘拆成第二个动作之后，
模型手上多了一个「存不存」的选择——它就会去问（真书上这一轮问了：「可以我就存进去了」）。
作者的裁定把选择拿掉：没有第二个动作，就没有那个问题。

### 2. 右边摊一整稿，是让作者在错的地方读

正文的家在左边的编辑器里：那儿有章标题、有保存、有历史、有检验。右边再摊一份，
作者要在两块屏幕上读同一段字，还得自己去点「存进去」。**稿子写进左边，右边只报一行**，
读和改都在正文该在的地方。

### 3. ADR 0022 的四件好处，三件留着，一件换了个实现

- 同一轮多稿不再打架 —— 换成 `_written` 那条「自己写的不算作者改的」规则，仍然成立；
- 崩了重跑安全 —— 落盘幂等（同内容不多出一版快照），仍然成立；
- 一批稿可以并发 —— 慢的那一段（模型调用）仍在锁外并发，落盘那一小段回到
  `ToolContext.db_guard` 里排队；
- 碰撞窗口 —— 从「起草到落盘之间的几十秒」变回「写手写的那几十秒」；撞上了闸照旧拒，
  稿子留在桌上（`tests/test_candidates.py::test_a_refused_landing_leaves_the_draft_on_the_desk`）。

## 代价

- **作者在写手写的那几十秒里改了那一章 ⇒ 这一稿不进书。** 那时模型能做的只有告诉他、
  或者按新的正文重写一稿——没有「作者点一下就存」的路了。这是 ADR 0021 的立场原样：
  永远不覆盖作者更晚的改动。
- **要几个版本时，只有最后一稿在正文里。** 其余在版本历史（有差异视图）和并排页里。
  作者裁定不要红绿 diff，所以并排页是比较几版的地方。
