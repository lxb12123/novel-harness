# ADR 0048：稿子直接进左边的编辑器 —— 写的过程看得到，写完以未保存的样子留着，作者按保存才进书

## 作者的原话

看着右边对话里摆着的一整稿（可展开、带「起草要求 / 补充资料」）和助手那句
「你觉得这个方向可以吗？可以我就存进去了」：

> 我在想为什么不直接修改在左边，反正这不是有历史状态管理吗？要是觉得不可以就直接点那个
> 历史恢复就行了……（改一两句的话红色跟绿色那种）我感觉也不需要这样子，因为写小说的话，
> 如果有红色绿色的整体看起来很乱，反正就是在左边那边改。

同一天后面几句（对着第一版看的）：

> 我希望有个编辑的过程在左边也能看到。……他的内容是一段一段字的走，不是一个一个的，看起来
> 就是不美观。……写完之后右上角那个保存按钮都不用点就可以了，我希望用户可以去点击这个保存，
> 从草稿变成正文，这样这个版本就保存到历史上；AI 编写的或者修改的——增加的绿色的底、修改的
> 浅红色的底——点击保存这个底就消失了。……用户拉到最底部，画面跟着写的走；在上方看前面的内容
> 时留在这个页面，正中间要有一个方向标，滑到最下方。

再后面（对着第三版看的，稿子又出现在了右边）：

> 为什么现在稿子又是在右边写？我前面特地把你调到左边。……一定要在左边写。……不要在这个里面
> 留这种东西。……我的左侧就像你现在的这个 Claude terminal 一样：我在最新内容的底部，画面就
> 实时跟着写；我在上面一点点，画面感受不到流动，我可以固定在这边看内容。左侧屏幕居中底部
> 有一个点击快速到最下边的。……**不管是他写的还是他编辑的，只要没有保存就要有那种编辑的痕迹，
> 红色和绿色代表减去和增加**——（指着一张 git diff 的图）类似这种效果。

## 决策（终稿）

**稿子直接进左边的正文编辑器，写的过程看得到，写完以未保存的样子留着；作者按「保存」才写进书。**

| 动作 | 花钱 | 动书 | 谁决定 |
|---|---|---|---|
| **起草**（`draft_chapter`） | 花 | **不动**（稿子流进编辑器） | 模型 |
| **读回一稿**（`read_draft`） | 不花 | 不动 | 模型（只在作者要合并两版时） |
| **保存**（`PUT …/chapters/{n}/text`，带 `draft_id`） | 不花 | **动** | **作者** |

- **模型手上没有落盘这个动作。** `save_draft` 删了，`ChapterDesk.land` 也删了；ADR 0019
  边界一最后一条「写正文必须作者确认」又成立了，而且比原来更硬——表里没有一条工具收一段正文，
  也没有一条工具写盘。它也就不会再问「要不要存」：工具描述和人设改成「不用问、也不用告诉他去
  点保存，写完说一句写了什么」。
- **写的过程在左边。** 写手写的那几十秒里，字一片片流进左边的编辑器（同一条 `draft_delta`
  流，`frontend/src/liveDraft.ts`）。到手的字**匀速露出来**，不是一段一段跳
  （`typewriter.ts`：露字的速度按最近两秒来了多少字定，一片到了之后在下一片到之前均匀铺开；
  积压超过三秒的量时加速；收场之后加速收尾）。这几十秒里键盘锁着（他敲的字会和流进来的字
  混在一起）。**贴着底时画面跟着写；翻上去看前面的内容时画面留在原地**，正文底部正中一颗
  「滑到最下方」，点一下回到最新、继续跟。
- **写完 = 一份未保存的修改。** 字全露完之后整份进编辑器、标脏、键盘解锁，顶栏一句
  「写作助手的一稿，按「保存」写入本章」。按保存：正文写盘、版本历史多一版，请求带上
  `draft_id`——后端在候选表上记「这一稿进书了」（清理策略只清进过书的）并在日志页留**作者**
  那一行（不是系统的）。**不要它，没有专门的按钮**（作者：「这个按钮没必要存在」）——它和
  作者自己敲了没保存的字一样：⌘Z 一步步退回去（稿子整篇换进来那一下在撤销历史里自成一步，
  不和他刚敲的字并成一笔），或者「历史」里对着**当前**那一版按「还原」——编辑器里有没保存的
  修改时那一行才有这颗按钮，意思是丢掉这些修改、回到磁盘上这一版，不写盘。
- **没保存的改动都有痕迹，不分谁改的**（`editMarks.ts`）。编辑器里这份正文和**上一次保存的
  那一版**之间的差，照 git diff 的样子画：保存版里有、现在没有的段是**减去**——一块红的、
  不可编辑的字块，插回它原来的位置；现在有、保存版里没有的段是**增加**——整行绿。一段改了
  几个字 = 旧的一段红、新的一段绿，按行算，不做字级 diff。写作助手流进来的和作者自己敲的走
  **同一条路**——它每敲一个键都重算（两头相同的行先剥掉，`diff.ts`）——按「保存」痕迹就没了，
  那一刻保存版就是眼前这份。流着的时候按半份正文的规矩画：还在打的那一行不算，尾巴上还没被
  后面原样保留的段钉死的删除先不画红（不然红块闪一下又没），流一收场全份对全份。
  作者上午说过「红绿看着乱」，晚上指着 git diff 说要的正是这个——以后一句为准。
  **大块红折起来**：一块红里删掉的段数到了保存版的一半以上（且不止两段）就折成一行
  「已删除 N 段」，点开才摊开、再点折回；作者点开之后接着敲字它不折回去（摊没摊开记在编辑器
  状态里，按那一块的内容认），换了保存版归零。整章重写就是这一档——旧章不再是一整屏红压在
  新稿上面，只剩一行。
- **稿子永远在左边。** 作者手上有没保存的字时也一样：稿子照写在编辑器里、替掉它们——那几段
  没丢，在编辑器的撤销历史里（⌘Z）。第三版曾给「编辑器里有没保存的字」留了一条退到右边的路，
  第二稿真的退过去了——作者当场否了。
- **贴着底跟、翻上去留在原地，判「翻上去了」只认作者自己的滚动手势。** 滚轮 / 触摸 / 拖
  滚动条 / 键盘之后紧跟着的 scroll 才算他翻了；编辑器自己滚（跟底那一下、CM6 量完行高再对
  一次）也会发 scroll，那时离底几十像素只是正文刚长出来一截——按位置判会在正文长到满一屏
  之后每隔一会儿就把跟底掐断一次、弹出「滑到最下方」（作者：「他到满一页的时候他就不让人跟」）。
  滚回底了（不管谁滚的）就又贴上。
- **写出来的和本章正文一字不差时，说出来。** 真书第 158 章：助手连开五稿、要求各不相同，
  写手回的正文五次逐字节等于磁盘上那一章——写手把「目标章当前正文」照抄了回来（那一段在
  写手 prompt 里只挂着一个标签、又排在最末，模型眼里就是「接着输出这个」；现在它说清自己是
  要被替掉的，并排在「这一场要写」前面，`product_draft._TARGET_CHAPTER_ASK`）。界面这一侧：
  这样的一稿放进编辑器后不脏、没有痕迹，顶栏说「写作助手的这一稿与本章正文相同」，右边那一行
  说「已放入编辑器，与本章正文相同」——作者才知道没有红绿不是界面坏了（「为什么我这边左边
  还没有？」）。
- **对话这一侧每稿一行，字一个都不画。** 「第几稿 · 字数 · 在哪儿」+ 写手那句自述：在编辑器里
  未保存的说「已放入编辑器，按「保存」写入本章」，保存了的说「已写入第 N 章」，还在桌上的
  （一批几稿的第二稿起 / 上一稿被替下来的 / 按停砍断的）一颗「放入编辑器」——读它的地方也是
  左边的正文。写的时候右边连那一行都没有（作者：「不用特地提醒在左边什么的」）。摊开的卡
  （`DraftCard`）只在并排比那一页；起草要求和补充资料也只在那儿。
- **写手那句自述的记号，第一行开头的变体也认。** 真书上写手把 `〖自述〗` 写成了 `「自述」`，
  ADR 0022 下那一行只是候选卡上多一行机器话，现在它会随保存进作者的章。`split_self_note`
  只在第一个非空行的开头认 `【自述】` / `「自述」` / `（自述）` 这几种（那是我们要它写自述
  的位置，写手的散文不会从那儿起笔），行中和后面的行仍然一律不认；前端流字时也不把那一行画进正文。

## 同日改动记录

这份 ADR 一天里改了三版，记下来是因为**第一版的机制和终稿相反**：

1. **第一版（上午）：起草即落盘。** `draft_chapter` 写完直接写进那一章（`ChapterDesk.land`
   在锁里排队、`_written` 记着自己写的那一版好让一批几稿依次盖），退路是版本历史。
2. **第二版：写的过程流进左边。** 同一条流喂给编辑器，落盘之后编辑器换成磁盘上那一版。
3. **第三版：落盘交回作者。** 作者看着流进来的字之后说：写完不该自动就存了，他要自己按保存、
   看清哪些是新的哪些是改的。于是第一版的落盘机制整个退了（`land` / `_land` / `_written` /
   `LandingReport` / `landing_*` 那十句都删了），保存走他自己那条 `PUT`，带上 `draft_id`。
   ADR 0021 的「落盘不问作者」到此**收回**：不是机器不问，是机器不落盘。这一版给「作者手上
   有没保存的字」留了一条路：那时不接，稿子退到右边那一格里长、写完是一张卡。
4. **终稿：稿子永远在左边，痕迹改成 git diff 式。** 第三版那条退路真的走到了（上一稿没保存
   就是「有没保存的字」），第二稿在右边写了出来，作者：「我前面特地把你调到左边……一定要在
   左边写」。退路删了（收起他的字、稿子照写）；右边的卡也删了，每稿一行。同一晚他把痕迹的
   要求改成「不管是他写的还是他编辑的，只要没有保存就要有编辑的痕迹，红减绿增」——第三版
   那套只给助手那一稿涂的段级底色（`tint.ts`）换成了对着保存版算的 diff（`editMarks.ts`），
   作者自己敲的字也一样画。再后面：「放弃这一稿」那颗按钮删了（不要它走 ⌘Z 或「历史」）；
   大块红折起来；跟底改成只认作者自己的手势。

## 为什么

### 1. 「问一句要不要存」是 ADR 0022 拆开之后长出来的，不是谁想要的

ADR 0022 把落盘拆成模型的第二个动作之后，模型手上多了一个「存不存」的选择——它就会去问
（真书上这一轮问了：「可以我就存进去了」）。终稿把选择从模型手里拿掉的方式不是「让它直接存」，
是**它根本没有存这个动作**：存是作者按的那一下。

### 2. 右边摊一整稿，是让作者在错的地方读

正文的家在左边的编辑器里：那儿有章标题、有保存、有历史、有检验。右边再摊一份，
作者要在两块屏幕上读同一段字。**稿子进左边，右边只报一行**，读和改都在正文该在的地方；
而它以未保存的样子留着，正是作者熟悉的那个形态——和他自己改了几段还没按保存一模一样。

### 3. ADR 0022 的四件好处，三件原样留着，一件不再需要

- 同一轮多稿不再打架 —— 这一层不写盘了，没有底稿闸可撞；
- 崩了重跑安全 —— 补跑只是再花一次钱，不会往书里写第二遍；
- 一批稿可以并发 —— `draft_chapter` 仍然没有副作用；
- 「作者打字 / agent 落盘」的碰撞 —— 不存在了：写盘只有作者自己那一次。

## 代价

- **要几个版本时，编辑器里只有第一稿。** 其余在右边各一行，「放入编辑器」换进来看；
  并排页仍是比较几版的地方。
- **写完那一刻它是一份未保存的修改。** 关掉标签页、换章，和作者自己没保存的字一样会丢
  （稿子本身还在桌上，`read_draft` / 并排页 / 「放入编辑器」找得回来）。
- **整章重写时看不到旧章和新章的对照。** 按行算的 diff 对着一份被整个重写的正文，就是旧章
  全删、新章全增；旧章那一块折成一行，点开也只是上下堆着，不和新稿对齐。保存版和新稿左右
  并排的视图今天没有（并排页比的是几稿之间，「历史」抽屉里是上下堆的行级 diff）。
- **删掉一个空行没有痕迹。** 空行不参与比对（它们长得一模一样，参与了会把这一段的红块和另一
  段的绿行配成对）；保存按钮上的水滴仍然说它没保存。

## 没做的（有意）

- **改一两句的工具。** 今天助手改一章只有整章重写这一条路；「替换某一段」要靠引语定位
  （`text/anchor`），另开一刀。
