# ADR 0025：没登记的路由去问端点自己 —— 把「查证」从事先审计扩成运行时读表

- **状态**：已接受
- **日期**：2026-08-13
- **推翻了**：不是原始需求文档，也不是任何一条 ADR，而是一个**从没写下来过的隐含前提**——
  「一条路由的能力**只能**由维护者事先审计、手写进 `CAPABILITY_REGISTRY`」。
  `resolve_capabilities` 的签名里一直留着 `metadata` 这一档（`override → 注册表 →
  metadata → unknown`），**而它从落地那天起就零调用方**。本 ADR 是它的第一个走法。
- **相关**：[ADR 0011](0011-bilingual-draft-length.md)（长度与 provider 档）、
  [ADR 0013](0013-length-is-the-authors-intent.md)（长度是作者的意愿，不给模型旋钮）、
  [ADR 0024](0024-a-turn-is-a-conversation-not-a-black-box.md)（边跑边发事件 —— **本 ADR 是它在
  作者自选端点上的前置条件**：不流式就没有事件）
- **决策日志**：没有。**当天的实测证据全部写在下面「实测证据」那一节**——
  它是这条 ADR 的论证本身，不该躺在一份非权威的日记里再被引用一次。
  复跑：`uv run python scripts/probe_stream_usage.py --base-url ... --model ... [--provider ...]`

## 决策

**`resolve_capabilities` 返回 `unknown` 的那些路由，去问端点自己。**
只对「把能力发布成可读 API」的家成立；今天只有 OpenRouter
（`GET /api/v1/models/{slug}/endpoints`，公开、免鉴权）。实现在 `draft/discovery.py`，
装配层改调 `resolve_with_discovery()`（`api/deps.py` ×3、`api/app.py` ×1、`agent/model.py` ×1）。

**六条边界，每一条都是「往哪边错」的裁定：**

| | 规矩 | 错了会怎样 |
|---|---|---|
| 一 | **登记过的路由一次网都不发**（在 `resolve_with_discovery` 里短路，不靠内部优先级） | 否则 M2 判分链的能力可能被一个第三方 API 的返回值改写 = **考卷被外部改动** |
| 二 | **数字逐字段取下确界**（上下文取一家、输出可能取另一家），参数集取**交集** | 我们不发锁上游的字段 ⇒ 任何一次请求都可能落到最小的那家 |
| 三 | **读不懂就整份作废**，退回今天的 `unknown` | **半份能力比没有能力危险**：它能通过 `plan_call`，于是稿子按一个我们编的预算发出去 |
| 四 | **认出推理能力时方言必须是 `OPENROUTER`** | `NONE` 方言下 OFF 档一个字段都不发，而这些模型**默认就在思考** ⇒ 预算算少 ⇒ 稿子被截断 |
| 五 | **`reserve_ratio_high` 一律 `None`** | 它只能靠实跑长稿测右尾，问不出来。于是非 OFF 档在 `plan_call` 上被拒 —— 理由是「没实测过预算比例」，不是「不支持这个档」 |
| 六 | **判据是 host 精确相等** | 子串判据会让 `openrouter.ai.evil.example.com` 命中，而那时一个陌生主机能改我们的预算、能开我们的流式 |

## 为什么

### 1. 「作者自己选端点」是产品事实，而 fail-closed 的代价全落在他身上

BYOK 从 2026-08-02 就落地了：作者在设置页填地址/模型/钥匙，填什么是**他的自由**。
而注册表只认那几条精确路由（条数在 ARCHITECTURE 的「当前状态」），填了别的 ⇒ `unknown` ⇒ **三样东西同时哑掉**：

| 字段 | `unknown` | 作者看到的 |
|---|---|---|
| `supports_streaming` | `None` | 起草不流式 ⇒ **「停」退化成「这一稿写完才停」、字不再一个个长出来** |
| `supports_stream_usage` | `None` | 每一稿的 token 数「未记录」 |
| `max_context_tokens` | `None` | 记忆层倒推不出预算 |

**注意第一行**：ADR 0024 刚刚把「边写边看」做出来，而它在作者自选的端点上**从来没亮过**。
这不是那一刀没做完，是它的前提（流式）被 fail-closed 掐掉了。

### 2. 注册表的立场没有松动，松动的是「查证」的定义

原来的规矩是「没查证过的不许声称支持」。**本 ADR 一个字都没改它**——
改的是「查证」可以来自哪里：

    维护者读文档 + 实跑     → 写进注册表      （照旧）
    端点自己发布的能力 API   → 运行时读         （本 ADR）
    什么都没有              → unknown         （照旧）

第二档**不比第一档弱**：那份 API 是这家自己对每个上游逐条声明的上限，
比「读一遍文档抄下来」更贴近真实路由。真正的差别是**它会变**，而注册表是冻的——
所以它进 `metadata` 那一档（低于注册表、高于 unknown），位置本来就是对的。

### 3. 为什么是「问」而不是「登记几个热门 slug」

2026-08-13 的产品裁定：**不锁模型**。OpenRouter 上有 14 个 DeepSeek slug、
上千个模型，作者选哪个是他的事。预先登记等于替他挑，而且下个月就过期。

### 4. 下确界为什么是唯一读法

同一个 slug 后面站着一堆上游（`deepseek/deepseek-v4-flash` 实测 **19 家**），
上限差得离谱：

    输出上限   Venice 32,768 · DeepInfra 65,536 · 官方 DeepSeek 384,000
    缓存读价   官方 $0.0028/M · 第三方 $0.017–0.07/M（差 6–25 倍）

**产品今天不发锁上游的字段**，所以任何一次请求都可能落到最小的那家。
取 `min` 是唯一 fail-closed 的读法；取 `max` 或「挑一家全抄」的后果是**高估**，
而高估的表现是稿子写到一半被上游截断。

## 实测证据（2026-08-13，`scripts/probe_stream_usage.py`）

路由 `openrouter.ai/api/v1 + deepseek/deepseek-v4-flash`，锁官方上游与不锁各一轮：

- **流式下报 usage**：三臂全报，**连不要 usage 的那一臂都报**（OpenRouter 归一成 OpenAI 形状转出来）；
- **前缀缓存过中转照样命中**：同一段 1,814 token 的前缀连发两次，第二次 `cached_tokens=1792`（**98.8%**），
  而且 `_cache_usage` **不用改一行就认得出**——它的判据一直是「响应里有哪个字段」，不是「我配的是哪家」；
- **推理四档全通**（off/low/medium/high）；
- **输出上限测不出来**：384,000 收下了，400,000 也收下了 ⇒ 它不校验 ⇒
  「收下了」不能当证据，上限只能取端点表声明的那个。

## 代价（承认，不粉饰）

- **引擎第一次为了拿能力去问一个第三方。** 进程内缓存 + TTL 一小时 + 5 秒超时 + 失败也进缓存，
  但这仍然是一条新的外部依赖。**失败方向是安全的**（退回 `unknown` = 今天的行为）。
- **`supports_streaming` / `supports_stream_usage` 是 host 级外推**，不是逐 slug 实测：
  它们被当成「OpenRouter 这个 host 的属性」。若某个 slug 其实不吃 `stream_options`，
  症状是**起草 400**。那时把这两个改回 `None`（退回不流式但写得出稿），
  **别去给单个 slug 开豁免**——豁免会被拓宽。
- **下确界会低估**：作者锁了官方、本可以用 384,000 输出的那一档，我们照样只给他 32,768。
  那不是 bug，是「我们不知道这一次会落到谁头上」的诚实表达。要拿回那个大数，
  得先让产品发得出锁上游的字段（**那是另一次改动，本 ADR 不做**）。
- **`/draft` 仍然对这些路由 422**（它写死 `ReasoningEffort.HIGH`）。起草工具和聊天走 OFF，两条都活。
  **这条不是本 ADR 引入的**，它在 `unknown` 那一档就存在；本 ADR 只是把理由从
  「这个档不支持」换成了真话「这个档的预算比例没实测过」。

## 什么条件下推翻本 ADR

满足**任意一条**：

- **端点发布的数字被证明不可信**（声明的上限发过去就被拒）。那时退回只认注册表，
  并把那家从 `_DISCOVERERS` 上摘掉。
- **出现「问一次要很久」的形态**：缓存没挡住、作者在起草前干等。那时改成
  「作者在设置页保存时问一次并存下来」——**那个形状更好，本 ADR 没做只是因为它要动设置存储**。
- **有人为了让某个 slug 能用而在这个模块里加豁免**。那说明判据错了，
  该改判据，不该加豁免（同「屏幕守卫不许开豁免」那条）。

## 若此决策错误，修复成本是什么

**低。** 把 `_DISCOVERERS` 清空，一切退回今天的 `unknown`——
所有装配点调的还是同一个函数名，wire shape 不变，注册表不变。

**但有一条不对称**：如果边界三（读不懂就整份作废）写松了，
**作者的稿子会按一份我们编的预算发出去**，而症状是「写到一半没了」，
看起来像模型不行。所以那一档必须有测试：`tests/test_capability_discovery.py`
八种烂响应逐一断言退回 `unknown`。
