# ADR 0037：拿不准就往里加人，不整个放弃 —— cast 与认知边界的退化方向

- **状态**：已接受
- **日期**：2026-08-23
- **推翻了**：不是原始需求文档，是**本仓库自己**——[ADR 0018](0018-cast-is-derived-not-declared.md)
  §2 那句「歧义称呼由 `rules_only=True` **天然出局**（fail-closed）」。
  **那只在 cast 因此变空时成立。** 决策正文一字未动，那一节已加带日期的补记。
- **相关**：[ADR 0005](0005-set-judgment-only.md)（规则只做集合判断）、
  [ADR 0015](0015-inline-continuation-is-a-short-draft.md) D4（退化态的「在场：未知」——
  本 ADR 把它删了）、[ADR 0019](0019-agent-loop-not-graph.md) 边界一 / 边界六
  （工具表是权限边界；认知矩阵不进稳定前缀）

## 决策

**一条判据，三处落地。**

> **多算一个人 = 多一批禁令 = 安全；少算一个人 = 漏 = 危险。**
> 所以拿不准的时候**往里加**，而不是**整个放弃**。

| 处 | 从前 | 现在 |
|---|---|---|
| 歧义称呼（模式二） | 「师兄」解析不出唯一的人 → **整章退化成全书全禁** | **所有候选的正式名都算在场**，按这几个人算禁写清单 |
| 模型主动查认知矩阵 | 查不到（整张表被出参收窄挡在外面） | **给一格，不给整张表**：某人在第 N 章知不知道某条秘密，答案里明写「截至第 N 章」 |
| 续写的【在场】块 | 渲染「【在场】未知。因此这一段不得说破任何尚未公开的秘密。」 | **删掉**。粗的禁写清单和「尚未登场」两行留着当提醒 |

**保留不动**：第一章、或者全新的书，前面没人可借——那时全禁是唯一诚实的答案。

## 为什么

### 「整个放弃」也安全，但它安全得没用

判据是「在场**至少有一个人**还不知道」→ 就禁。所以**只加不减是 fail-closed 的那一侧**，
方向可证明。全禁当然也在那一侧——但 **AI 面对一份「什么都别碰」的清单，写出来的东西本来
就不能用**。安全而无用不是安全，是把成本转嫁给了作者。

而它有多常见：起草一个刚开头的空章，**必然触发**——那正是最常用的起草场景。

### ADR 0018 §2 那句话错在哪

它说歧义称呼被 `rules_only=True` 挡在外面是 fail-closed。**这只在 cast 因此变空时成立**：
空 cast 会整体退化成全禁，那确实是安全侧。

但**这一场还有别人在的时候，丢掉那一个人就是 fail-open**——禁令按剩下的人算，比该有的少。
它和 `panel/constraints.py` 记着的那个真 bug 是同一形态。
`test_more_candidates_only_ever_means_more_bans_never_fewer` 就是那个反例：
同一份正文，不展开时 `[顾清音]` 禁 0 条，展开后 `[顾清音, 萧决]` 禁 1 条，断言
`bans(narrow) ⊆ bans(wide)`。方向反了就红。

### 为什么给一格而不是整张表 —— 理由是**寿命**，不是内容

模块头原来的理由是「出参一律收窄，`Node` / `StateSnapshot` / `KnowledgeMatrix` 一个都不出」，
因为节点属性里作者写的东西会穿过序列化。**这条对矩阵不成立**——矩阵上没有 props，
只有 id/label/name 和几个纯量。

站得住的理由是另一个：**对话是持久化且会累积的。**

矩阵跟章号绑死。模型在第 10 章查了一次，那张表就永远躺在历史里；写到第 50 章时**它已经错了**，
而且错的方向是 **fail-open**（到第 50 章更多人已经知道，禁令该更少，旧表看起来更严）。

> **起草时的 prompt 每次重建、用完就没了，所以安全；工具结果会永久留下，所以不安全。
> 两者的差别不在内容，在寿命。**

所以：一次一格；**章号必须写进句子本身，不能只挂字段**（投影那道闸只丢「绑在更后面的章」的
返回，一条第 10 章的答案在第 50 章照样在）。

### 为什么续写那一块该删

```
【在场】
未知。因此这一段不得说破任何尚未公开的秘密。
```

「未知」两个字不带信息；后半句跟下面那行禁写清单是**同一句话说了两遍**。

**拆分线是「依赖在场的搬走，不依赖在场的留下」**：认知矩阵和精确的禁写清单依赖在场，
归验证侧；粗的禁写清单和「尚未登场的实体」（只看章号）留在写时当提醒。

**关键是一条不对称**：写之前不知道谁在场（那是被这一段写出来的结果），写之后知道（数得出来）。
同一个问题在生成侧无解，在验证侧**精确**——把它搬过去不是降级处理，
**是搬到了它唯一能算准的地方**（见 [ADR 0038](0038-track-guardrails-and-split-contexts.md)）。

## 两处不对称，都是有意的

**一、模式二展开歧义，验证侧不展开。** 模式二算的是「给模型的禁令」，多算只多禁；
验证侧算的是「报不报警」，**多算一个人就是多一条打扰**——而 ADR 0030 的第一条推翻条件
正是误报把通知变成噪声。

**二、模型那一侧展开，作者右栏不展开。** 「师兄」对应 8 个人时，右栏冒出 8 行是噪声，
正好犯了「机制词不上屏」。**右栏要给人看得懂，模型那边要宁可多禁——两个目标不同，
判据不同是对的。** 写在这儿，是因为下一个人会把它当成 bug 去「修统一」。

## 实现上两条容易踩的

- **展开出去的必须是候选的正式名。** 把「师兄」原文交回去会被 `resolve_cast` 判成
  unresolved，等于又全禁。
- **展开只放开「歧义」这一条**，不放开短别名 / 作者标掉的别名——放开了就是往 cast 灌噪声。

## 若决策错误，修复成本

**低。** `mentioned_cast` 的 `expand_ambiguous` 默认 False，模式二那一侧传 True；
关掉它就退回今天的行为，面板和模式一那条路一个字节不受影响。

窄工具 `knows_secret` 是工具表尾部追加（不插中间，稳定前缀不作废），摘掉它也是一行。

**但摘之前先回答：退回全禁之后，起草一个空章时 AI 拿到的那份「什么都别碰」的清单，
作者要怎么用？** 没有答案时，别摘。
