# ADR 0007：正文在磁盘上，v1 不做编辑器

- 状态：已接受
- 日期：2026-07-16
- 推翻了什么：需求文档第 4 节技术栈（TipTap / ProseMirror）、第 17 节 Writing Workspace、第 22 节第 12 项

## 决策

**正文是磁盘上的 Markdown（`chapters/151.md`）。作者继续用 VSCode / Obsidian / Typora / 任何能编辑 .md 的东西写。**

**Novel Harness 是旁边那个浏览器窗口**：它 watch 文件、显示面板、跑检查、起草场景、管图谱。**只读面板，无编辑器。**

场景元数据是一行 Markdown 注释：

```markdown
## 场景 3
<!-- nh: cast=萧决,顾清音,李管家 loc=青云城主府 goal=李管家试探萧决的身世 -->
正文……
```

丑，但零 UI 成本。面板上有「本场景在场角色」多选框——点一下，这行注释被写回文件。**50 行代码 vs 4 周。**

## 论证

1. **TipTap 是 v1 最大的单项开销：4–6 周。**

2. **它买来一整类 bug。** 见 ADR 0006 的三重错位（坐标系 / UTF-16 vs code point / 快照漂移）。这些会以「偶尔位置差一两个字」的形态出现，被误当成小 bug 调两周。

3. **换编辑器是头号采纳障碍。** 日更作者的编辑器是**肌肉记忆**——他的快捷键、他的字数统计、他的自动备份、他的断更恐惧。**换编辑器 = 一次断更风险 = 掉推荐位 = 真金白银。**

4. **决定性的一条：面板是产品，而面板不需要编辑器。** 为了托管一个面板去造一个编辑器，是反的。

## 这一条也顶了胜出方案自己

「编辑器优先」方案的骨架和它最强的三条洞察（规则只在作者确认的边上开火 / 价值曲线从 t=0 起步 / 证据是误报缓释而非审计）全部保留。砍掉的是它的编辑器。

**这不是背叛它的论点，这是执行它的论点**——它论证的是「作者今天就愿意打开」，而**「你不用换编辑器」比「我们的编辑器很好用」更接近这个论点**。

## 副作用（全是好的）

1. **offset 地狱整个消失**（v1 没有行内 decoration）
2. **`revalidate` 从第一天起就被真实的编辑行为持续压测**——而自研编辑器反而会因为可控而**掩盖**这个问题
3. **README 的 GIF 多说了一句话**：分屏，左边 VSCode 打字，右边浏览器面板实时更新在场角色的认知边界矩阵，8 秒。而且它顺带说了：**不用换编辑器**

## 实时性：拆两条路径

| 路径 | 触发 | 延迟 |
|---|---|---|
| **面板** | 场景元数据变更（`cast` / `loc`） | **不读正文**，本机 HTTP 2–5ms，瞬时 |
| **规则** | 正文变更 → debounce **2s** → 后端跑 | 「停手 2 秒后闪红」 |

规则不需要 200ms——**它是一个「检查」功能，不是自动补全。**

这样避开了「用 TypeScript 把规则重写一遍」的重复实现：**判分器和 Validator 保持同一份 Python 代码**（`checks/`）。这一条对 M2 的 kill-gate 至关重要——评测用的判分器就是产品用的 Validator。

快照策略：debounce 只 `UPDATE` 文本；`chapter_snapshot` 仅在**显式保存 / 切章 / 关闭**时插，且插之前比 `text_sha256` 去重。否则每 800ms 插一行 = GB 级。

## v1 的用户画像（这条写进 README 第一屏）

> **写中文长篇、正文用 Markdown、会开终端的作者。**

这排除了 95% 的目标市场（Windows + WPS + 没装过 Python）。**这是诚实且完全正当的选择——早期开源项目本来就该服务技术型早期用户。**

被否决的替代方案：Windows 签名 exe（2–3 周 + 每次发版的 Windows CI）。不选，因为**它解决了装机也解决不了「作者要多写字不要少写错」这条更根本的风险**。

分发用 `uvx novel-harness`，不用 Docker Compose——比 `docker compose up` 更一键，且不要求装 Docker Desktop。

## 若此决策错误，修复成本是什么

**低，而且是加法。** 如果真有作者要求内置编辑器，v1.1 加 TipTap 时：
- 图层、规则、面板、起草**全部不动**（它们本来就不依赖编辑器）
- 只需新增一个前端组件 + 一套 `(para_index, quote, k)` → ProseMirror pos 的映射

**而反向不成立**：先做编辑器，4–6 周沉没，且 offset bug 会污染 M1–M3 的每一次调试。
