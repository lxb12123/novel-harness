# ADR 0045：只有「机器要推翻作者」才做提案卡 —— 机器推翻机器，直接改

- **状态**：已接受（2026-09-06，维护者裁定）
- **推翻了**：不是原始需求文档，是 [**ADR 0020**](0020-clean-extraction-auto-canon.md)
  定的三个例外桶之一 —— `edge_conflict` 的**触发条件**。
  另外两个桶（`low_confidence_main` / `new_character`）一个字没动。
- **相关**：[ADR 0020](0020-clean-extraction-auto-canon.md)（干净抽取自动升 CANON——
  这一刀是把「干净」的定义放宽，不是把闸拆了）、
  [ADR 0043](0043-facts-store-a-start-not-an-interval.md)（**这一刀的前提**：
  事实只记起点、人物卡印全部历史，所以自动生效不丢东西）、
  [ADR 0005](0005-set-judgment-only.md)（只做集合判断——新判据仍然是查一行记录）、
  [ADR 0004](0004-declaration-over-extraction.md)（作者的决定优先于抽取，
  这一刀正是把那条原则落到「谁值得被打扰」上）

---

## 一句话

从前：**抽取读出的事实和当前 Canon 不一样 → 做一张卡等作者点。**
现在：**只有那一格是作者亲手改过的，才做卡。** 机器推翻机器，直接生效。

---

## 事实（真书实测）

2026-09-06 全书回填之后，待确认队列：

| | |
|---|---|
| 卡片 | **100 张** |
| 条目 | **298 条**（位置 142 / 状态 90 / 关系 66） |
| 按 15 秒一条估 | **75 分钟纯点击**，而且每写十几章再攒一批 |

位置那 142 条里大量是「同一处两个叫法」（荣国府 / 宁荣街 / 贾府）——系统分不清那是
**他走了**还是**同一处的两个名字**，那需要读懂剧情，铁律不做（ADR 0005）。

**而不点的时候那些事实既不进人物卡也不进写作上下文。** 也就是说：抽取花了钱、读对了，
产物躺在一个没人点得完的队列里，等于白跑。

维护者的原话：

> 「这类问题导致的冲突不需要放通知这边，直接更新抽取到那个角色卡的状态中，
> 然后用户要是觉得不满他自己可以改这个内容的。然后在角色卡这边改内容发现真的与
> 原文意思冲突现在这种就可以去在通知中加这个冲突卡片。」

---

## 决策

`extract/service.py` 里那个 bucket 判据从

```python
if current is not None:                      # 和当前 Canon 不一样
```

变成

```python
if current is not None and queries.active_canon_override_for_edge(...) is not None:
                                             # …而且那一格是作者亲手改过的
```

**判据是查一行 `canon_edge_override`**（「这条边当前由作者接管」，020 就有的机制），
**不是判断两句话意思冲不冲突**——后者是语义判断，ADR 0005 的铁律禁的。

没进 bucket 的边落进 `report.clean_edge_ids`，由 `promote_clean_facts` 照旧自动升
CANON（那条路一个字没改）。

---

## 为什么这一刀敢落：**它不丢东西**

这是它和「把闸拆了」的全部区别，而前提是同日的另一刀（ADR 0043）：

| 人物卡那一格 | 自动生效之后 |
|---|---|
| 状态（修为 / 身份 / 装备…） | **印全部历史**（`state_history`）：`三阶 第18章（最新）  一阶 第5章` |
| 所在地 | **印全部历史**（`location_history`）：`观音寺 第156章（最新）  荣国府 第5章` |
| 关系 | 黑框里本来就按章号列全部 |

**旧值不会消失，只是不再排第一。** 作者随时看得见系统把什么换成了什么，不满意就在
那一格上手改（`PATCH /canon/edges/{id}`，那条路 020 就在）。

⚠️ **这一刀不许在 ADR 0043 落地之前做**：那之前人物卡只印当前值，自动生效等于把
旧值静默抹掉——那才是真的丢东西。

---

## 留下的那一种卡，以及它为什么值得留

**机器要盖掉作者亲手改过的那一格。** 这一档不能自动生效，理由和上面完全对称：
自动那条路不许花作者没按过的钱去抹掉他刚做的决定（同 `_head_missing` 那条
「他删一次系统别买回来一次」的纪律，ADR 0043 也照旧遵守）。

两侧各一条测试，**缺一条这一刀就读不出是「换判据」还是「拆闸」**：

- `test_auto_canon.py::test_clean_facts_promote_themselves_and_bucketed_ones_stay_in_the_queue`
  —— 作者没碰过那一格 → 直接升，队列里没有 `edge_conflict`；
- `test_auto_canon.py::test_a_slot_the_author_took_over_still_asks_first`
  —— 作者先接管 → 同一条更新回到队列上。

## 配套的第三问（另一个开关，默认关）

作者接着问的是第三种情况：**他自己改完那一格，改的东西和原文对不上怎么办。**
今天完全没有任何东西会去核对它。

落法：`settings.review_card_edits`，**默认关**，开了才在 `PATCH /canon/edges/{id}`
之后（后台任务）叫一次核对模型，落 `text_advisory`（只告警、永不阻断、不进队列）。

**为什么是开关而不是默认行为**，两条都不是「省钱」那么简单：

1. 它每改一格花一次模型调用，而作者理顺一个人物卡可能连着改十几格；
2. **它判错的时候是在质疑作者的决定。** 机器判错机器，作者笑一下就过去了；
   机器判错作者，那是在说「你写的东西不对」——这一侧的误报比另一侧刺人得多。

那一问的输入**刻意窄**（那一格现在的值 + 它挂着的那句原文），不给整章正文：
前两问的教训是给多了模型会跑去评价文笔。它是 `ReviewKind` 的第三个成员
（`card_edit`），账、去重、失败形态全部沿用既有那两问。

**顺带补的第三件**：改过的那一格在人物卡上带「你改过」的标记，点得到那一章
（判据是 `author_owned`，同一行 `canon_edge_override`）。**这一件零成本、零误报**，
而且它让上面那个开关变成可选项而不是必需品——作者自己看得见哪些是他改的。

---

## 若此决策错误，修复成本

**低。** 一行判据，改回去就是从前的行为：

```python
if current is not None:                      # 去掉后半个条件
```

真正不可逆的只有一样：**这段时间里自动生效的那些事实已经是 CANON 了**。但它们
不是「丢了的旧值」——旧值还在历史里，而且每一条自动生效都在 `decision_log` 里
留了痕（`actor='system'`，ADR 0020 的前提之一就是这条退路）。要回退到「全部重新
等确认」得手工撤回，那不现实；但**要停止继续自动生效，改那一行就够了**。

## 没有做什么

| | 为什么 |
|---|---|
| **合并近义地点 / 字段名** | 「宁荣街 == 荣国府」是语义判断，引擎不做。位置那 142 条冲突里大量是这一类，**自动生效之后它们变成人物卡上并列的两个地名**——作者一眼看得出是不是同一处，而这正是把判断留给他 |
| 让核对模型默认跑 | 见上面那两条理由 |
| 动另外两个桶 | `low_confidence_main`（主角低置信）和 `new_character`（新人物）照旧进队列。它们不是「机器推翻机器」——一个是机器自己不确定，一个是要在书里新增一个人 |
