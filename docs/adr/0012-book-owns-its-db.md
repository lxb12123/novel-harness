# ADR 0012：库跟着书走（没有全局默认位置）

- 状态：已接受
- 日期：2026-08-02
- 解决的问题：`novel-harness` 不带参数该开哪个库——`__main__.py` 因此一直是 stub
  （`uvx` 叙事里「一条命令」的最后一截）。

## 决策

**一本小说 = 一个文件夹，`book.db` 住在那个文件夹里**（跟稿子一起搬家）：

```text
我的小说/
├── 书稿/          # 作者自己的 markdown
├── 大纲.md
└── book.db        # 系统建的，跟书走
```

- `novel-harness` 不带参数：从当前目录**向上**找最近的 `book.db`，找到就
  `serve --db <它>`；找不到就给一句人话 + 两条出路（进书文件夹 / 先建库）。
- 带参数时原样交给 `nh`（`--help` / `serve` / `import` 照常）。
- **多本书物理隔离**：查找只向上不向下，A 的库只会在 A 文件夹里被命中；
  程序一次只开一本书。

## 为什么

- **搬家 = 复制文件夹**（ADR 0007 的精神：稿子在磁盘上、作者自己管文件）——
  图谱跟着书走，不会出现「库在 C 盘、稿子在 D 盘」这种作者搞不懂的事。
- **不把绝对路径写进库**（ADR 0007 的 `root_path` 教训：路径进了库，库就不可搬家）。
- 和已有的「＋新书/导入」按钮天然接上：导入 = 选一个文件夹 → 在那儿建 `book.db`。

被否掉的替代：`~/Library/Application Support` / `~/Documents` 之类的全局位置——
作者找不到、备份会漏掉它，等于把一本书拆成两个地方。

## 若决策错误，修复成本

低。位置是**入口的行为**，不是数据格式：真要改成全局目录，给查找顺序加一个
候选路径即可，已存在的书不受影响（它们的 `book.db` 本来就在自己的文件夹里）。
