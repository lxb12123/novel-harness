## 一句话

作者的原话（2026-09-12）：

> 「助手应该要分析一下用户的意图……他的工具很多……有目的的筛选去检索，而不是直接全部拿进去……
> 写手只有最近几章的上下文，那么涉及更远的那些章节或者章节细节，助手就应该帮忙把这些喂进去……
> 然后助手也要做校准——是**这个**校准：侧边栏那个检验规则，加用户自己填的，还有会记住的、
> 有时限的规则。我主要是不满这个（旧的）校准，因为它是很早很早以前的东西。」

**写手只管写；找资料、定要求、对照规矩，都归助手。** 校准这个词留下，换了含义：
对照的是**规矩**（检验规则 / 有时限的规矩 / 查到的事实矛盾），不是一份旧报告。

## 为什么旧的那条链要退

1. **它服务的对象都没了。** 0033 定于 8 月 17 日；校准报告里「登场没 / 不许说破什么 /
   安全事实必须先纠正」那几格是为秘密（8-25 下线）、未登场清单（8-31 下线）、R3（9-05 砍）
   设计的。刀落在它们身上时，这条链没人动。
2. **它在真书上从来没跑通过。** 158 章那本：校准报告 6 份（全是 2026-09-12 失败那几轮留下的）、
   封存 0 份、模式二起草出来的稿子 **0 篇**。写手那 264 次成功调用全是续写模式的。
3. **它装不下作者真正要说的话。** 「要写什么」被锁成五个封闭码（进入某地 / 寻找 / 试探某人 /
   推迟揭示 / 推进线索），「重写结局，裕王已经死了别再当活人写」一个码都表达不了；
   在真书上封存出来的 `goal_spec` 是**空的**。
4. **它撑爆了助手的上下文。** 报告把第 1–N 章的全部摘要都装成事实，一份 232 KB，比一次
   工具返回的天花板大七倍；投影层只能整条收起，于是助手连报告的编号都没读到，猜了一个去
   封存、起草，八步用完。同日的临时修补（按预算收成 `CalibrationView`）证明了这条链的形状
   本身不对：写手反正会自己装那几格，再为助手查一遍是重复。

## 新的起草流程（模式二）

```
你说一句（「重写结局」「给第 40 章补一场戏」……）
   │
   ▼
① 意图分析   助手判断：要写哪一章、是新写还是重写、牵涉谁、牵涉哪几章
   │
   ▼
② 由粗到细检索（工具，它自己定）
   目录 → 总结（粗）→ 事件 → 角色卡（关系/状态）→ 原文（只在需要细节时）
   有目的地挑，不是整本拿
   │
   ▼
③ 校准（新含义）——对照规矩，不是对照旧报告
   · 检验规则那一栏：内置的（今天为零）+ 你自己加的禁用字
     （它用 validation_rules 读，还能看这一章上次检验命中了哪几处）
   · 你交代过的有时限的规矩（它记着的那几条，带「管到什么时候」）
   · 它查到的事实矛盾（裕王 154 章已死 → 这一稿不能当活人写）
   → 决定这一稿要守什么、要避什么，写进 brief
   │
   ▼
④ draft_chapter(chapter, brief, materials)
   brief     = 它用自己的话写的「这一稿要做什么 + 要守什么」
   materials = 它筛出来的、写手固定装配够不着的东西：
               远章的总结 / 关键事件 / 原文节选，几段，按预算封顶
   │
   ▼
   写手提示词 = 后端固定六格（文风 / 禁用字 / 在场角色卡 / 最近事件 / 最近总结 / 正文）
              + 「要写什么」= brief
              + 新一格「助手补的资料」= materials
   │
   ▼
⑤ 稿子摆桌上，你挑、你存
```

## 分工

| | 谁做 | 说明 |
|---|---|---|
| 文风、检验规则里的禁用字 | 后端自动进写手提示词 | 今天就是这样，不动 |
| 在场人物角色卡、最近事件、最近几章总结、正文 | 后端自动 | 写手的「近处」，今天就是这样，不动 |
| 远处的章节、细节原文、跨章的线索 | **助手挑了喂**（`materials`） | 写手今天完全够不着的部分 |
| 检验规则 | **两条路**：助手在③里读它、据此定 brief；后端照旧把禁用字自动塞进写手提示词 | 两条读的是同一份数据（`validation_rule` 表），不会漂 |
| 你交代过的有时限的规矩 | **助手对照后写进 brief** | 今天它们只在助手眼前，写手看不见 |
| 事实矛盾（谁死了、谁在哪） | 助手查完写进 brief | **不补进写手的固定装配**（作者 2026-09-12 当场否了第一版里「在哪 / 已亡补进角色卡那一行」：「我之前就是特地把这个给砍掉」「有上下文就够了……如果用户在他的规则校验那边有写，那就我们也不用瞎操心」）。死人开口、人不在场这类事，作者要管就写进检验规则，引擎不替他操心——同 ADR 0042 那一刀 |

## 砍掉

- 工具：`calibrate_scene`、`seal_scene_brief`；`draft_chapter` 不再收 `calibration_id`。
- `calibration/` 整个包（校准 / 封存 / 渲染 / 可见性白名单 / 撤销交接）、`ToolContext` 上
  `calibrations` / `author_turn` 两个接线口、五个封闭指令码、风格码、`SceneBrief` 及它在写手
  提示词里的「本稿执行计划」分区（**「目标章当前正文」那一段保留**，它和校准无关）。
- 迁移 017 的两张表留着不删（迁移不回退），只是没有写入方了。

## 两条守着的线

1. **`materials` 有预算上限**：占写手窗口的一份，装不下从后往前砍，回执里说砍了几段。
   助手挑得再多也不能把写手撑爆——否则就是旧报告那种「装不下就整条清掉」换个地方再犯。
2. **作者看得见它喂了什么**：这一稿的 `brief` 和 `materials` 跟着稿子存进候选表，桌上那张卡
   能展开看「这一稿的要求 / 它补的资料」。挑错了作者才看得出来。

## 不变的边界

- 在场名单照旧从正文里数（ADR 0018），助手报不了。
- 写手固定装配那六格照旧由后端拼，助手一个字插不进去——它能给的只有「要写什么」和「补的资料」两格。
- 稿子照旧先摆桌上（ADR 0022），存进书是作者点的。

## 若此决策错误，修复成本是什么

**低。** 助手给写手的两格都是纯文本，进的是提示词里两个独立分区；收回 = 删那两个入参、
删那两个分区。候选表上多的两列是记录，留着不碍事。真正贵的那一档——「助手把不该进正文的
东西夹进 brief」——在秘密下线之后没有结构性的受害者，剩下的是文学判断，由作者在桌上那张卡
看着 brief 自己裁。
