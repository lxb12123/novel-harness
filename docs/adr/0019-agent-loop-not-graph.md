# ADR 0019：模式二走单 Agent 工具循环，工具表就是权限边界

- **状态**：已接受
- **日期**：2026-08-06
- **推翻了**：不是原始需求文档。推翻的是**桌面那份《Agent 编排架构：LangChain 与 LangGraph 整理》

- **相关**：[ADR 0005](0005-set-judgment-only.md)（只做集合判断）、
  [ADR 0007](0007-manuscript-lives-on-disk.md)（正文在磁盘）、
  [ADR 0010](0010-writer-boundary.md)（Writer 边界）、
  [ADR 0015](0015-inline-continuation-is-a-short-draft.md)（模式一，不适用本 ADR）、

- **决策日志**：`docs_dev/2026-08-06-模式二编排定为单agent工具循环.md`（记「当时怎么想」，非权威）

## 决策

模式二（agent harness）走**单 Agent 工具循环**，**循环归模型，不归代码**。
不引入 LangGraph，不引入 LangChain。

六条边界，本 ADR 的全部重量在这里：

1. **工具表就是权限边界。** 见 §边界一。
2. **`draft` 工具只接受章号，不接受约束。** 见 §边界二。
3. **对话进 SQLite，正文留磁盘。** 见 §边界三。
4. **总结不许含图谱事实。** 见 §边界四。
5. **上下文投影按章号参数化，不按时间近。** 见 §边界五。
6. **稳定前缀的判据是「跨章不变」。** 见 §边界六。

**模式一（行内续写，ADR 0015）不适用本 ADR**，它是单次调用加一个过期计数器，
刻意不编排——停手 400ms 就要出结果的交互里塞不下第二次往返。别把它拖进来。

## 为什么不是图编排

用那份文档自己的 §3.1 六问：

| 问题 | 本项目 | 指向 |
|---|---|---|
| 流程能否明确写死？ | 不能——模型自己决定叫哪个工具 | 要 agent |
| 需要循环返回前一步？ | 需要，**但循环在模型的 tool loop 内完成** | 不要状态图 |
| 中途失败必须继续？ | **必须**（维护者当天定的） | **不要图，但要持久化** |
| 需要等人工？ | 要作者确认写正文，是**一次同步确认** | 不要 interrupt/resume |
| 多角色要独立上下文？ | 不要，查约束/跑检查/读正文全是纯函数 | 保持单 Agent |
| 跨机器、超长任务？ | 单用户单机 | 不要分布式 |

> **补记（2026-08-23）：第五问的答案要补一格 —— 那个理由在「验证轨道」这件事上不成立。**
>
> 当年答「不要」，理由是**「查约束 / 跑检查 / 读正文全是纯函数」**。
> 两条都变了：
>
> 1. **验证轨道不是纯函数。** 「作者刚改的这一段跟后面第 64 章抵不抵触」要模型判语义
>    （规则够不着，ADR 0005），它是一次真的模型调用，不是一次查询。
> 2. **要独立上下文的原因不是「角色不同」，是「写的那个不能看见验的那个看见的东西」。**
>    ——**这一条当年没考虑过。** 后面章节的总结里可能写着这一章的读者还不该知道的事
>    （第 64 章：「萧决终于知道自己身上养的是玄血蛊。」）。把它给写第 2 章的模型看，
>    等于把伏笔亲手告诉它，而那正是铁律 5 的同一个失败从另一扇门进来。
>    **解法不是过滤，是分开：写的和验的不必是同一个上下文。**
>
> **这不是推翻本 ADR，是给那一行补一格。** 落地形态仍然守着上面的六条边界：
>
> - **模式二**：包成**一个工具**，不做成「写完必须验、验完必须改」的流水线——
>   边界一（工具表就是权限边界）在这儿是**字面成立**的：**那个工具有权看轨道，agent 没有。**
>   循环仍然归模型（**尚未落地**，那是轨道阶段 3）。
> - **模式一**：**不在续写那一次里验。** 本 ADR 开头那句「停手 400ms 就要出结果的
>   交互里塞不下第二次往返」仍然对，所以它落在正文之后的后台那一遍
>   （`advisory_review.py`，[ADR 0030](0030-versioned-summaries-and-advisory-reconciliation.md)
>   的窄例外：只写通知、不阻断、不改数据）。
> - **回给 Writer / 作者的评语形状限死**：只有「第几句 + 跟第几章 + 冲突类型」，
>   **没有自由文本的理由字段**。这不是措辞要求，是边界四那条论证的同一形态——
>   一个 `reason: str` 就是一条让轨道原文回流进 Writer 上下文的路。
>
> 不补这一格的话，下一个人读到上面那张表会以为「验证要独立上下文」这件事已经被否掉了。

第三问翻了之后，「不上 LangGraph」**更成立而不是更不成立**：

**LangGraph 的 Checkpoint 贵在图有东西要快照**——执行到哪个节点、条件边走了哪支、
并行 fan-out 谁完成了。**线性 tool loop 没有这些。** 它的执行态就是
「一串 message + 哪几个 `tool_call` 还缺 `tool_result`」。resume = 看尾巴、补跑缺的、继续。
用图运行时拿这个能力，90% 的机制是空转。

幂等也是白捡的：T1–T5 只读或纯函数，**重放免费**；唯一有副作用的写正文已经幂等——
`UNIQUE (chapter_id, text_sha256)`（`001_init.sql:328`）让同一段文本写两次不多出一行，
而且它本来就要作者确认，**那是天然的 checkpoint 边界**。

不引入 LangChain 的理由不同：它的三个卖点各自已经存在——统一模型接口是
`draft/provider.py`（OpenAI 兼容是作者的显式决定），工具定义是一个 `dict[str, Callable]`，
agent 循环约五十行。换来一棵依赖树，**进的是把「陌生机器 `uvx novel-harness` 能跑」
当 M0 验收的项目**。这跟 ADR 0001 / 0002 砍掉 Neo4j 和 Qdrant 是同一条理由，
不能对那两个成立、对它就不成立。

## 边界一：工具表就是权限边界

**这一节写错，产品核心主张当场破功。**

Claude Code 给模型 `Read` 是安全的。这里**给一个通用的「读图谱节点」工具就是泄漏**——
agent 一调就把 PLANNED 秘密的正文读进对话历史，而对话是持久化且会累积的，
之后每一轮起草它都在上下文里。原则 11 / 铁律 5 破功，**而且是我们自己递过去的**。

因此：

- **查约束的工具只返回转译后的结果**——`must_not_reveal` 的显示名（`NodeRef`）
  和 `forbidden_entities` 的首现章号。**永不返回 `Node`**（`NodeProps` 是 `extra="allow"`，
  作者写在秘密节点上的 `twist` 会原样穿过去，那是 `graph.models.NodeRef` 记录过的实测泄漏形态）。
  这条走 `panel/constraints.py` 那个既有闸门，**不另开路径**。
- **第 4 道 arch-guard 的 `WRITER_BANNED` 里的东西不进工具表**（`resolve_cast` 等）。
- **任何读工具都必须穿过 `StoryGraph`**，不许直连 SQLite——时态过滤全系统只实现一次
  （`graph/queries.py`，铁律 3）。
- ~~**写正文必须作者确认**，模型不能直接落盘。~~
  **2026-08-11 被 [ADR 0021](0021-agent-writes-drafts-without-asking.md) 推翻**：
  起草直接落盘（走 `PUT /chapters/{n}/text` 那条既有路径，磁盘先、DB 跟），
  退路是版本历史 + 日志页，**唯一的闸是「拒绝覆盖作者比它更晚改过的那一章」**。
  理由链同 ADR 0020。**本节其余三条原样有效。**
  范围限制：只对**已经存在的章**成立——新建一章要起章标题，而标题是切章的锚。

**运输层不认识工具表，也不许认识**（`draft/provider.py`）。它只负责把声明发出去、
把模型的请求原样带回来：不 `json.loads` 参数（「解析失败算什么」是编排层的判断），
不校验工具名在不在表里（认得它就等于有第二份工具表，两份迟早漂）。
**这道闸只许有一处。**

## 边界二：`draft` 工具只接受章号

约束是**逐章**算的，而对话**跨章累积**且现在还要持久化——一个会话能无限长、
能隔三个月回来。所以陈旧的约束会一直躺在 context 里，而方向是 fail-open 的最坏那侧：

```
ch40 的 must_not_reveal ⊇ ch90 的     ← 到第 90 章，更多人已经知道了
```

模型看着那份**更短**的清单去写第 40 章，就会以为「只有这两条不能说」。

**解法不是清理历史，是让历史进不了 prompt：**

> 起草工具只接受章号。约束由后端当场从 `scene_view(chapter)` 算，
> **模型没有机会把约束作为参数传进来。**

现有 `/draft` 已经是这个形状（客户端只发 `mode / goal / cast / length`），
新工具必须保持它。这跟铁律 5 同源：完整 PLANNED 只能由后端转译，模型碰不到原件，
自然也无法把过期的原件递回来。

**残余代价（接受）**：模型可能基于陈旧认知说出「这一章你可以说破 X」——推理被污染，
但写出来的正文受的是当前章的约束。那是「话说错了」，不是「稿子崩了」，而且作者看得见。

## 边界三：对话进 SQLite，正文留磁盘

会话持久化写进 `book.db`（ADR 0012：书自己带库）。但：

**写正文工具的产物是磁盘写，不是 checkpoint 写。**

没有持久化的时候这是个理论风险；现在要存对话了，它是真风险——
一旦模型的中间产物也进了会话表，「哪一份正文是真的」就有了第二个答案，
而 ADR 0007 的铁律是**正文的真相源在磁盘上，DB 永远不是**。

## 边界四：总结不许含图谱事实

滑动窗口丢掉的是原始 message，总结留下的是**一段自然语言**。差别是致命的：
原始的工具返回带工具名、带章号，**可定位、可过期**；压进散文之后
「萧决此时还不知道血脉秘密」——**「此时」是第几章？**

这跟 ADR 0017 拦 wiki 存事实是**同一条论证**：

> wiki 页面没有时态，也没有证据——它连章号的位置都没有。
> 一旦设定住进 wiki，「谁在第几章还不该知道什么」就有了两个答案，
> 而其中一个答不出「第几章」。

总结是同一种东西，只是它住在 context 里而不是磁盘上。所以：

| 总结**该**留 | 总结**禁止**含 |
|---|---|
| 作者的意图、被否决的方向 | `must_not_reveal` 的内容 |
| 现在在写第几章 | 谁知道 / 不知道什么 |
| 作者的文风偏好 | 任何绑定章号的状态、秘密名、未登场实体名 |

一句话：**图谱事实随时能重查，而且查回来的永远是当前的。**
把它压进总结 = 用一份会过期的自然语言副本，换掉一个永远新鲜的确定性查询。

## 边界五：上下文投影按章号参数化，不按时间近

对话历史是 **canonical**，永不破坏；模型看到的是它的一次**投影**。这是这个仓库同一个
思想的第四次应用（正文/DB → ADR 0007；区间/`CURRENT` → ARCHITECTURE §5；
事件/认知矩阵 → 边界四的同源论证）。

**通行的投影按「时间近」切**（stable prefix + compacted history + recent tail）。
**这里不够。** 作者会从第 90 章回头改第 40 章——那时「最近」是错的坐标：
对话的近端讲的是第 90 章，而给第 40 章起草的投影**必须是第 40 章视角的**。

> **投影函数必须带章号：`project(canonical, chapter) -> messages`。**
> 「最近」只决定**取多少**，「第几章」决定**取什么**。

边界二（起草工具只收章号）是这条的特例。反过来说：**任何按「最近 N 条」切出来的
上下文，只要里面含逐章变的事实，就是一个等着发生的跨章泄漏。**

### 附带两条

- **Recent Tail 必须逐字，不许摘要**（语言/动作/情绪的连续性只能靠原文）。
  但**产品的尾巴长度不许继承 kill-gate 的参数**：`assemble.py` 里那个 `[-800:]`
  是 X0 对照臂的定义（ARCHITECTURE §9：「X0 只给上一场景最多 800 个输入 code point」），
  它的存在是为了**证明给得少会崩**。产品继承它 = 产品用对照组的预算跑。
  **反过来也成立：改产品的尾巴不许改到三臂**——那是改考卷（EVAL_PROTOCOL §2 冻结）。
  正确形状是截断长度参数化，三臂用冻结的默认值。
- **压缩之前先剪枝，顺序写死**：老 `tool_result` → 老 `tool_call` → agent 中间推理
  → 最后才碰作者说的话。**正文永不压缩**（它在磁盘上，是产品本身）。
  第一条在这个项目里零损失且更优：**丢掉的工具返回重查一次就有，而且查回来的是当前的。**

## 边界六：稳定前缀的判据是「跨章不变」

**在别的项目里「稳定前缀」是性能优化；在这里它是泄漏面。**

一份被当作稳定前缀缓存起来的 `must_not_reveal`，就是一条被钉死在 context 里的过期约束——
而它过期的方向是 fail-open 的最坏那侧（到第 90 章更多人已经知道，清单更短）。

能进稳定前缀的只有三样：

| 能进 | 不能进 |
|---|---|
| 文风（`house_style`） | `must_not_reveal` / `forbidden_entities` |
| 工具表声明 | 认知矩阵、人物处境、关系阶段 |
| 人物的**静态**档案（性别 / 性格 / 背景） | 任何带章号的东西 |

判据只有一条：**这个东西换一章会不会变。** 会变就不许进。

顺带一个今天就存在的错误顺序：`product_assemble.py:94` 把记忆前言（逐章变）排在
文风（跨章不变）**前面**，于是唯一稳定的那块被夹在中间，前缀缓存价值为零。
正确顺序是 `[文风][记忆][用户]`——纯换顺序，`assemble()` 一个字不动，三臂不受影响。

## 什么条件下推翻本 ADR

满足**任意一条**才重新评估图编排：

- **出现真正的并行 fan-out**：多个子任务同时在飞、**且分支之间有依赖**
  （Planner 生成 5 个子任务，其中 3 个要等前 2 个的结果）。
  线性 loop 的「一串 message + 缺哪个 result」表示不了部分完成的依赖图——
  那才是 Checkpoint 真正在解决的问题。
  （**注意**：模型一轮发多个 `tool_call` 并发跑**不算**，那个仍然表示得了。）
- 工具表长到某个工具**必须有独立上下文**才不污染主对话——
  那时是 Supervisor / 子图的问题，不是持久化的问题。

原来还有一条「崩了几十轮白跑 ≥ 3 次」，**当天就作废了**：
维护者直接决定要执行 resume，而它不需要图。

## 若此决策错误，修复成本是什么

**中等偏低，但四条边界的成本不一样，别当成一件事：**

- **换掉编排形状**（真要上 LangGraph）：agent loop 是一个纯函数加一张工具表，
  重写它不动 `graph/` / `panel/` / `checks/` 任何一行。代价是 loop 本身 + 它的测试。
- **边界一写错**：**最贵，而且不可回收**——一旦某个工具把 `Node` 交出去过，
  那段秘密就已经在作者的持久化对话里了，改代码不会把它删掉。所以这一条必须**先有测试**：
  喂一个带 `twist` 的 Secret，断言工具返回和 prompt 里一个字都不出现它。
- **边界二写错**：改工具签名即可，历史不受影响（约束本来就没进 prompt）。
- **边界三写错**：会造出第二份正文。磁盘那份仍然是权威，清掉会话表里的即可。
- **边界四写错**：总结已经生成的那些含事实的散文要作废重生成——
  代价是作者的会话摘要丢一次，不影响任何 canon 数据。
- **边界五写错**（投影没带章号）：**和边界二同一个故障，但更隐蔽**——
  边界二堵的是「模型把过期约束当参数传回来」，这条堵的是「过期约束根本没离开过 context」。
  修复本身便宜（投影函数加参数），**但它错的时候不会报错**：产出的是一段读起来
  完全正常、只是说破了不该说破的东西的正文。所以它必须有测试：
  构造一个「先聊第 90 章再回头写第 40 章」的会话，断言第 40 章的投影里
  不含第 90 章的禁说清单。
- **边界六写错**：把逐章变的东西缓存进了稳定前缀。**症状同边界五**，
  且因为缓存的存在会更持久。清缓存 + 重排消息即可，不动数据。
  代价只是白付一次前缀 token。
