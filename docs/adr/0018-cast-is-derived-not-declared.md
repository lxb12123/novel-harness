# ADR 0018：在场是从正文推出来的，不是作者填的表单

- **状态**：已接受
- **日期**：2026-08-06
- **推翻了**：不是原始需求文档，是**本仓库自己**——顶栏「出场人物」输入框和章节准备页的「在场」框，
  以及它们背后那个「写之前先填清楚谁在场」的心智。
- **相关**：[ADR 0004](0004-declaration-over-extraction.md)（声明优于抽取）、
  [ADR 0005](0005-set-judgment-only.md)（只做集合判断）、
  [ADR 0015](0015-inline-continuation-is-a-short-draft.md)（D4：不知道谁在场就全禁）

## 决策

**面板的 `cast` 由引擎从本章正文里数出来，作者不再填。**

- 新增 `src/novel_harness/mentioned.py::mentioned_cast()`：角色册的全部可用称呼 → 正则
  alternation → 逐段命中 → 按首次出现顺序去重。**只收 `Character`**。
- `/matrix` `/constraints` `/state` 的 `?cast=` 变成**可选**：传了听作者的，空着就推。
- 新增 `GET /chapters/{n}/mentioned` 把推导结果交给界面显示，**三个既有端点的出参形状一个字节不动**
  （M2 判分链走的是 Python 里的 `scene_constraints`，不经过 HTTP，因此完全不受影响）。
- 顶栏和章节准备页的在场输入框**删除**。章节准备页从「写作前简报」改名「核对」。
- 场景块仍然压过推导——那是作者在正文里亲手标的，比数出来的可信。

## 为什么

### 1. 在场人物是写出来的**结果**，不是写之前的输入

这是作者（小说作者，不是维护者）给的论据，它成立：

- 没名字的配角（「那个卖伞的老头」）**永远进不了角色册**，作者填不出来；
- 新人物是写到那儿才需要的，写之前不知道自己会加谁；
- 情节驱动的写法里，谁在场是写着写着定下来的。

把它做成写作**前**的必填项，等于要求作者预先知道自己还没写出来的东西。
顶栏那个框是这个要求的最强版本——它是全局 chrome，是作者打开工作台第一眼看到的东西。

### 2. 「被提到」是集合判断，不是语义判断

`mentioned_cast` 不回答「谁在这一场里」。它回答：**角色册里的哪些称呼在这一章的正文里出现过**。
用的是 `text/mentions.py` 那条正则 alternation，和 R2 FUTURE_LEAK 同一份实现。
一个语义判断都没有，ADR 0005 的铁律没有被碰。

歧义称呼（「师兄」→ 8 个人）由 `rules_only=True` 天然出局——系统不猜（ADR 0004）。

> **补记（2026-08-22）：上面那句话现在只描述默认档。**
> `mentioned_cast` 多了一个 `expand_ambiguous`，**模式二的起草约束这一条路传 `True`**：
> 「师兄」命中时把 8 个候选**全部**算进 cast。**这仍然不是猜**——猜是从 8 个里挑 1 个，
> 这是 8 个都算，而判据「在场至少有一个人还不知道」下多算只会多禁。
> 改它的理由是原来那半句的落点：歧义出局在 cast 因此变空时才是 fail-closed，
> 还有别人在场时丢掉那一个人就是下面 §3 那条 fail-open（这个仓库修过的真 bug 的同一形态）；
> 而它变空时的「多禁」形态是**整章全书全禁**——安全，却安全得没用。
> **面板那三个端点仍走默认档 `False`**，`panel/constraints.py::resolve_cast` 也**不**展开
> （歧义照旧进 `unresolved`）——**这个不对称是 2026-08-22 裁定的，不是没接完**：
> 那一侧的出参是给模型的保险（宁可多禁），右栏的出参要渲染给作者看（8 行没有解释的人
> 是噪声，且犯「引擎的机制不上作者的屏」）。两边的注释里都写了「别修统一」。
> 本 ADR 的决策一个字没动。

### 3. 推不准的时候，错在**安全**那一侧

这是整件事成立的支点，**方向搞反就是泄漏**：

```
SceneConstraints.must_not_reveal 的判据 =
    「在场的人里**至少有一个**还不知道（或持错误认知）」
```

- cast **多**算一个人 → must_not_reveal **多**一条 → fail-closed，代价是**少写一段**
- cast **少**算一个人 → must_not_reveal **少**一条 → fail-open，代价是**崩人设**

而「被提到的人」是「真正在场的人」的**超集**——回忆里的死人、被议论的第三方、信里写到的
名字都会进来。**超集恰好落在多算那一侧。**

`panel/constraints.scene_constraints` 的 docstring 里那段「李管家静默地从 cast 里消失，
血脉秘密从 must_not_reveal 里消失」记的就是后一种，它是这个仓库修过的真 bug。
本 ADR 的推导只可能往前一种方向错。

### 4. 它天然把 cast 推到「写完之后」

推导要读正文。**章还没写就推不出东西**——所以这条改动在结构上就做不到「写之前先算好在场」。
这正是想要的：cast 从写作前的表单，变成写完回头核对时的一个产物。

起草侧（整章起草 / 行内续写）不受影响，它们照旧走 ADR 0015 的路：没有 cast 就全禁。

## 界面上不许说「在场」

**推导结果的措辞是「这一章提到：…」。**

引擎在数字符串，它没有读懂剧情。说「在场：萧决、顾清音」是在向作者承诺一件系统做不到的事——
作者会以为系统确认过他们在同一个屋子里。说「提到」则把不确定性交回给作者，他自己一眼就能判断
这是不是他要的那几个人。

工程上多算是安全的，**但那不代表可以在界面上把它说成另一件事**。
`RightPanel.test.tsx` 有一条断言钉住界面文案里不出现「在场」。

## 如果这个决策是错的

**症状**：作者发现面板算的人不对——比如某一章大段回忆，死者被反复提到，矩阵里多出好几行他
根本没在写的人；或者对白密集但全靠代词，真正在场的人一个都没被点名，矩阵是空的。

**修复成本：低。** 三处，都是加东西不是拆东西：

1. **推导本身**可以收紧到高信号位置（只认说话人标签「萧决道：」），代价是召回更低——
   而低召回落在多禁那一侧，仍然安全。ADR 0014 实测显式标签覆盖率只有 8.2%，所以这条是
   「更保守」不是「更准」。
2. **手填框**可以加回来，但**加在右栏那几格里**，不加回顶栏——顶栏那个位置本身就是错的。
3. **场景块**这条路一直开着且优先级最高，作者随时可以在正文里显式标注。

数据层零风险：这条决策不写任何东西进库，`valid_from` 不受影响，约束 10（作者永不填章号）
也不受影响。推错了只是面板显示得不好，改一个纯函数就回来了。

## 补记（2026-08-25）：§3 那条单调性证明**失去了它的对象**

维护者裁定秘密整套功能下线（[ADR 0039](0039-secrets-offline.md)）。**正文一个字未改**，
下面是这个决定对本 ADR 论证的影响。

### 塌掉的是哪一句

§3「推不准的时候，错在**安全**那一侧」是整件事的支点，原话：

```
SceneConstraints.must_not_reveal 的判据 = 「在场的人里至少有一个还不知道」
- cast 多算一个人 → must_not_reveal 多一条 → fail-closed，代价是少写一段
- cast 少算一个人 → must_not_reveal 少一条 → fail-open，代价是崩人设
```

**`must_not_reveal` 今天不存在**，`SceneConstraints` 只剩 `forbidden_entities`，
而它**按章号算、与 cast 无关**。于是：

- 多算一个人 **不再多禁任何东西**；
- 少算一个人 **不再少禁任何东西**。

**这条不对称整个消失了。** 不是变弱，是两侧都不再落在「安全」这个轴上。

### cast 今天还有什么去处

两个，都还活着：

1. **Writer prompt 的【在场】那一块**（`draft/assemble.py`）——多算 = 对模型说「这一场
   有这个人」，而那句话是假的；少算 = 漏掉一个真在场的人。**两侧都是错，只是错法不同。**
2. **右栏「这一章提到」**（给作者看的）——本 ADR「界面上不许说『在场』」那一节
   **一个字都没受影响**：引擎在数字符串、没有读懂剧情，这件事跟秘密无关。

### 决策不动，但两处依赖它的判断现在悬着

**§1（在场是写出来的结果，不是写之前的输入）、§2（集合判断不是语义判断）、§4
（推导天然把 cast 推到写完之后）、以及界面措辞那一节 —— 全部不受影响，决策本身不动。**

但下面两处当年是**引用 §3 来正当化的**，它们的行为**没有跟着改**（改它们是维护者的裁定）：

- **`mentioned_cast(expand_ambiguous=True)`**（2026-08-22，模式二起草这一路）：
  「师兄」指向 8 个人时 8 个全算，理由写的是「多算只会多一批禁令」。
  今天那个理由不成立，行为原样留着，`agent/tools.py::_derived_cast_from_text`
  的 docstring 里已经把这件事写明。
- **面板侧不展开、起草侧展开这个不对称**（同一天裁定）：它另一半理由是
  「右栏出参要渲染给作者看，8 行没有解释的人是噪声」——**那一半仍然成立**，
  所以这个不对称今天靠单腿站着。

**要动之前先回答**：一个指向 8 个人的称呼，是 8 个全报（模型可能把 7 个不在场的人
写进去）、还是整个丢掉（真正在场的那个人从名单里消失）？今天没有哪一侧是「安全」那一侧。
