# ADR 0015：行内续写是起草路径的一个短档，不是第二条路

- 状态：**已接受**（2026-08-06 维护者裁定）
- 日期：2026-08-05
- 解决的问题：作者要「像 VS Code 那样，停手一下就提示接下来一两段」。这是新能力，
  但它是**新端点、新模块，还是现有 `/draft` 的一组参数**？没定之前动手，大概率长出第二条
  绕过 `ResolvedConstraints` 的生成路径。

## 决策

**行内续写复用 `POST /chapters/{n}/draft`，不新建端点、不新建模块。** 它与整章起草的差别
只有两处：`LengthSpec` 小一档、`previous_tail` 是作者光标前的正文。

五条裁定：

### D1 长度靠 `LengthSpec`，不引入第二个长度概念（ADR 0013 已铺好）

`LengthSpec` 的下限是 `Field(ge=1)`，唯一不可协商的是硬上限。一两段（约 80–300 字）
是合法取值，**后端一个字都不用改**。

M2 的 kill-gate 走冻结的 `M2_LENGTH_SPEC`，不读作者设置也不读环境变量（ADR 0011 D1），
**所以续写档动不到考卷**。

### D2 `previous_tail` = 作者光标前的正文（`assemble()` 已有此参数）

`assemble(..., previous_tail: str = "")` 的契约是「上文。空串 = 开篇」。整章起草传的是
上一章的尾巴；续写传的是作者此刻正在写的这一段之前的字。**同一个参数，不同的喂法。**

### D3 `goal` 在续写模式下由**后端**填一句固定文本，前端不许传自由文本

`DraftRequest.goal` 今天是 `Field(min_length=1)`。续写场景里作者根本没有「本场目标」
要表达——他表达的就是已经写下的那些字（走 D2）。

**这一条是在缩小 ADR 0010 的洞，不是扩大它。** `goal` 是那份 ADR 点名的三个自由文本入口
之一：作者可以把伏笔用自然语言写进去，而本仓库禁止长出判断「这句话是不是说破了」的能力
（ADR 0005）。续写模式把这个入口**关掉**，换成后端的一句常量，等于少一个泄漏面。

> 实现约束：常量在后端，不是前端传一个「默认 goal」——前端能传的东西作者就能改。

### D4 续写**不要求** `cast`：不知道谁在场时走「全禁」退化态

**空 cast 的语义是「不知道在场是谁」，答案是 `must_not_reveal` 取全部秘密。**
不是「不给续写」。

这不是新发明的语义。`scene_constraints()` 的第一行 docstring 就是**「算不准就多禁」**，
`ResolvedConstraints` 自己把这个状态命名为「fail-closed 的退化值」，而读端
（矩阵 / 约束 / state）今天已经在返它了（空 cast → 退化 + `unresolved_cast` 横幅，返 200）。
**缺的只是 `assemble()` 今天只收非退化的那一种。**

要加的是**一个显式的退化型**，不是把 `ResolvedConstraints.cast` 的 `min_length=1` 放宽：

- 放宽 `min_length` = 把那个类型携带的证明作废。它存在的**全部意义**就是
  「must_not_reveal 是算出来的答案，不是退化值」——一旦空 cast 能穿过去，
  `panel/constraints.py` 记的那次病史（人静默消失 → 秘密从清单里消失 → fail-open）
  立刻能重演，而且没有任何东西会红。
- 加显式类型 = `assemble()` **知道自己拿的是哪一种**，渲染成
  「在场：未知。本章不得说破任何尚未公开的秘密」，而不是伪装成一份精确清单。

**方向是 fail-closed**：错的方向是「续写太保守，该能写的没写」，不是「说漏嘴」。
作者填了 cast（或点一下场景块自动填）→ 约束收紧到精确值，续写更自由。**填 cast 变成
一个「让它写得更准」的奖励，而不是「不填就不给用」的门槛。**

### D6 **不做「AI 推衍在场人物」**

从上文推断「这一场谁在」是**语义判断**，ADR 0005 在 v1 里禁止本仓库长出这种能力。

但更要命的是**方向**：推衍漏掉一个在场的人 → 他不该知道的秘密不进 `must_not_reveal`
→ Writer 拿到「无需保密」→ **fail-open，错误指向泄漏**。而全禁不需要推衍就直接得到
安全答案。

**无名配角这一条正好说明全禁为什么更优。** 「掌柜的」「一个小厮」「路人甲」永远不会
进花名册，也不需要进——**全禁模式下不管谁在场，答案都一样**。推衍则必须回答
「掌柜的算不算在场」这个没有正确答案的问题；全禁不用问。

### D5 续写的产出永远不是 canon（继承 ADR 0010 D1）

它落进编辑器缓冲区；作者接受了才是磁盘上的字；要进图仍然只有 `declare.py` 一条路。
**「作者按了 Tab」不等于「作者确认了一条事实」。**

## 论证

**为什么不新建端点。** 新端点意味着第二次装配上下文的机会，而 `assemble()` 是 `draft/`
唯一的 prompt 出口（ADR 0010）。第二个出口 = 第二处可能漏掉 `must_not_reveal` 的地方，
且那类 bug 没有任何症状（生成出来的文字看起来完全正常）。

**为什么这件事比看起来便宜。** 端点、`previous_tail`、随请求给的长度三样都已经在了。
真正的工作量在 CodeMirror 6 的 ghost text（内联渲染 / Tab 接受 / Esc 拒绝 / 不与
`highlight` 跳转打架），那是前端活，不碰引擎。

**作者担心的「推理赶不上删改」在这儿不成立。** 那是**验证**的难题（改了第 3 段，第 40 段
的结论还算不算数 —— 要增量失效）。续写只需要**取消**：停手 400ms 发一次，一敲键就丢掉
在飞的那次，过期结果直接扔。没有状态要维护。

**为什么减少 cast 依赖是对的（这条推翻了本文档的第一版 D4）。** 在场人物在写作过程中
是**结果不是前提**：它由上文决定、由剧情推进决定，新角色是被这一段写出来的，而无名配角
根本没有身份可填。要求作者在写之前先声明在场是谁，等于要求他先知道自己要写什么——
那正是这个产品说要替他记住的东西，不该反过来问他。

## 这条 ADR 不守什么（诚实交代）

- **它继承 ADR 0010 的每一个洞**，包括第 4 道守卫明说拦不住的那格。尤其：`previous_tail`
  现在是**作者正在写的正文**，作者自己在正文里写下的伏笔会原样进 prompt。
  **但那是作者自己的字，不是引擎替他泄漏的**——两者的责任归属不同，别混。
- **起草线仍是实验状态**（修正案 7）。续写是它的延伸，**继承那个标注**：响应带
  `experimental`，不声称图谱约束已被证明有效（ADR 0009 是维护者裁定，非数据裁决）。
- **D3 的常量能不能守住，只有 review 拦得住。** 有人把 `goal` 重新开成自由文本入口时，
  类型系统和守卫都不会红。
- **全禁是有代价的，而且随书变长而变贵**：每次续写的 prompt 都带着全书秘密名单
  （只有名字，`NodeRef` 无 props，不会连内容一起泄——但条数会涨）。722 章的书秘密攒多了
  会占 token。**这是接受的代价，不是没看见**：可选的收窄是只带「本章之前已声明的」，
  但那是实现时的优化，不改本 ADR 的裁定。
- **D4 让「不填 cast」变成常态之后，`unresolved_cast` 那条横幅在续写路径上没有位置。**
  作者写错一个称呼（打错字、用了没登记的别名）时，续写不会提醒他——它只会更保守。
  **说漏嘴的风险没了，说错人的风险还在**，那由别的地方管（花名册、`resolve`）。

## 若此决策错误，修复成本是什么

**低。** 它是同一条路由的一组参数：没有新表、没有新端点、没有新数据格式。
撤掉 = 前端不再发那种形状的请求，后端把 D3 的常量删掉。已生成的续写不在库里
（D5：它只到过编辑器缓冲区）。

**触发回滚的条件**：若续写为了「更懂上下文」开始要求 `assemble()` 之外的额外输入
（例如直接读图、直接读快照），说明它正在长成第二条生成路径——那时应当先补 ADR，
而不是继续在 `/draft` 上挂参数。
