# ADR 0021：起草直接落盘，退路是版本历史；不问「可以吗」，但绝不盖掉作者更晚的改动

- **状态**：已接受
- **日期**：2026-08-11
- **推翻了**：不是原始需求文档，是**本仓库自己**——
  [ADR 0019](0019-agent-loop-not-graph.md) 边界一的最后一句
  「**写正文必须作者确认，模型不能直接落盘**」。同节的其余三条**原样保留**。
- **相关**：[ADR 0007](0007-manuscript-lives-on-disk.md)（正文真相源在磁盘）、
  [ADR 0019](0019-agent-loop-not-graph.md)（模式二六条边界）、
  **[ADR 0020](0020-clean-extraction-auto-canon.md)（同一条理由链的上一次应用）**
- **决策日志**：`docs_dev/2026-08-10-模式二与事后可查可改的进度板.md`（记「当时怎么想」，非权威）

## 决策

**agent 起草完直接写进磁盘，不弹框问作者。** 每次落盘产生一份内容寻址快照，
作者在版本历史里看得见、回退得掉，日志页有一行 `actor='system'`。

**只留一道闸，而且它不是「问你可不可以」：**

> **它拒绝覆盖作者比它更晚改过的那一章。**

agent 起草时记下所依据的那份正文的 `text_sha256`；落盘前比对磁盘当前值，
不一致就**停下来说出来**，不写。形状同 `expected_canon_version` 那套乐观闸
（`corrections.py` / `review.py` 的 409），不是新机制。

**边界一的其余三条不动**：查约束的工具只返回转译后的结果、`WRITER_BANNED`
不进工具表、任何读工具都必须穿过 `StoryGraph`。

## 为什么

### 1. 这是 ADR 0020 的同一条理由链，换了个对象

2026-08-10 作者推翻了「事前逐条确认」，原话是「**无需留人工可以留记录**」。
ADR 0020 把它落成了工程约束：**不挡，但每步留痕，错了看得见、跳得过去、改得掉。**

| 怕什么 | 事前确认 | 本 ADR |
|---|---|---|
| 作者没同意 | 挡住 | **不挡**（承认这是代价） |
| 发现不了 | 挡住 | 版本历史 + 日志页一行 |
| 改不掉 | 挡住 | 回退到上一份快照 |

**「一稿写完弹个框问你要不要」在真实写作里是纯摩擦**：作者本来就要读那一稿再改，
而弹框逼他在**读之前**先做一次判断。

### 2. 三样退路今天全是现成的，不是这条 ADR 许诺的未来

- **内容寻址快照**：`chapter_snapshot` 的 `UNIQUE (chapter_id, text_sha256)`
  （`001_init.sql`）——同一段文本写两次不多出一行，落盘天然幂等。
  ADR 0019 自己引用过它，管它叫「天然的 checkpoint 边界」。
- **版本历史**：`GET /chapters/{n}/history` + 前端 `HistoryDrawer` 已经在了。
- **日志页**：ADR 0020 落地的 `GET /activity`，`actor` 分得开系统和作者。

### 3. 保存路径本来就是「磁盘先、DB 跟」

`PUT /chapters/{n}/text` 的原文注释：「先写磁盘（文件是作者的），再 `importer.sync` 落快照」。
**agent 走的是同一条路，不另开**——一个功能不留两个入口，也不给「哪份正文是真的」
第二个答案（ADR 0007）。

## 范围：只对已经存在的章成立

`PUT /chapters/{n}/text` 在文件不存在时是 404，而**这条 404 不许为 agent 放开**：

- **新建一章是作者的动作**——他要起章标题，而标题是切章的锚（`importer` 按
  「首个非空行」认标题，切错了整本书的章号会漂）。
- 一稿「第 8 章」在只有 7 章的书里没有落点：`chapter_snapshot.chapter_id`
  外键指向 `chapter`，而 `chapter` 行只在磁盘上有文件、跑过 import 之后才存在。

所以 agent 给一本 7 章的书起第 8 章的草时，**它交出文本、说清楚「这一章还不存在」，
由作者建**。这不是「等人确认」，是「这件事本来就不是它的活」。

## 代价（承认，不粉饰）

- **作者可能一直不看版本历史。** 那时错误会静默累积。这跟 ADR 0020 是同一个赌注：
  赌「错了能退」比「错了先拦住」更符合一个每天写 5000 字的人的实际工作方式。
- **快照会长得快。** 每一次 agent 起草都是一份。内容寻址让重复的那些不占行，
  但不同的每一稿都占。**版本历史要能按 `actor` 过滤**，否则作者自己存的那几版
  会被淹在几十版机器稿里——同 ADR 0020 对 `decision_log` 说过的那条。
- **那道 sha 闸只挡「同一章的并发」，挡不住「agent 写了一稿、作者没看见就接着写」。**
  后者的表现是作者在编辑器里看见一段自己没写的字。这条只能靠界面提示，不能靠闸。

## 什么条件下推翻本 ADR

满足**任意一条**就退回「落盘前问一次」：

- **真书上实测：agent 落盘的稿子里，作者事后回退掉的比例超过某个阈值。**
  阈值今天定不了——**没有真书数据之前不许在这儿编一个数字**（同 EVAL_PROTOCOL 的规矩）。
- **出现「退不回去」的形态**：某一次落盘之后版本历史里找不回上一版。
  那时先修版本历史，修不了才退回确认。

## 若此决策错误，修复成本是什么

**低。** 落盘前加一次确认是一个开关；已经落盘的那些稿子留在版本历史里，
本来就是可回退的。

**但有一条不对称**：如果 sha 闸写错（该拒的没拒），**作者的字会被盖掉，
而快照里只有盖之后那一份的记录**——被盖掉的那一版如果从没被 `sync` 过就是真没了。
所以那道闸必须先有测试：构造「agent 拿着旧底稿、作者刚改过」的局面，
断言它**不写**、且说得出为什么。
