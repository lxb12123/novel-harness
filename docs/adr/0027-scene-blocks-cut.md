# ADR 0027：场景块和 R4 一起砍掉 —— 一条零误报的规则，在真书上一次都没开过火

- **状态**：已接受
- **日期**：2026-08-14
- **推翻了**：不是原始需求文档，是**本仓库自己**——PLAN §5「改 3」那行 Markdown 注释
  （`## 场景 N` + `<!-- nh: cast=… loc=… goal=… -->`）、`text/scenes.py`、
  `checks/location_conflict.py`（R4）、两条 HTTP 路由、中栏的场景条、底栏的「场景顺序」列，
  以及它们背后那个「写之前先把这一场标清楚」的心智。
- **相关**：[ADR 0005](0005-set-judgment-only.md)（规则只做集合判断，那张表把 R4 排在最上面）、
  [ADR 0014](0014-r5-cut-by-quote-coverage.md)（R5 死于同一个判据）、
  [ADR 0018](0018-cast-is-derived-not-declared.md)（在场是推出来的，不是填的）、
  [ADR 0028](0028-rules-expire-by-situation.md)（同日的另一刀，同一条起因）

## 决策

**场景块这套标记语法整个删掉，连同它唯一的消费者 R4。**

删掉的东西：

| 层 | 东西 |
|---|---|
| 规则 | `checks/location_conflict.py`（R4 `LOCATION_CONFLICT`）；`ALL_CHECKS` 从 3 条变 2 条 |
| 文本 | `text/scenes.py`（`parse_scenes` / `write_scene_directive` 和它那 5 个异常） |
| 契约 | `checks.base.Scene`、`CheckContext.scenes` |
| HTTP | `GET`/`PUT …/chapters/{n}/scenes`；`POST …/check` 出参里的 `scene_count` |
| 界面 | `SceneBar.tsx`（中栏那条场景条）、底栏「场景顺序」那一列、`useScenes` / `useWriteScene` |

**没删的**：`panel/constraints.scene_constraints` 和 `SceneView`。名字里有「scene」，
但它们收的是**一份称呼清单**（`cast`），跟这套标记语法没有任何关系——它是
`must_not_reveal` 那条链的入口，M2 判分链走的就是它。

## 为什么

### 1. 判据只有一条：**真书上零覆盖**

场景块要作者在正文里亲手写下两行：

```markdown
## 场景 3
<!-- nh: cast=萧决,顾清音 loc=青云城主府 goal=李管家试探萧决的身世 -->
```

R4 拿其中的 `loc=` 去比对图上的 `LOCATED_AT` 边——**两侧都是作者自己敲进去的字**，
所以它零误报。而作者（小说作者，不是维护者）导进来的那本 722 章的书里，
**这样的块一个都没有，以后也不会有**：他不会去学一套 HTML 注释语法。

于是 R4 在产品里的实际行为是：`ctx.scenes` 恒为空元组 → 循环一次都不进 → 恒返回 `[]`。
**「零误报」在一条永远跑不起来的规则上是免费的。**

这和 [ADR 0014](0014-r5-cut-by-quote-coverage.md) 砍掉 R5 是同一个判据，只是数字更极端：
R5 的显式说话人标签在真书样本里覆盖 8.2%（门槛 10%），场景块是 **0%**。

> ⚠️ **两条规则死于同一个判据，这不是巧合。** ADR 0005 那张表按「输入从哪儿来」排规则，
> 排在最上面那几条（不读正文、零 FP）之所以便宜，是因为**它们把成本转嫁给了作者**。
> 下一次往那张表上加规则时，先问一句：**这条规则的输入，作者真的会去填吗？**

### 2. 它已经被 ADR 0018 掏空了一半

场景块原本有两个身份：**R4 的输入**，和**面板「在场是谁」的来源**。
2026-08-06 的 ADR 0018 把后一个换掉了——在场由 `mentioned.py` 从本章正文里数出来，
场景块降级成「作者手标了就压过推算」。而他一次都没标过。

剩下那半个身份（R4 的输入）由上一节判掉，于是它一个身份都不剩。

### 3. 屏幕上那句话是常驻的，不是空态

作者的原话（2026-08-14，看着工作台）：**「为什么会有场景信息」**。

他看到的是中栏正文上方一行斜体字：

> 这一章还没有场景信息。你可以先继续写正文。

三处不对，而且是叠着的：

1. **「场景信息」是引擎内部的名字**，他从来没要过这个东西；
2. **它在他的书上永远为真**，所以那不是空态，是**常驻文案**；
3. **它带着「你有件事没做」的口气**（「你可以先*继续*写正文」＝正事还没干），
   而那件「正事」在 ADR 0018 之后已经不是作者的活了。

同样的话还躺在底栏（「第 N 章还没有场景信息」）和右栏检查面板里。
**检查面板那一句还是假的**：它写着「暂时无法进行内容检查」，而 R2/R3 从 2026-08-02
起就不读场景块，零场景块照样跑了两条规则。那句话说谎说了 12 天——和 `demo.sh`
那次是同一天、同一个原因断的，只是这一处没有任何东西在验它。

## 代价

- **「同一场里地点对不上」这类问题今天没人查了。** 这是真的损失，但它损失的是一个
  **从未交付过的**能力：真书上它一次都没查过。
- **`FIRE_SCOPE` 失去了显式调用方**（R4 是唯一那个）。常量留着，docstring 里写清了
  它今天靠 `state_at` 的默认值成立——那个「恰好」是这条铁律现在唯一的实现。
- **`tests/test_store_conformance.py` 的第 6 节换了主角**（R4 → R3）。
  **换而不是删**：那一节是唯一把 `test_checks.py` 里那个 `RulesFakeGraph` 钉在生产
  `state_at` 上的地方，整节删掉的话那个 Fake 从此可以单方面漂移，而所有测试一路绿。

## 什么时候该重新考虑

**不是「等作者愿意标场景」——那一天不会来。**

真正的触发条件是：**抽取器开始产出「这一章分了几场 / 每场在哪儿 / 谁在」。**
它今天已经在写 `LOCATED_AT` 了（`extract/ingest_helpers.py`，干净的自动升 CANON，
ADR 0020），多写一层是同类的活。那时「每场在哪儿」是**模型生成、作者可改**的东西，
正好落在作者 2026-08-14 定的那条验收口径上——而**那时该长出来的是一条新规则，
不是把这套要作者手写的标记语法接回来**。
