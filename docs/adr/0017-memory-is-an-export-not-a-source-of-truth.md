# ADR 0017：小说记忆是导出物，图才是真相源

- 状态：**已接受**（2026-08-06 维护者裁定）
- 日期：2026-08-05
- 解决的问题：agent 模式下作者要一份「这本小说的记忆」——按几章一段的总结、可以翻、
  可以 grep。以 md wiki 的形式放进书文件夹是合理的，**但它一旦能存事实，这个项目
  唯一的卖点就废了**。这份 ADR 定的是那条界。

## 决策

**章摘要 / agent 笔记以 md 导出到书文件夹**（作者能用 Obsidian 打开、能随文件夹搬家、
agent 能 `read`/`glob`/`grep`）。

**但：SQLite 仍是权威，导出物随时可整份重建；作者声明的事实必须走 `declare.py` 进图。**

| 内容 | 归谁 | 丢了会怎样 |
|---|---|---|
| 章摘要、agent 笔记、派生索引 | **md 导出物** | 重跑一次，付一次模型钱 |
| 谁知道什么 / 谁在哪 / 从第几章起 | **图**（`declare.py` → `valid_from` 由引语算出） | **不可重建**——那是作者的意图，不在任何已写文本里（ADR 0004） |

## 论证

### 为什么要导出成 md

- **合 ADR 0007 的精神**：稿子在磁盘、作者自己管文件。记忆跟着书文件夹搬家。
- **agent 模式下 md 目录是天然的工具面**：`read` / `glob` / `grep` 就能翻，不需要 embedding，
  不需要新服务。
- **作者看得见**。SQLite 里的摘要他打不开；md 他能读、能判断这份记忆对不对。

### 为什么 SQLite 仍是权威

`chapter_summary` 的 `UNIQUE (project_id, chapter_number, schema_version, prompt_hash)`
是**内容寻址去重**——同一章同一 prompt **只付一次调用**（`draft/rolling_summary.py` 的
设计目的）。md 文件握不住这把钥匙。丢掉它 = 每次重跑都重新付费，而这本书有 722 章。

### 为什么 wiki 不能存事实（最要紧的一条）

图里的每条事实带 `valid_from` + 证据锚，而那个章号**是由引语算出来的，不是谁填的**
（ADR 0006 / 约束 6：作者永远不填章号，表单里有章号输入框 = 邀请污染）。

**wiki 页面没有时态，也没有证据——它连章号的位置都没有。**

一旦设定住进 wiki，「谁在第几章还不该知道什么」就有了两个答案，而其中一个**答不出
「第几章」**。那正好是这个项目唯一没有别人做过的东西（ARCHITECTURE §1–2）。
这比约束 6 拦的那种污染更糟：约束 6 拦的是填错的章号，这里是根本没有章号。

### 顺带纠正一个前提

提出这件事时的理由是「本地可能不具备向量切块查询条件，所以只能用 md wiki」。
**这个前提不成立。**

[ADR 0002](0002-no-vector-retrieval-in-v1.md) 不是说本地做不了，是**有意推迟，且 v1.1 的
选型已经定死**：`fastembed`（ONNX，不拉 torch）+ `BAAI/bge-small-zh-v1.5`（512 维，90MB）
+ `sqlite-vec`，无 Docker、无 torch、约 100MB 一次性下载。

所以 **md wiki 是和向量并列的选择，不是它的替代品**，两者可以同时存在：md 给作者和
agent 读，向量（v1.1，分区 G）给历史证据检索。**本 ADR 不解冻 ADR 0002**，只是不让
「本地做不了向量」这句错话变成 md wiki 的论据——用错的理由做对的事，下次会用同一个
错理由做错的事。

## 这条 ADR 不守什么（诚实交代）

- **没有任何机制阻止作者往导出目录里写自己的东西**，而下次重建会覆盖掉。缓解只有两条，
  都是纪律不是保证：
  1. 每份导出文件头印一句「本文件由系统生成，重建时会被整份覆盖」；
  2. 目录名要让人一眼看出是生成物（例如 `记忆-自动生成/`，不要叫 `wiki/` 或 `笔记/`）。
- **它不阻止 agent 把结论写进 md 然后当事实用。** agent 读自己写的笔记，笔记里有一句
  「李管家知道血脉秘密」——引擎无从判断那句话有没有出处。**边界只在「什么能进图」上是
  硬的**（ADR 0010 D1 + `declare.py`），在「prompt 里能出现什么」上是软的。
- **摘要本身就不是事实，这一点已经是既有约定**：`rolling_summary` 的模块 docstring 写着
  「摘要不是作者确认的事实（不进 `decision_log`），进写作 prompt 时明确标注
  『机器摘要，仅背景』」。本 ADR 是把那条约定扩展到导出物，不是新发明。

## 若此决策错误，修复成本是什么

**低。** 导出是纯加法：SQLite 里的东西一个字不动，撤掉 = 不再写那个目录。

**触发回滚的条件**：

1. **实测有作者在导出目录里写原创内容并因覆盖而丢失** —— 说明这个形状错了。
   那时的加法路径是给一个**不被覆盖**的 `notes/` 目录（作者的，系统只读不写），
   而不是让导出物变成可编辑的真相源。
2. 有人提出「让 wiki 里的某类内容反向进图」—— 那等于给 `valid_from` 开一条不经引语的
   来源，**应当先推翻 ADR 0006 和约束 6**，而不是在本 ADR 上加例外。
