# ADR 0049：改一段 —— 助手说改哪儿、怎么改，写手只写那一段，后端拼回整章

- **状态**：已接受（2026-09-12，维护者提出）
- **日期**：2026-09-12
- **推翻了**：不是原始需求文档，是**本仓库自己**——
  [ADR 0048](0048-drafting-writes-the-chapter.md) 里「没做的（有意）」那一条（「改一两句的工具，另开一刀」），
  以及同一天晚上先做的那一版（`draft_chapter` 上一位 `intent: rewrite | revise`，见「同日改动记录」）。
- **相关**：[ADR 0047](0047-drafting-is-assistant-curated-not-calibrated.md)（助手给写手的是
  「要写什么」和「补的资料」，不是正文——本 ADR 沿用）、[ADR 0019](0019-agent-loop-not-graph.md)
  （边界一：工具表里没有一条工具收助手写的正文——本 ADR 沿用）、
  [ADR 0006](0006-anchor-no-offset.md)（锚是引语，禁 offset——本 ADR 沿用）

## 维护者的原话

看着第 158 章连开五稿、写手五次抄回同一篇之后（[ADR 0048](0048-drafting-writes-the-chapter.md)
同日改动记录第 4 条），我把写手 prompt 里那一段写死成「这一次是重写」：

> 问题是也不一定，每次都是说要重新写……有些时候可能就是让他去改这篇里面的语句。
> 那我这次是有明显的明确的目的，说他是重新写这章能理解吗？就是你这样子是直接写死了。

换成 `draft_chapter` 上一位 `intent`（重写 / 修改）之后：

> 这明显不是一个好的解决方法，你需要和我讨论一下。目的是什么？什么东西卡住，然后怎么解决？
> ……是的，这个就应该让写手来，然后方向还有目的就应该让助手来。

## 目的

作者说「第三段太硬了，改软一点」，助手应该：**只改那一段**；花那一段的钱和时间；改完
作者在左边看到就那一段红一段绿，按保存才算数。「整章重写」仍然可以，但那是另一个动作。

## 卡住的地方

1. **助手只有一把锤子。** 它手上唯一能写正文的工具是 `draft_chapter`，产物永远是一整章。
   「改一句」只能变成「整章再写一遍、嘱咐它别的别动」：三千字的章改一句，写手照样输出
   三千字、五十秒、整章的钱；而「其余一字不动」是嘱咐不是机制，拦不住它顺手改别处。
2. **写手不知道拿现有正文干什么**，才把整章抄了回来（那一段只挂一个标签、又排在 prompt 最末）。
   写死一句「这一次是重写」，或者加一位 `intent` 让助手选，都只是在嘱咐上下功夫，
   没有解决第 1 条。
3. **助手自己不许写正文**（ADR 0019 边界一）：工具表里没有一条工具收助手写的正文——文风、
   作者的禁用词、人物记忆都是后端装配给写手的，助手绕过写手直接往章里塞字，这些全废。
   所以「让助手自己改那一句」不是出路。

## 决策

**再加一把小锤子：`revise_passage`（改一段）。** 助手给三样，写手写，后端拼。

| 谁 | 做什么 |
|---|---|
| **助手** | 改哪儿（`quote`：那一段的原文，从正文里原样引，必须恰好出现一次；`until` 定范围末尾）、怎么改（`kind`：`replace` / `insert_after` / `delete`）、对写手说什么（`brief`）。作者这一次要改的**全放在一次调用里**（`edits` 是一串）。 |
| **写手** | 看整章（同 `draft_chapter` 的装配：文风、规矩、记忆、上文、在场都在），**只写出那一段**（`_PASSAGE_ASK`：不重写别的段落、不加标题说明、接口要顺）。字数口径按那一段的长短（`passage_length`），不按整章的。一次调用，不按整章的长度策略续写。 |
| **后端** | 找那一段（`draft/passage.py::locate_span`：恰好一次才算找到，找不到 / 多处 / 前后颠倒 / 几处重叠一律拒，不替它挑）；每一处写手写完再**从后往前**拼回正文（`splice`）；切掉章标那一行；收进候选表当**一稿**（`brief` 记的是每一处「改哪儿 + 怎么改」）；整章一片送到界面（`TurnEvent.revising`）。 |
| **界面** | 整章直接放进编辑器，**不逐字重打**（逐字重打一遍整章，作者看到的是「整章都在动」）；痕迹上只有改过的那几处（`editMarks.ts`）；右边一行「已放入编辑器，按保存写入本章」；作者按保存才进书。 |

`draft_chapter` 从此就是整章重写，而且**不给写手看现有正文**：先前那一段前面写死「这一次是
整章重写、不要照抄」并不管用——第 9 稿（要求「只写一个场景、三条线一笔带过」）交回来 101 段里
100 段和磁盘上逐字相同，只换了第一行。嘱咐没用，不给才有用。要保留哪几段原样、只改别的，
走 `revise_passage`（`quote` + `until` 把要改的范围圈出来）。晚上先做的那一位 `intent` 撤了。

边界一句没破：`revise_passage` 收的仍是**引语和对写手说的话**，不是正文；出参和 `draft_chapter`
同一个形状（编号 / 字数 / 开头 / 自述），没有新路通向图数据。`delete` 那一档不用写手、不花钱，
拿掉的也只是作者自己书里已有的字，而且和别的一稿一样要他按保存才算。

## 为什么是这个形状

- **粒度是引语，不是字符位置**（ADR 0006）：位置只在这一次拼接的瞬间算出来用一下，不出
  `passage.py`、不存。引语两头的空白不算（助手从工具返回里抄的时候常带一个换行）。
- **恰好一次才算找到。** 找到多处时替它挑一处，产物是改错了地方，而它在屏幕上长得完全正常
  （§5.9 那条老规矩）。拒绝的话里说清怎么办（「引长一点」「先用 chapter_text 读一遍」）。
- **一次调用一稿。** 分几次调用就是几稿，后一稿是对着磁盘上那一版改的、看不见前一稿改了什么
  （前一稿还没保存）。所以工具说明里写死「作者这一次要改的全放在一次调用里」。
- **整章一片送到、不逐字露。** 打字机是给「从头写」准备的；改一段时逐字重打一遍整章，
  痕迹和正文同时在动，作者分不出哪儿改了。`present`（桌上拿一稿进编辑器）同理，也改成直接放。
- **改一段不留半截。** 作者按停时 `draft_chapter` 会把半截存成一稿（那是付过钱的信息）；
  改一段的半截是半句话，拼进整章比没改更坏——拒，钱照旧带在回执上。

## 代价

- **写手仍然要读整章**（输入 token 照付），省下的是输出：几十个字 vs 几千字。要它连整章都不读
  （只给前后几段）是下一步的优化，今天先保证它写出来的段接得上。
- **「其余一字不动」在机制上成立了**，但写手写出来的那一段接不接得上前后文仍然是它的事——
  接口不顺，作者看 diff 时一眼看得见，改一句或者再要一次。
- **标题改不了**：章标那一行不在正文里（它是切章的锚），引它会被拒「找不到」。改标题走顶栏。

## 同日改动记录

1. 上午到傍晚：[ADR 0048](0048-drafting-writes-the-chapter.md) 的四版。
2. 晚：写手抄回整章 → 那一段前面写死「这一次是重写」→ 维护者否（「写死了」）→ `draft_chapter`
   多一位 `intent: rewrite | revise`、有正文时必填不说就拒 → 维护者否（「这明显不是一个好的
   解决方法」：改几句不该走整章重写，要讨论目的 / 卡点 / 解法）→ 本 ADR。`intent` 撤了。
3. 本 ADR 落地后第一稿（第 9 稿）：那句「整章重写、不要照抄」压不住写手——100 / 101 段照抄。
   于是整章重写**不再给写手看现有正文**（`agent/drafting.py::_write_the_open_stream`），
   现有正文只在改一段时进 prompt。

## 没做的（有意）

- **只给写手前后几段而不是整章**——先保证接得上，再省输入。
- **改标题**——走顶栏，不走这把工具。
