# ADR 0022：起草是提议，不是落盘；候选既不进正文也不进对话

- **状态**：已接受；**入口形态 2026-09-12 被 [ADR 0048](0048-drafting-writes-the-chapter.md) 换掉**——起草写完直接写进那一章，`save_draft` 删了，对话里不再摊候选让作者挑。候选表、`read_draft`、并排页、「候选不进对话」这几条原样保留。
- **日期**：2026-08-12

  落盘是起草的副作用）。**它的精神原样保留：落盘仍然不问作者。**
- **相关**：[ADR 0007](0007-manuscript-lives-on-disk.md)、

## 决策

**起草和落盘拆成两个动作。**

| 动作 | 花钱 | 动书 | 谁决定 |
|---|---|---|---|
| **生成一稿** | 花 | **不动** | 模型 |
| **落盘** | 不花 | 动 | 模型（**仍然不问作者**，ADR 0021 精神不变） |

方向清楚时模型「生成 + 立刻落盘」，作者的体验和 ADR 0021 一模一样。
方向不清楚时模型生成几稿、**不落盘**，把它们摆在对话里让作者挑。

**候选稿存在自己的地方，既不进正文也不进对话历史：**

- **不进正文** —— 它还不是书的一部分（边界三：「哪一份正文是真的」只许有一个答案）。
- **不进对话** —— 三稿 ≈ 9,000 字，而**无状态 API 每一轮重发整个消息数组**，
  它会被反复付费到会话结束。对话里只放 **id + 定长预览 + 那一稿的自述**。

**那一稿的自述由写它的那个模型给。** 起草是工具内部另起的一次模型调用，
外面那个模型**没看过正文**——它要说「我推荐第二版，因为更冷」就得先把 9,000 字读进上下文。
让写手交一句三十字的自述，同一次调用里白送。
**引擎全程没给散文打过分**（ADR 0005 一个字没破），是写它的模型在说自己写了什么。

## 为什么

### 1. 「写三个版本让我挑」和「写完直接存」在旧机制下是拧着的

ADR 0021 下，一批三稿的真实行为是：第一稿落盘 ⇒ 磁盘变了 ⇒ 后两稿手里的底稿全过期 ⇒
**被 sha 闸拒掉**。作者要三版，拿到一版，付了三份钱，还收到两句
「这一章在别处刚被改过」——而「别处」是它自己，同一轮里，半秒之前。

那道闸没写错，**是「落盘是起草的副作用」这个机制错了**。

### 2. 拆开之后四件事同时好了

- **同一轮多稿不再打架**：三次返回、零次写入，没有赛跑。
- **崩了重跑安全**：补跑一稿只是再花一次钱，**不会往书里写第二遍**。
- **「作者打字 / agent 落盘」的碰撞窗口从几十秒缩到几毫秒**——
  落盘不再等在一次模型调用后面。撞上的概率掉几个数量级。
- **一批稿可以并发**：起草没有副作用了，三稿同时跑，两三分钟压回一分钟。
  （旧机制下不敢并发——三个都要往同一个文件写。）

### 3. 候选进对话的成本是「每一轮都付」，不是一次

跟模型对话的接口是**无状态**的：每一轮把整个消息数组从头重发。
工具返回也是消息。所以三稿从生成那一刻起**每一轮都在被重发**，
直到有人主动拿掉——而默认没有任何东西会拿掉它。

界面上折叠、划掉、关标签页都不改变发出去的那份数组。**这是协议层的事实，不是实现偷懒。**

## 保留不动的

- **落盘仍然不问作者**（ADR 0021 的核心）。
- **sha 闸原样留着**：拒绝覆盖作者比它更晚改过的那一章。它现在守的是一个几毫秒的动作。
- **只对已经存在的章成立**：新建一章要起章标题，而标题是切章的锚。
- **落盘前先跑一次幂等 `sync`**（ADR 0021 的退路承诺押在这一条上）。
- **保留作者那一行章标题 + 写前验「恰好一章」+ 空稿闸**（3.6 挖出来的三条，照 ADR 字面做会毁书）。

## 代价（承认，不粉饰）

- **多一张表、多一个工具**（按 id 读回某一稿，只在作者要合并两版时才会被调用）。
- **候选会堆积**。落盘或被否决之后它就是死重，要有清理策略——
  但**不许在作者还可能回头看的时候清**。
- **作者要读三章才能做一个决定。** 钱是三倍，而读 9,000 字是更真实的代价。
  所以入口是「推荐那一版摊开 + 另两版各一句自述」，不是三章并排硬摊。
- **预览长度必须是一个写死的数并有测试**。没有硬上限的话，一份 500 字预览 × 3
  就把省下的吃回去一半。

## 什么条件下推翻本 ADR

- **作者实测反馈：他从来不用多版本，每次都是一稿改到满意。**
  那时「生成 + 落盘」两步合一是纯摩擦，该退回 ADR 0021 的单步机制。
- **候选表成为第二个「哪份正文是真的」的答案**——
  比如版本抽屉里开始出现没落盘的候选。那时先修边界，修不了才退。

## 若此决策错误，修复成本是什么

**低。** 两个动作合回一个是一次调用点的改动，候选表留着不碍事。

**但有一条不对称**：如果候选表泄漏了秘密原文，**它是落盘的**——
和对话历史一样不可回收（ADR 0019 边界一）。所以候选表必须先有那张网：
喂一本带 `props.twist` / `plot_note` / `SecretDetail.description` 的书跑完整链路，
**直接查表的每一列**搜那几种毒。这跟在出参上搜不是一回事。
