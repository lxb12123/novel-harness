# ADR 0042：R3 DEAD_SPEAKS 砍掉，系统规则清零 —— 死而复生的书上它会一路误报，而它是闸

- **状态**：已接受
- **日期**：2026-09-05
- **裁决类型**：**维护者裁定，不是数据裁决**（同 ADR 0041）。这一刀没有跑任何实验，
  依据是产品判断 + 一条结构性事实（下面第 2 节）。
- **推翻了**：不是原始需求文档，是**本仓库自己**——`checks/dead_speaks.py`、
  `checks/catalog.py::SYSTEM_RULES` 里的 R3 `RuleSpec`、`ALL_CHECKS` 从 1 条变
  **0 条**，以及「引擎自带一套连续性硬规则」这条设计本身。
- **相关**：[ADR 0005](0005-set-judgment-only.md)（规则只做集合判断——那张表里
  R2/R3/R4/R5 现在**全是历史记录**，正文一字不改）、
  [ADR 0014](0014-r5-cut-by-quote-coverage.md) / [ADR 0027](0027-scene-blocks-cut.md) /
  [ADR 0040](0040-future-leak-cut.md)（R5、R4、R2 死于同一类判据的更早三次）、
  `docs/M3_GATE_PROTOCOL_RETIREMENT.md`（M3 那张卷子随之退役，协议正文冻结不动）

## 决策

**`checks/dead_speaks.py` 整个删掉，连同它在 `ALL_CHECKS` 和
`checks/catalog.py::SYSTEM_RULES` 里的登记。`SYSTEM_RULES` 因此变成空元组。**
迁移 035 把这次目录语义变化带来的新 `ruleset_epoch`（2 → 3）/ `ruleset_hash`
（空目录的 sha256）写回所有既有项目。

**没有删的——这一条比删了什么更重要**：

| 东西 | 现状 |
|---|---|
| 整套规则机制（`catalog` / `service` / `RuleSpec` / `ruleset_hash` / epoch 迁移纪律） | **保留**。维护者原话：「我们只是把系统那个隐藏了，把我们系统的规则都去掉了，**因为指不定我们以后也有规则**。」 |
| 检验发生的位置 | **一个都没动**：保存后那一轮（`chapter_refresh.py`）、`POST …/chapters/{n}/check` 照旧跑 |
| 作者自定义规则（`checks/custom.py` 的 `forbidden_literal`） | **保留，且从这一天起是唯一的规则来源**；同一条 `SYSTEM_RULES + load_custom_rules` 路径 |
| `HEALTH_DIM_NAME` / `declare_death()` / 抽取的 `kind="death"` | **保留**。「他死了」这条事实照旧进图、照旧显示在人物卡的「状态」那一格 |
| `node.props.first_appears_chapter` / `declare_first_appearance()` | 保留（它现在一个消费者都没有了——见「留下的洞」） |

删的只是**「拿这条事实开一道闸」**这一件事。

## 为什么

### 1. 死而复生是常见写法，而引擎里没有「活过来」这个动作

作者的原话：「有些人他们就是写死而复生的时候依旧能讲话了，你不能就是这么干吧。」

这不只是「某些书不适用」，它在这个引擎里有一个**结构性**的形态：

- `is_dead` 的唯一判据是 `HAS_STATE(health) = dead` 这条边；
- 写它的只有两条路：抽取的 `kind="death"`、作者的 `POST …/declare/death`；
- **反过来的写入方一个都没有**——抽取的封闭枚举里根本没有「复活」这个 kind，
  作者面上也没有「他活过来了」这个动作。

于是一个人被标死之后**在图上永远是死的**。他后面每一句带说话人标签的台词都会命中
R3，而 R3 `blocks_downstream=True` ——**它不是提示，是闸**：验证不过，那一章的
总结和抽取直接停（`chapter_refresh.py`）。作者唯一的出路是到活动记录里把那条死亡
事实手动撤回，也就是**为了让工具别卡住，去删掉一条正确的事实**。

一条会系统性误报的规则挡在产品链路上，比没有规则坏得多——这正是 ADR 0005 立的
那条线：**误报 5–20 条/章 = 作者弃用**。R3 在这类书上的误报率是「此后每一句台词」。

### 2. 它剩下的价值本来就薄

R3 只在「名字紧贴说话动词」这一种机械形状上开火（中文），或「右引号后第一个词」
（英文）。它抓的是一种作者自己回读时几乎必然会发现的错，而代价是上面那条闸。

维护者的判断：「那我们现在的这种上下文注入程度，这种规则简直就是摆设。」
写作模型今天拿得到人物状态（含生死）、拿得到本章在场名单——「死人不该说话」这件事
已经在**写之前**被上下文覆盖了，而 R3 是在**写之后**再拦一道。

### 3. 那条被提议的替代品（「检验角色存在是否合理」）做不了

作者一度提议把这条规则改名成「检验角色存在是否合理」。**这在本仓库是明确越线的**：
它要回答「这个角色此刻出现合不合理」——语义判断，[ADR 0005](0005-set-judgment-only.md)
的铁律禁止；而「LLM 当裁判」那条路是当初有意砍掉的。

更危险的是**只改这句话、底下还是原来那条检查**：屏幕上写着「检验角色存在是否合理」，
实际跑的还是「名字紧贴动词 × 标着已死」。那是这个仓库最不能犯的错——
向作者承诺一件系统做不到的事。所以这个替代方案没有被采纳，规则整条删掉。

## 代价与留下的洞

1. **系统规则为零 = 一本没加过规则的书，检验那一步什么都不查。** 这是有意的：
   出参里 `rules: []` 和 `issues: []` 是两件事，「没有规则」必须和「没有问题」分得开
   （§10 约束 8）。`tests/test_rules_fire.py::test_nothing_is_checked_before_the_author_writes_a_rule`
   钉这一条。
2. **`first_appears_chapter` 现在零消费者。** R2 死后它还剩 R3 的「未登场就说话」那半支，
   R3 一走它就彻底没人读了。字段和 `declare_first_appearance()` 保留未删——
   哪天要清，那是另一份 ADR 的事。
3. **M3 那张卷子退役。** 它量的是 R2/R3 的误报/真阳性，主语没了。
   **协议正文（`docs/M3_GATE_PROTOCOL.md` + 修正案 1）冻结不动**，
   `synth/m3_replay.py` / `synth/m3_ground_truth.json` / `tests/test_m3_replay.py` 删除，
   退役说明另开一份（同 M2 那次的 `EVAL_PROTOCOL_RETIREMENT.md` 的做法）。
4. **`FakeGraph` 少了一处「经由规则打真库」的对照。** `tests/test_store_conformance.py`
   第 6 节删了（那一节先后是 R4、R3），因为今天唯一的规则只读段落、不碰图。
   闭开区间那条缝没有裸奔：同文件第 4 节直接打两个后端的 `state_at`。

## 换来的

规则这一格从「引擎替作者定，且只有一条」变成「**作者自己定，多少条都行**」。
配套这一刀落地的还有工作台那一栏（「检查」→「**检验规则**」）：系统那一组
**空着就整组不显示**（判的是空不空，不是写死「没有系统规则」——目录里再放一条它自己
就回来），作者那一组能加能删，加的是一段「不许出现的字」，引擎逐段精确子串匹配，
**不执行作者写的代码、不上正则、不把这句话交给模型**。
