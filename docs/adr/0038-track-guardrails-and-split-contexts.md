# ADR 0038：改老章的轨道 —— 写时给护栏，写完异步验，写的和验的分上下文

- **日期**：2026-08-23

  一份文档里**的前提：「作者永远在书的最前沿写」。它从来没被审视过，因为没人写下来过。
  另外给 [ADR 0019](0019-agent-loop-not-graph.md) 的六问表**补一格**（原文一字未动，
  后面追加带日期的补记）。

  只告警不阻断的**窄例外**——本 ADR 整条异步链靠它才允许存在）、
  [ADR 0005](0005-set-judgment-only.md)（规则只做集合判断，所以「秘密说破了没有」只能用模型）、

## 那个没写下来的前提

作者跳回去改第 2 章时，引擎**完全不知道第 3 章之后存在**：

- 算权重时，章号更大的一律当成「还没写」，权重 0；
- 拼 prompt 时只取「比当前章更早」的总结和事件；
- 续写的上文只有「光标之前」，同章之内。

**这不是三个 bug，是同一个前提的三个投影。** 于是改出来的东西可能跟第 47 章直接打架，
而没有任何东西会发现。

**2026-08-23 裁定：这个前提不成立。**

## 决策

### 一、触发：只在「不是最新章」时启用

比一下当前章号和全书最大章号，一次查询——**这个判断已经在用了**（后台算调度原点就是这么干的），
所以提成 `focus.frontier_chapter()` 一份，不写第二份。是最新章 → 照旧，什么都不变。

### 二、锚定按相关性，不按位置

**不取「后面 N 章」**：区间是死的，猜小了漏、猜大了全浪费，而铺垫的影响范围本来就不固定。
**按「共同提到了谁 / 哪个地方 / 哪个物件」取。**

| 级 | 做什么 | 花钱 | 本 ADR |
|---|---|---|---|
| 一 | 扫刚改的那段字 → 命中角色册 → 反查倒排表 → 后面哪些章的总结提到了它们 | **0** | ✅ |
| 二 | 读那几章的总结（8 章 ≈ 960 字） | **0** | ✅ |
| 三 | 总结说不清 → 下探到那几章原文的相关段落 | **0** | ❌ 待定 |
| 四 | 用模型判「写的这段跟轨道抵不抵触」 | 花 | ✅（异步，见四） |

倒排表**六类都收**：人物、地点、势力、秘密、伏笔、**物件**。所以「玄铁令第 64 章写着只能在
水底唤醒，你第 2 章写它发白光」和人物那条线是**同一次查询**捞回来的。
（不收引擎内部的状态维度和章节本身——它们在总结里到处都是，进去全是噪声。）

**今天的真实缺口，一句话：不是缺一套检索，是缺一根线。**
索引在跑、反查函数在、定位能力在、通知那一格在——**但写作那条路一次都不调它们。**

### 三、信息隔离 —— **这一条是整个设计的地基**

后面章节的总结里，可能写着这一章的读者还不该知道的事
（第 64 章：「萧决终于知道自己身上养的是玄血蛊。」）。把它给写第 2 章的模型看，
**等于把伏笔亲手告诉它——那正是这个产品的核心主张会被从背后拆掉的地方。**

**解法不是过滤，是分开：写的和验的不必是同一个上下文。**

```
Writer 的上下文：前文、下文、前面章节的总结          —— 干净的，从没见过轨道
       ↓ 写出来
验证那一侧：轨道（可能带着不该出现的内容）+ Writer 写的那段
       ↓ 判
回给 Writer：一条结构化的评语，不含轨道原文
```

**评语形状限死**，只许「第几句 + 跟第几章冲突 + 冲突类型」：

```
✅ 第 3 句 ↔ 第 64 章，设定冲突
❌ 「你写萧决不知道那件事是错的，第 64 章他才知道自己身上是玄血蛊」
```

结构化的出参能被机械检查，自由文本不能。**作者要细节自己去翻第 64 章。**

**机制是形状，不是提示词。** `TrackClash` 只有 `(sentence, chapter, conflict)` 三个字段——
**没有自由文本字段能装下后面那一章的原文**。提示词里那句「不要复述」只是省一次无用生成，
不是依靠。守卫是数据驱动的：拿这一次轨道里的**每一段总结**去搜评语和通知，一个字都不许出现。

### 四、模式一：落进正文之后，后台异步验

ADR 0019 明写模式一不适用它，理由是「停手 400 毫秒就要出结果的交互里塞不下第二次往返」。
**那句话仍然对**，所以不在续写那一次里验：

```
续写建议照旧出来（不等验证）
  → 作者接受了、落进正文
  → 后台验一遍（跟保存后跑总结/抽取同一条路）
  → 不对 → 一条通知，不阻断
```

**两问同一条路、同一个落点**：秘密有没有被说破（认知矩阵那一半，见 ADR 0037）、
新写的跟后面章节抵不抵触（轨道那一半）。

**不阻断**是硬的：走新加的第四种通知类型，**一次都不碰 `validation_blocked`**——
那一类有副作用（会把这一章的自动总结和抽取停掉），挂错档会让作者**改个老章就把整章的
自动整理停掉**，而那不会有任何东西报错，只会表现成「总结怎么一直不更新」。

**锚由我们算，不由模型给。** 模型返回的是我们编的句号；`(para_index, quote_text,
occurrence_k)` 三个分量全部来自自己切的句表（ADR 0006）。模型返回的 quote 有 10–30% 对不上
原文——直接塞进锚就是一条点过去落在别处的通知。问不出 occurrence 的那一句整句不进表：
**宁可少一句，也不落一条骗人的锚。**

## 给 ADR 0019 补的那一格

它当年的六问里有一问是「多角色要独立上下文？」，答案是「**不要**，查约束 / 跑检查 / 读正文
全是纯函数」。

**那个理由在这儿不成立**：验证轨道不是纯函数（要模型判语义），而且要独立上下文的原因
**不是「角色不同」，是「写的那个不能看见验的那个看见的东西」**——**这一条当年没考虑过。**

**不是推翻它，是补一格。** 落地形态仍守它六条边界：模式二做成工具（工具持有轨道，agent 没有
——「工具表就是权限边界」这句话在这儿字面成立）、模式一不在续写那一次里验、评语形状限死。
不补的话，下一个人读到那张表会以为这件事已经被否掉了。

## 成本闸（做实现的人自己定的，记在这儿以免被当成 bug）

**核对只在「这一版正文是作者存出来的」时才跑。** 补总结那一轮会为每一章下一张单，在那儿
顺手核对一遍等于把接一本 158 章旧书的成本**翻一倍**（每章 2 次调用 → 4 次）。

本 ADR 交付的是「保存之后验一遍」；**「扫全书找矛盾」是另一个决定**，它有自己的成本和
一次几十条通知的噪声。要开那件事就改那一行。

另外两道门：闸门放行了才核对（阻断的章不值得再花钱）；作者正盯着的那一章不核对——
借的是总结那一支**同一个**判据，不是第二份口径。

## 范围之外

- **阶段 3（模式二做成工具）没做。** 模式二今天直接调 `draft_chapter()`，不经过 HTTP 壳，
  所以它那条路上还没有轨道。做的时候要连上「系统在『不是最新章』时提醒模型去调」——
  **判断在系统这边，调用在模型那边**，不能指望它自觉。
- **阶段 4（三级下探在模式一里按什么规则触发）待定。** 模式二交给循环自己决定；
  模式一**现在定死规则就是拍脑袋**，等有真实案例再说。

## 若决策错误，修复成本

**中。** 两个新模块（`track.py` / `advisory_review.py`）住在 `draft/` 外面，删掉它们
不影响写作那条路——这正是信息隔离顺带买到的东西。第四种通知类型是一次迁移。

**但先分清要退的是哪一半**：锚定那一半零成本、零模型调用，退它没有收益；
花钱的是第四级。真嫌贵就先关第四级，把前两级留着——**它们本来就只是把已经在跑的索引
接上了一根线。**
