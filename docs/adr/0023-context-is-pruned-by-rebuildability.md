## 决策一：剪枝的排序判据是「可不可重建」

通用做法按**新不新**排。在这个项目里那是错的坐标：

| 类别 | 处理 | 为什么 |
|---|---|---|
| **作者说过的话** | **永不动，永不压缩** | **全场唯一不可重建的东西** |
| **作者定下的规矩** | **升格成结构化的一条**（见决策二） | 小、跨轮有效、丢了最气人 |
| 约束 / 图谱查询的返回 | **随时丢** | 重查回来的**更新鲜**——丢掉不是有损，是升级 |
| 正文读取的返回 | **随时丢** | 磁盘上有（ADR 0007） |
| 候选稿 | 落盘或否决之后丢 | 已经有归宿（ADR 0022） |
| agent 的中间推理 | 丢 | 能重想 |
| **正文本身** | **永不压缩** | 它在磁盘上，它就是产品 |

第三、四行是这个系统独有的便宜：**丢掉的重查一次就有，而且查回来的是当前的。**

**总结（compaction）仍然受边界四管**：该留「作者的意图、被否决的方向、现在写第几章、
文风偏好」，**禁止含**「`must_not_reveal` 的内容、谁知道 / 不知道什么、
任何绑章号的状态 / 秘密名 / 未登场实体名」。
论证同 ADR 0017 拦 wiki：压进散文之后「他此时还不知道」——**「此时」是第几章？**

### 厂商的服务端上下文管理：有就用，没有自己做

**这是两层，不是二选一。**

```
我们这一层（不可外包）：按章号筛掉不属于这次视角的      ← 服务端不知道第几章
        ↓
厂商那一层（能力表里有就用）：清旧工具返回 / 压缩历史
        ↓
自己兜底（厂商没有时）：本 ADR 的剪枝
```

判据进 `ProviderCapabilities`（那张表已经在按 endpoint + model 冻结
`supports_streaming` / `reasoning_levels`，多一列不是新机制），**未登记一律 fail-closed 走自己的**。

**⚠️ 修订（2026-08-12，落地当天）：上面那个开启条件写错了，而且是空集。**

原文写的是「厂商那一层只许开在**我们自己已经放弃**的那部分上」。
**在 `chat.completions` 这个无状态协议上，那部分根本不在发出去的 payload 里**——
每一轮把整个数组从头重发（ADR 0022 §3 就是靠这条事实决定候选稿不进对话的），
**我们已经放弃的东西服务端见都见不到，没有可清的**。
要让那句话非空，端点得自己存着这段会话（有状态那一类），而那不是本仓钉死的协议。

**而且「它说得出清了什么」也不是充分条件**：**服务端不知道第几章。**
它把一条绑第 90 章的返回压成散文，那段散文对第 40 章的投影就是边界四点名的那个故障，
只是发生在我们的筛子够不着的地方。

**所以真正的开启条件是两条同时成立**，今天一条都不成立：

1. 端点**有状态**（会话存在它那边），否则「我们放弃的那部分」是空集；
2. 它清掉的那些**本来就不该按章号筛**，否则它替我们做的是一次我们禁止的操作。

落地时的处置：能力位 `server_context_management` **加了但不启用**（三档
`NONE / OPAQUE / REPORTED`，未登记 fail-closed），注册表里全部路由都是 `None`，
全库零消费者。**它今天是一个占位，不是一条已经在用的路径。**

## 决策二：作者的规矩带章号区间，取窄 + 重复放宽

作者在对话里说的「别写打斗」「冷一点」「太煽情了」是**偏好，不是事实**——
不进 canon，但要活过剪枝。

**时钟是章号，不是挂钟。** 全系统都在用这个钟（边的 `[valid_from, valid_to)`、
投影坐标、约束计算），作者脑子里也是按章走的。挂钟和轮数都跟意图无关。

- **默认只管当前这一章**，切章自动失效。
- **「整本书都这样」不是把有效期改成 9999，是升格进 `house_style`**——
  那是边界六允许进稳定前缀的三样之一（跨章不变）。
- **章级规矩不许进稳定前缀**（边界六的判据只有一句：换一章会不会变，会变就不许进）。

### 安全方向跟 `must_not_reveal` 是**反**的

| | 拿不准时 | 为什么 |
|---|---|---|
| `must_not_reveal` | **留着**（多禁 = fail-closed） | 说破了收不回来 |
| **作者的偏好** | **放掉**（早失效） | 留着 = 第 200 章写不出打戏，而**作者不知道为什么** |

写错一场戏一眼看得见、改一次就好；说破一个秘密改不回来。
**这个仓库其余地方「fail-closed 更安全」的直觉，在这一条上不适用。**

### 歧义怎么办：取窄 + 数重复，不猜意思

「这三版太煽情了」——是「这一章别太煽情」还是「就这三版」？**分不出来，也不该假装分得出来。**

救命的事实是：**两种解读的下一步动作完全一样**（重写时避开煽情），
区别只在这条规矩活多久。所以**不用当场决定**：

- **取窄**（就这一批）。猜窄了的代价是作者再说一次（顺口，他本来就要评价下一批）；
  猜宽了的代价是**一条隐形的规矩跟着他走，他不知道它在**。
- **说第二次就自动升到章级。** 一次是偶然，两次是模式——
  而「说了几遍」是**集合判断，不是语义判断**（ADR 0005 一个字没破）。
- **摆出来、能取消**（ADR 0020 那条理由链的第三次应用：不问，但看得见、改得掉）。

**agent 在对话里问一句不违反约束 8**——那条治的是「系统主动推队列 / 弹框」。
但**不该每次都问**，只在真的会改变下一步动作时问，而上面那种情形不会。

### 顺出来的通用原则：歧义的三种合法反应

选哪个，看**猜错的两个方向代价对不对称**：

| 反应 | 什么时候 | 仓库里的现成例子 |
|---|---|---|
| 摆候选，绝不挑 | 两个方向都很贵 | `AmbiguousName`：「师兄」指 8 个人 |
| **取窄 + 观察重复** | 一边便宜一边**隐形** | ← 本 ADR |
| 全禁 / fail-closed | 一边可恢复一边**不可恢复** | 推不出在场就全禁（ADR 0018） |

## 前置：先把账算对

`agent/loop.py` 的预算**只量对话、不量工具声明**。

**⚠️ 那个「18%」是低估的低估，而且它会长**（2026-08-12 落地当天实测修正）：
HEAD 上是 **3,934 字 = 23%**；ADR 0022 加了 `save_draft` / `read_draft` 之后是
**5,171 字 = 默认预算 17,000 的 30%**，留给对话历史的只剩 11,429 字。

> **每加一条工具，所有会话的记性都变短一截**，而在这次改动之前**没有任何东西显示这件事**。

所以 `Projection` 要把 `tool_units` 单独报出来。默认预算要不要放宽是产品决定，
但**别再拿 17,000 当「对话能用 17,000」**。

**在省之前先量准**——否则本 ADR 所有「省了多少」都是估的。
且要有一条断言：**预算量出来的数，和真正发出去那份 payload 的实际大小，
误差必须在一个写死的范围内。**

## 代价

- **规矩提炼是模型的判断，它会判错**：作者随口一句可能被升格成常驻。
  退路是看得见 + 能取消，**不是事前确认**。
- **章级规矩逐轮重算**，进不了稳定前缀，所以每一轮都要重发（小，但不是零）。
- **厂商那一层一旦启用，「裁了什么」这句承诺就有一段我们看不见**。

## 什么条件下推翻

- **实测：作者从来不管那份「现在生效的规矩」清单，而它经常是错的。**
  那时该退回「规矩必须作者亲手写」，或者干脆不提炼。
- **章号这个时钟被证明不合作者的直觉**（比如他其实按「场景」而不是按「章」想）。
  那时换时钟，不是换机制。
