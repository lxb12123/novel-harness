# ADR 0024：一轮不再是黑箱 —— 编排边跑边发事件，模型能停下来问作者

- **状态**：已接受
- **日期**：2026-08-12
- **推翻了**：两样，都是**本仓库自己**——
  ① 一个从 M1.5 起就**没被任何人写下来过**的隐含前提：「工作台 = HTTP 请求/响应」。
  没人决定过它，所以也没人能反对它。
  ② [ADR 0019](0019-agent-loop-not-graph.md) §3.1 第四问「需要等人工？**要作者确认写正文，
  是一次同步确认** ⇒ 不要 interrupt/resume」——那条理由的前提已经被
  [ADR 0021](0021-agent-writes-drafts-without-asking.md) /
  [0022](0022-drafting-is-a-proposal-not-a-write.md) 拿掉了（落盘不再问作者）。
  **结论仍然成立，但要换一条理由**（见「为什么不需要 interrupt/resume」）。
- **相关**：[ADR 0019](0019-agent-loop-not-graph.md)（边界一 / 三 / 五）、
  [0005](0005-set-judgment-only.md)、[0021](0021-agent-writes-drafts-without-asking.md)、
  [0022](0022-drafting-is-a-proposal-not-a-write.md)、

## 决策

**一轮从「三分钟的黑箱」变成「一场真的对话」。** 四条：

1. **编排边跑边发事件。** `run_turn` 不再只在跑完时返回一个结果，
   它在每一步的边界往外喊：在查什么 / 查完了 / 在写第几稿 / 模型吐了这一段 / 停下来了。
2. **引擎不许认识传输。** loop 只管发事件，WebSocket / SSE 是一层薄适配器 ——
   同 ADR 0019 边界一那条「**运输层不认识工具表，也不许认识**」的纪律。
   这也是 Codex 那套的真正价值：同一个核心能驱动 CLI / TUI / MCP / 桌面壳。
3. **传输只换一条。** 只有「跑一轮」那条换成长连接。
   `GET /chats`、`PUT /chapters/{n}/text` 那些**原样不动** —— 它们本来就是问一句答一句。
4. **加一个「问作者」的工具。** **模型决定什么时候问，作者决定答什么。**
   出参形状要能渲染成几个可点的选项，而不是一段散文。

## 为什么

### 1. 不是性能问题，是能力问题（有实测）

用我们自己的 app、真 loopback socket、同一端点、取中位数：

| | |
|---|---|
| 引擎直调（含开关 SQLite 连接） | **0.832 ms** |
| + 路由 / 校验 / 序列化 | 1.310 ms |
| + 真 loopback socket | **1.878 ms** |

**HTTP 那一整层 ≈ 1 毫秒 —— 大约等于「多开一次数据库连接」。**
人的感知阈值 200 毫秒，一次起草 30–60 秒。**这条差别在这个产品里量不出来。**

> 所以要换的理由**跟快慢没有半点关系**：请求/响应这个形状**不能推**。
> 想在中途显示「它正在查这一章还有谁不知道那件事」，**哪怕 HTTP 快到零毫秒也做不到。**

> ⚠️ **举例更正（2026-08-12）**：原文举的是「正在**查第 40 章**的约束」——
> **开跑那一声说不出章号**。章号躺在 `ToolCall.arguments` 里，那是一串没解析过的字，
> 而**解析点只许有一个**（`dispatch`）。开跑那一声只有工具标签，
> **章号在「查完了」那一声里才第一次说得出口**。

### 2. 「可中断」今天几乎是白做的

2026-08-12 刚落地了起草可中断（`6b13abd`）。但作者**看不见它在写什么**，
屏幕上只有一个秒表 —— 于是按停退化成「等太久了，算了」。

**那不是判断，那是放弃。** 它本该是「读到第三行发现语气不对 ⇒ 第 5 秒按停」。

**没有事件流，上一刀的产出兑现不了。**

> ⚠️ **一条捆绑关系，别当 bug 修（2026-08-12 实测）**：**逐字看得见的只有「起草」，
> 不包括「对话回复」。** 回复那一档的输出预算 4,024 远在流式阈值 16k 之下 ⇒
> `plan.stream is False`，而这件事仓库里**已经有一条测试钉着**
> （`test_todays_agent_call_is_not_streaming_so_that_precision_is_not_in_production`）。
>
> 而且 **`interruptible` 同时决定流式和可中断** —— 也就是
> **没有停止信号就没有流，也就没有边写边看**。两件事在产品上是捆着的，
> 而本节举的那个例子（「读到第三行发现语气不对 ⇒ 第 5 秒按停」）读的**本来就是稿子**。
>
> **2026-09-12 补记：上面那条测试翻过来了**（改名
> `test_the_agent_call_streams_so_that_stop_lands_within_a_chunk`）。作者按「停」要等整份
> 回复回来这件事在真书上是十几秒到一分钟（原话：「没有办法第一时间暂停」），所以回复那一次
> 调用也要了 `interruptible`——预算一个字没抬，只是 `_streams` 的第二个理由成立了。
> 捆绑关系照旧：wire 上有流了，**边写边看仍然只有起草那一档**，因为装配层造对话端口时没接
> `on_event`（`api/chat.py::build_agent_model` 那个注入点的签名是十几处测试桩共用的）。
> 被掐断的那次调用**进账**（token 留空），停下来之后 loop 还会问作者一句
> （`run_turn(debrief_on_stop=True)`，见 `agent/loop.py::STOP_DEBRIEF_PROMPT`）。
> 同日第二刀：`Cancellation` 也是一个 AbortController——`stop()` 亮信号之后叫挂着的钩子，
> 适配器挂的是 `socket.shutdown`（`agent/model.py::_cut`），于是卡在两片之间的 `recv`
> 当场醒，不用等模型吐下一片；块摘要那一次非流式调用也在钩子底下。这就是 Codex /
> Claude Code 那一路「断流 + 掐断正在跑的东西」在这套阻塞式客户端上的样子——
> 这儿的「工具」没有子进程，唯一会跑很久的是起草那几条流，它们和回复走同一个钩子。

### 3. 写小说本来就是边写边商量

作者的原话：「我不是很确定，这时候 **AI 开始反问**慢慢收集用户大致需要的方向。」

而要问的那些问题，**答案物理上只在作者脑子里**——
「这一场你想让萧决知道那件事吗？」不是打扰，**是产品本身**。
一个不问这句就往下写的助手，写出来的只能是它猜的那个版本。

### 4. 缺的是最后一厘米，不是能力

事件在引擎里**本来就存在**：`run_turn` 一步步跑，每一步都清楚自己在干什么。
它只是**跑完才开口**。而模型 → 服务器那半条流 `6b13abd` 已经做完了
（实测「第 3 片之后按停 ⇒ 只拉了 4 片」）。

**剩下的不是「实现流式」，是「把已经在手里的流接出去」。**
这正是本仓反复犯的那个错，它自己有一份诊断叫
`docs_dev/2026-08-06-引擎能力差最后一厘米没接线.md`。

## 为什么不需要 interrupt / resume 机制

ADR 0019 拒绝图编排时，第四问的答案是「要作者确认写正文，是**一次同步确认**」。
那个确认已经不存在了（ADR 0021 / 0022）。**但结论不变，换一条更强的理由：**

> **在对话里，「停下来问」就等于「这一轮说完了」。**
> 作者答一句，下一轮接着跑。
> 会话表和 resume 全是现成的（ADR 0019：执行态就是「一串 message + 缺哪几个 result」）。

挂起 / 恢复那套机制在这儿**一行都不用写**。

> 🔴 **2026-08-12 落地当天更正**：这儿原本写的是「**模型不再叫工具，loop 自己就停**」——
> **那是关于模型行为的希望，不是 loop 的性质，而且实测是假的。**
> 探针（`test_without_that_stop_it_would_have_gone_on_guessing`）：模型叫完
> `ask_author` 之后，for 之后还有下一次模型调用，**它会接着叫别的工具** ——
> 实测那次 `draft_chapter` **真的跑掉了**，于是作者同时收到「一个问题」和
> 「一份照猜写出来的稿子」，**而钱已经花了**。
>
> **结论保住了，但换的是理由**：不是「模型会收手」，是**代码把它收掉** ——
> 第 11 种停法 `ASKED_AUTHOR`。这跟另外十种是同一条纪律：**循环归模型，停止条件归代码。**
>
> 判据是**出参的类型**（`AuthorQuestion`），**不是工具名、也不是 `ToolSpec` 上一个开关**：
> 「哪个工具结束一轮」是一张会漂的表，而类型判断在加第二条会问的工具那天自动成立。

## 「问作者」不违反约束 8

约束 8 是「**系统不确定时的默认动作是闭嘴，不是提问**」。

那条治的是**系统主动往作者面前推队列**（`STALE` 的边只停火 + 灰点，永不推队列）。
**agent 在对话里问一句不在它管辖内** —— 是作者先开的口，而且答案只有他有。

**但两条边界要守住：**

- **不许每次都问。** 只在「不问就得猜，而猜错了作者看不出来」时问。
  判断何时问是**模型**的事（ADR 0005 禁的是**引擎**做语义判断，不是模型）。
- ~~**问句里不许夹带秘密。** 它和别的工具返回一样要过边界一那道网。~~

  🔴 **2026-08-12 落地当天更正：对这一条工具，那道网不可能是同一张。**
  别的工具那道网量的是「**引擎交给模型什么**」；而 `ask_author` 的内容
  **100% 是模型自己的字**。「这句话有没有说破秘密」是**语义判断**，
  ADR 0005 禁的正是引擎去做它。

  **引擎能保证的只有两条，两条都做成了断言：**
  ① **引擎一个字都不加** —— handler 里连一个数据来源都没有（源码断言钉着，
  这是「实现里够不着」而不是「纪律上不许」）；
  ② **事件流不把工具返回摊开**（`TurnEvent` 上没有一个字段装得下 `ToolOutcome.content`）。

  **这条落差写进了 `tools.py` 的模块 docstring**，免得下一个人以为那道网罩住了它。

## 代价（承认，不粉饰）

- **🔴 每一条事件都是一个新的输出面，而边界一不可回收。**
  今天一轮的返回是**投影过的**（工具查到了什么根本不上屏，只有一个「查了 3 次」的数）。
  事件流会把中间过程摊开 —— **那些中间过程里就有工具原返回**。
  这一条必须先有网再有管子：喂一本带 `props.twist` / `plot_note` 的书跑完整一轮，
  **把每一条事件拼起来搜毒**。
- **契约夹具那道网在事件流上没有现成对应物。** 本仓最硬的守卫是「从真 app dump 出真出参、
  冻成 `api.json`」，而一串按时间来的消息不是一个能逐字节冻住的 JSON。

  🔴 **2026-08-12 更正了这条的做法**：原文说「把一整轮的事件序列冻成一份录像」，
  **但冻在 `tests/` 里的录像只是又一份手写夹具 —— 正是那条缝原本的病。**
  `api.json` 的价值不在「冻住」，在**前端吃的是后端 dump 出来的同一份字节**。

  **所以正确的做法是走既有那条路**：`NH_UPDATE_FIXTURES=1` 多 dump 一段
  `chatTurnEvents`，让对话面板的组件测试吃**同一份**。
  ⚠️ 那一步**必须和前端一起做**（第二刀），第一刀（引擎层）里做不出来 ——
  引擎层那一刀用的是「事件种类序列 + 逐条不变量 + 整轮搜毒」，那是另一种网，不是这一种。
- **前端要从「等一个响应」改成「订阅」。** 对话面板 2026-08-12 才落地，要动它。
- **多一条要维护的传输。** CRUD 那些留着 HTTP 不是妥协，但两条传输就是两条。

## 明确不做的

- **不做 SaaS / 不上认证。** 长连接照旧只听 `127.0.0.1`（同 `nh serve` 的既有纪律）。
- **不为它引入任何新依赖**：FastAPI / uvicorn / 系统 WebView 三边都原生支持。
- **不动 CRUD。** 换它们一分好处没有，只多一套要维护的东西。
- **不做进程内 CRUD**（pywebview 的 JS ↔ Python 桥）：那会让开发时（浏览器）和
  装机后（桌面壳）变成**两条不同的传输**，而两份会漂 —— 换来的只有那 1 毫秒。

## 什么条件下推翻本 ADR

- **实测：作者从来不看中间过程，只等最后那段字。** 那时事件流是纯成本，
  退回「一个诚实的秒表」即可（那正是今天的形态，退得回去）。
- **「问作者」被证明是打扰**：作者实测嫌它问得多，或者它问的都是他不在乎的事。
  那时先收紧「什么时候问」的判据，收不住才砍掉那个工具。

## 若此决策错误，修复成本是什么

**中等，且不对称：**

- **换回请求/响应**：适配器扔掉即可，`run_turn` 那个 `on_event` 空着不叫就是今天的行为。
  **引擎不认识传输这条纪律让这次回退很便宜** —— 这也是它值得守的理由。
- **「问作者」砍掉**：从工具表删一行。
- **🔴 边界一在事件流上写错**：**最贵，而且不可回收** —— 同 ADR 0019 边界一。
  一条事件一旦把秘密推到了屏幕上（而对话是持久化的），改代码删不掉它。
  **所以那张网必须先于管子存在。**
